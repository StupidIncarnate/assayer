# M-2: the hand queue after the codemod

## Goal

After M-2, no file outside an `adapters/` folder breaks `raw-import-ban`, `platform-globals-ban` or
`bin-program-spawn-ban`, in production code, tests or harnesses, in any of the five packages. Every hit
that remains sits inside an `adapters/` folder, and Phase A removes those when it dissolves or re-homes
the adapters.

M-2 changes only import lines and the calls those imports feed. It changes no behaviour a test asserts,
and no P1 error text.

  import `execPath` from `#gateway/node/process`. M-1 did that.

  `globalThis.location.hash` left, in `packages/app/test/harnesses/e2e-fixtures.ts` line 66, runs inside

- D5's stylesheet move is done (G-7).

## Gateway gaps

No missing gateway export. Every replacement below uses a name the gateway already exports:

- `#gateway/node/fs`: `existsSync`, `mkdtempSync`, `writeFileSync(path, contents)`, `readFileSync(path)`
  (always utf8, takes no encoding argument), `rmSync(path, options?)`, `readdirSync(path)` (names only),
  `realpathSync`, `ensureDirSync(path)` (a recursive `mkdirSync`), `walkFilesSync({ rootPath, suffix })`.
- `#gateway/node/process`: `execPath`, `setEnv(name, value)`.
- `#gateway/bin/git`: `gitRun({ args, cwd })`, `currentBranch({ cwd })`.
- `#gateway/bin/npm`: `runBuild({ cwd, workspace? })`.

Two dependency declarations are missing. They are not gateway exports, but `gateway-dependency-declared`
requires them once a file imports `#gateway/bin/*`:

- `packages/cli/package.json` needs `"@assayer/bin": "*"` in `dependencies` (batch CL1).
- `packages/app/package.json` needs `"@assayer/bin": "*"` in `dependencies` (batch AP2).

`node_modules/@assayer/bin` is already a workspace link, so both resolve with no install. The operator
runs `npm install` afterwards so `package-lock.json` records the two entries.

Not added: `#gateway/npm/vite` and `#gateway/npm/vitejs__plugin-react`. Only `vite.config.ts` imports
them, lint never reads that file, and both are `devDependencies`, which `gateway-sync` does not cover.

There is no recursive directory listing that returns entries with a `parentPath`. `walkFilesSync` covers
both callers, because they only need file paths and filter by suffix anyway.

## Plan

Harness files have no proxy, and no test composes one, so only batch D1 has proxy work. Every batch is
one package. Run each batch's gate as listed. Core batches also run `npm run test:syntax`, because the
catalogue harnesses read the specimen tree.

Common rewrites, used in every harness batch:

- `import { … } from 'node:fs'` becomes `import { … } from '#gateway/node/fs'`.
- `readFileSync(p, 'utf8')` becomes `readFileSync(p)`. The wrapper takes one argument, so the encoding
  argument is a type error.
- `mkdirSync(p, { recursive: true })` becomes `ensureDirSync(p)`. Every `mkdirSync` call in these files
  passes `{ recursive: true }`.
- `writeFileSync`, `mkdtempSync`, `rmSync`, `existsSync`, `realpathSync` and a plain `readdirSync(p)` keep
  the same call. Every `writeFileSync` call in these files passes exactly two arguments.

## Risks

1. **Two files are invisible to ward's lint.** `packages/cli/test/harnesses/assayer-compile.harness.ts`
   and `packages/app/test/e2e-global-build.ts` fail to parse under `eslint.config.js`, because the root
   `tsconfig.json` `include` lists only `packages/*/src/**` and `packages/*/*.ts`. Other harnesses parse
   because a file under `src/` imports them. These two are imported only from `packages/cli/bin/` and
   `packages/app/playwright.config.ts`, which the root program never reaches. A ward lint scoped to
   either file reports a parse error, and R-2's scans never see them. The fix is a root `tsconfig.json`
   change (add `packages/*/test/**/*.ts` and `packages/*/bin/**/*.ts`), which is outside M-2's file list.
   It may bring new lint errors from other test and bin files into ward. The operator decides whether
   it joins M-2 as its own batch or goes to R-2.
2. **`e2e-global-build.ts` loads `@assayer/bin` before the build it starts.** Playwright does not set
   the `source` condition, so `#gateway/bin/npm` resolves to `packages/@gateway/bin/dist`. On a tree where
   bin's `dist` is missing, global setup fails before it can build anything. The same holds today for the
   `#gateway/node` and `#gateway/npm` imports the harnesses already make, so this adds one more package
   to that rule, not a new kind of failure. It also loses the live build log: `run` collects output, so
   the log shows only when the build fails.
3. **The walk swap must keep the same file set.** `walkFilesSync` skips a subtree it cannot read, where
   `readdirSync` threw. It joins paths with `/`, which matches `join` on Linux. It drops symlinks and
   other non-files, as `entry.isFile()` did. The catalogue check in C1 and the surface e2e in AP2 both
   fail on any difference, so a wrong swap cannot pass silently.
4. **`readFileSync` keeps its old name with a new signature.** A call that still passes `'utf8'` is a
   type error, not a silent change, so typecheck catches every one.
5. **Phase A edits two M-2 files afterwards.** `run-execute-broker.ts` and its proxy are adapter
   callers, and A-4 rewrites them. `specimen-catalogue.ts` and `syntax-surface.harness.ts` import
   `typescriptHarnessGateAdapter` by path, and A-2's re-home script rewrites that import. Neither
   conflicts with M-2's changes, but M-2 must land first.
6. **Lockfile.** Two `package.json` edits need an operator `npm install` before the commit, so
   `package-lock.json` matches.
