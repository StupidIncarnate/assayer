# G-4: `#gateway/npm/electron`

## Goal

Desktop reaches Electron only through `#gateway/npm/electron`. Jest cannot load Electron's main-process and
renderer APIs: outside the Electron runtime, `require('electron')` answers the path string of the Electron binary,
so `app`, `ipcMain` and the rest read `undefined`. The gateway folder therefore carries `electron.jest-mock.cjs`.
Dungeonmaster's Jest resolver (`@dungeonmaster/testing/ts-jest/gateway-module-mock-resolver.js`) serves that file
for every `#gateway/npm/electron` import in every test outside the npm gateway itself. No package config changes.

## What desktop uses today

Measured on 2026-09-30 from `packages/desktop/src/adapters/electron/`:

| Name | Where | What desktop calls |
|---|---|---|
| default export | `binary-path/electron-binary-path-adapter.ts` | reads it as the binary path string |
| `app` | `desktop-boot/electron-desktop-boot-adapter.ts` | `whenReady()`, `on('window-all-closed', ...)`, `quit()` |
| `BrowserWindow` | same | `new BrowserWindow(options)`, `loadURL(url)` |
| `Menu` | same | `setApplicationMenu(null)` |
| `ipcMain` | same | `handle(channel, handler)`; a handler calls `event.sender.send(channel, chunk)` |
| `IpcMainInvokeEvent` (type) | same | the run handler's event parameter |
| `contextBridge` | `preload-bridge/electron-preload-bridge-adapter.ts` | `exposeInMainWorld(key, api)` |
| `ipcRenderer` | same | `invoke(channel, ...args)`, `on(channel, listener)`, `removeAllListeners(channel)` |

`electron` is a root `devDependency` (`^32.1.0`, installed 32.3.3), hoisted to `node_modules/electron`, so the
gateway resolves it today. Neither `packages/desktop/package.json` nor `packages/@gateway/npm/package.json`
declares it.

## Design

- The barrel `electron.ts` passes through exactly the names above. It imports nothing but `electron`, so the
  preload (run with `sandbox: false`) loads one extra small file.
- The barrel has no `export * from 'electron'` line on purpose. The resolver maps the raw package name to the mock
  only when the barrel has one, and nothing outside the gateway imports raw `electron`.
- `electron-double.stub.ts` holds the one set of stand-in objects; `ElectronDoubleStub()` answers the same
  instance every call. `electron.jest-mock.cjs` requires it and adds the two shapes plain objects cannot carry:
  `BrowserWindow` as a constructor, and `default` as a getter. `electron.proxy.ts` requires the same file by
  relative path. Jest keys its module registry on the resolved path, so the code under test and the proxy see the
  same objects. The double is a stub, not a wrapper subfolder, because `gateway-colocation` demands that every
  wrapper file have a proxy and a barrel re-export.
- The double keeps Electron's own state rules: one `ipcMain` handler per channel, one `exposeInMainWorld` per
  key, and listeners that `removeAllListeners` really removes. That state lives in the call records of `jest.fn`
  logs, which the Jest setup resets after every test, because `enforce-proxy-patterns` forbids a reset call in the
  proxy constructor. A call whose answer matters (`ipcRenderer.invoke`, `loadURL`) throws a message naming
  `electronProxy` when nothing staged it.
- `electron.proxy.ts` stages `ipcRenderer.invoke` by exact `[channel, ...args]` and `loadURL` by URL, reads every
  call back with a `get...CallsFor` method, and offers named failures built from two recorded-failure stubs. Each
  stub copies the error Electron 32 builds, field for field.

## What Phase A changes in desktop's 3 proxies

Phase A owns these edits. This item touches none of them.

1. `packages/desktop/src/adapters/electron/binary-path/electron-binary-path-adapter.proxy.ts`: drop the
   `registerModuleMock` call. Compose `electronProxy()` and call `executablePathIs({ path: '/usr/bin/electron' })`.
   The source imports the default export from `#gateway/npm/electron`.
2. `packages/desktop/src/adapters/electron/desktop-boot/electron-desktop-boot-adapter.proxy.ts`: drop the
   `registerModuleMock` call and the raw `registerSpyOn` on `ipcMain.handle`. Compose `electronProxy()`.
   `handledChannels()` becomes `getHandledChannels()`. `invokeHandler` becomes the gateway proxy's
   `invokeHandler({ channel, args })`. `sentToRenderer()` becomes `getSentToSenderFor({ channel })`. The boot
   test stages `loadUrlResolves({ url })` for the renderer URL, because an unstaged `loadURL` throws.
3. `packages/desktop/src/adapters/electron/preload-bridge/electron-preload-bridge-adapter.proxy.ts`: drop the
   `registerModuleMock` call and the four raw `registerSpyOn` calls. Compose `electronProxy()`. The
   `calledWith([])` catch-all on `invoke` becomes one `invokeResolves({ channel, args, value })` per channel a test
   uses. `getApi()` becomes `getExposedApi({ key })`, `emitRunOutput` becomes `emitToRenderer({ channel, args })`,
   and the collectors become `getOnCallsFor`, `getRemoveAllListenersCallsFor` and `getInvokeCallsFor`.

Each adapter's `import ... from 'electron'` becomes `import ... from '#gateway/npm/electron'`. Desktop's
`package.json` already lists `@assayer/npm`.
