# G-1: `#gateway/bin/git`

## What this item does

It adds the `git` wrapper to assayer's `bin` gateway. It copies four functions from dungeonmaster's own `bin` gateway:
`gitRun`, `currentBranch`, `headSha` and `verifyRef`. It adds the functions core needs for its own git calls. It
then moves the placeholder `src/index.d.ts` out. Core's callers are not rewired here. Phase A does that.

The source is `/home/brutus-home/projects/codex-of-consentient-craft/packages/@gateway/bin/src/git/`. The path the
EPIC names, `node_modules/@dungeonmaster/bin/src/git/`, does not exist in assayer, because no package installs
`@dungeonmaster/bin`.

## Core's git call shapes, and the function that serves each

Every call goes through `packages/core/src/adapters/git/exec/git-exec-adapter.ts`.

| Call | Core caller | Gateway function |
|---|---|---|
| `rev-parse --abbrev-ref HEAD` | `brokers/git/current-branch` | `currentBranch` (copied) |
| `rev-parse --short HEAD` | `brokers/git/current-branch` | `resolveRef({ ref: 'HEAD', short: true })` (new) |
| `rev-parse <ref>` | `brokers/git/resolve-commit` | `resolveRef({ ref })` (new) |
| `rev-parse --is-inside-work-tree` | `brokers/git/detect-stable-branch` | `isInsideWorkTree` (new) |
| `branch --list main master` | `brokers/git/detect-stable-branch` | `branchList` (new) |
| `ls-tree -r <ref>` | `brokers/git/ls-tree` | `lsTree` (new) |
| `cat-file blob <sha>` | `brokers/git/cat-file` | `catFileBlob` (new) |

`resolveRef` is a ninth function the EPIC row does not name. None of the eight named functions returns a sha for a
named ref or a short sha. `headSha` returns only the full sha of HEAD, and `verifyRef` returns only a boolean.

## What happens when `git` is missing

Assayer has no P1 text for a missing `git` today. `gitExecAdapter` resolves a failed spawn as exit code 1 with empty
output, and every caller treats that exactly like "not a git repository": the branch reads `default`, the commit
reads `undefined`, the stable-branch check reads `hasGitRepo: false`, and the tree and blob read empty.

Every function in the new wrapper goes through `gitRun`, which throws `GitNotInstalledError` when `git` never starts.
When Phase A rewires a caller, it catches `GitNotInstalledError` and keeps that caller's current fallback. No error
text changes, because none exists.

Each new function returns `null` when git runs and exits non-zero. A caller keeps its current fallback with `?? []`
or `?? ''`.
