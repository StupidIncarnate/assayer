# A-1: the adapter table

Every file under `packages/*/src/adapters/` named `*-adapter.ts` gets one row below. A row says whether the adapter
dissolves into its callers (`inline`), moves with its body unchanged to a legal folder type (`rehome`, per D3), or
goes because nothing calls it (`delete`). SD-2 reads the `rehome` rows. SD-3, or the A-4 agents, read the `inline`
rows. The table keeps one fixed column shape so a script can parse it: one header row, one separator row, then one
row per adapter.

The census count of 110 holds. Two census details differ from the code:

- Core's walk-file folder holds 42 layer files plus `ts-morph-walk-file-adapter.ts`, so 43 files, not 43 layers plus
  the main file.
- `npx adapter-census --format=json` lists 63 adapters. It skips all 47 `*-layer-adapter.ts` files: core's 46 and
  desktop's `reply-value-layer-adapter.ts`. The rows for those 47 come from walking the folders.

No adapter has zero callers, so no row is `delete`. The three `testing-library` adapters in app have no production
caller, but tests call them, so they are not dead.

How the `callers` column is counted: a file counts when it names the adapter's export outside a comment and is not a
`.test`, `.proxy` or `.stub` file. That includes test harness files under `test/harnesses/` and core's root `.js`
runtime files. It leaves out the two re-export barrels `packages/core/adapters.ts` and `packages/core/testing.ts`,
which A-7 and Phase X remove. For a layer file, the callers are its sibling files in the same folder.

How a target was chosen: a body that does I/O, runs the code under test, or keeps mutable state goes in `brokers/`.
A pure reshape goes in `transformers/`, and a pure boolean check in `guards/`. The ts-morph walk and the harness
value-type reader parse in an in-memory project (`useInMemoryFileSystem: true`), so they do no I/O and go in
`transformers/`. Dungeonmaster's own transformers already import `#gateway/npm/typescript` and `#gateway/node/crypto`,
so a transformer may import a gateway pass-through. Every target path was checked against `get-architecture` and
`get-folder-detail` for `brokers`, `transformers`, `guards`, `contracts`, `statics` and `middleware`: brokers sit at
`brokers/<domain>/<action>/<domain>-<action>-broker.ts`, transformers and guards one level deep, every layer is
`<name>-layer-<suffix>.ts` flat beside its parent, and no file outside a layer's folder imports it. No new folder is
named after a library.

## Gateway gaps

1. **Desktop's run spawn (`node-child-process/exec`).** No `#gateway/node/child_process` wrapper runs a command to
   completion with all of these: an `env` merged over the process's own, `stdin` ignored, a callback for every stdout
   and every stderr chunk as it arrives, and stdout and stderr answered apart with the exit code. `run` has no chunk
   callback and inherits `stdin`. `stream` has no `env` and reports only stderr chunks. The fix is a gateway change
   copied from dungeonmaster, for example `onStdout` and `env` on `stream`, or a new `runStreaming`. The fallback, if
   the gateway change is refused, is the re-home named in that row's notes.
2. **Desktop's app launch (`node-child-process/spawn`).** No wrapper launches a detached child with `stdio: 'ignore'`,
   calls `unref()`, and logs a start failure. `spawnDetached` takes file descriptors and keeps the child referenced.
   `runFireAndForget` runs a shell string, which would need argument quoting. The fix is an option on
   `spawnDetached` (no descriptors means `'ignore'`, plus `unref()`), or a new wrapper.

Nothing else is missing. Every other `inline` row names a wrapper that exists today in `packages/@gateway/*/src/`,
and each of those wrapper folders that has a body also has a `.proxy.ts`. `#gateway/browser/window`,
`#gateway/node/path`, `#gateway/node/util`, `#gateway/node/module` and the npm React, Mantine and Testing Library
barrels are pass-throughs with no proxy, which the docs allow.

## Risks

1. **The walk's rename breaks the specimen suite, and the smoke-repo is off limits.**
   `smoke-repo/packages/syntax-repository/tsconfig.json` maps `@assayer/core/walk-file` to
   `packages/core/src/adapters/ts-morph/walk-file/ts-morph-walk-file-adapter`, and 103 smoke-repo files import
   `tsMorphWalkFileAdapter` by name. The brief forbids touching `smoke-repo/`. RH-walk cannot land until the
   operator decides. The recommended choice is a one-time exception for SD-2 to rewrite that one `paths` entry and
   the import name in the specimen `.test.ts` files only. Specimen source files stay untouched. The catalogue lists
   specimens without their tests, so the P0-5b hash run should show no change; run it to prove that. The other
   choice, keeping the old export name, breaks the transformer naming rule.
2. **SD-2's import rewrite cannot see path strings or files outside its TypeScript program.** It rewrites none of
   these, so each needs a hand edit or a later item:
   - `packages/core/src/statics/core-runtime/core-runtime-statics.ts` (`modules`), and the export names that the shim
     text in `assemble-shim-transformer.ts`, `probe-runtime.js` and `probe-transformer.js` destructure (A-3).
   - The path strings in `assemble-shim-transformer.test.ts`, `run-unit-broker.test.ts`,
     `jest-run-cli-adapter.test.ts`, `core-runtime.stub.ts`, `core-runtime-contract.test.ts`,
     `core-runtime-statics.test.ts` and `core-runtime-transformer.test.ts` (A-3).
   - `packages/core/adapters.ts`, core's `./adapters` export, the `@assayer/core/adapters` Jest mapper entry, and the
     walk proxy line in `packages/core/testing.ts` (A-7, Phase X). Desktop's `compiled-file-resolve-broker.ts`
