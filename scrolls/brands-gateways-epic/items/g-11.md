# G-11: the two child-process gateway gaps desktop needs

## Plan

Both gaps sit in `packages/@gateway/node/src/child_process/`.

1. Desktop's `node-child-process/exec` runs a command to completion and narrates it while it runs. `run` already
   merges `env`, returns `stdout` and `stderr` apart, and reports the exit code. It lacks two things: a chunk
   callback and a way to ignore stdin. Both are general, so they go into dungeonmaster's `run` as options, then
   the three `run/` files are copied into assayer unchanged.
2. Desktop's `node-child-process/spawn` launches Electron and lets go. `spawnDetached` already calls `unref()`.
   It does not fit for a different reason: it hands back a pid and throws when there is none, and a program that
   never starts has no pid. Node reports why only later, through the child's `'error'` event. Desktop's
   user-facing message needs that reason, so the throw cannot carry it. This is a fire-and-forget shape with no
   return value, which only assayer needs today. It goes into assayer's gateway only, as `spawnFireAndForget`.

## Result

- Dungeonmaster `36f0ff0`: `run` takes `stdin?: 'inherit' | 'ignore'` (default `'inherit'`) and
  `onStdout` / `onStderr` chunk callbacks. Each callback gets text decoded through a `StringDecoder`, so a
  multi-byte character split across chunks arrives whole. Every callback fires before the promise settles. The
  proxy can stage raw bytes, and `getOptionsFor` types the `stdio` it reads back. Copied into assayer unchanged.
- Assayer only: `spawnFireAndForget({ command, args, onStartFailure })` spawns with
  `{ detached: true, stdio: 'ignore' }`, always listens for `'error'`, and calls `unref()`. Its proxy stages by
  exact `command` and `args`: `setupLaunch` and `setupNotFound`. It reads back with `getCallsFor` and
  `getUnrefCountFor`. `setupNotFound` emits `SpawnNotFoundRecordedErrorStub`, whose test checks it field for field
  against a real ENOENT from `spawn`.

## The gateway call A-4 uses

Exec adapter, in `packages/desktop/src/brokers/run/execute/run-execute-broker.ts`:

```ts
const { exitCode, stdout, stderr } = await run({
  command,
  args: [...args],
  cwd,
  ...(env === undefined ? {} : { env: { ...env } }),
  stdin: 'ignore',
  onStdout: (chunk) => onOutput?.({ chunk }),
  onStderr: (chunk) => onOutput?.({ chunk }),
});
```

The caller parses `{ exitCode, stdout, stderr }` through `execResultContract`. Its proxy composes `runProxy()` and
stages `setupSuccess({ command, args, cwd, exitCode, stdout, stderr })`. It reads `env` and `stdio` back with
`getOptionsFor({ command })`. Two behaviours differ from the adapter. A program that never starts rejects with
`RunNotFoundError`, whose message reads `"<command>" never started: <Node message>`. A child killed by a signal
reports `exitCode: 1`, the same as the adapter's `code ?? 1`.

Spawn adapter, in `packages/desktop/src/brokers/desktop/launch/desktop-launch-broker.ts`:

```ts
spawnFireAndForget({
  command,
  args: [...args],
  onStartFailure: (error) => {
    stderr.write(
      `assayer: failed to launch ${command} (${error.message}). Verify the executable exists and is runnable, then try again.\n`,
    );
  },
});
```

Its proxy composes `spawnFireAndForgetProxy()` and stages `setupLaunch({ command, args })` or
`setupNotFound({ command, args })`. Node emits a start failure on a later tick, so a failure test awaits one
`setImmediate` before it reads stderr.
