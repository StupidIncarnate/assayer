# 8b.5.1 The generated-run startup, its integration test and the bin entry

- **Phase:** 8b, running at scale. **Row:** #5, alone.
- **Depends on:** row #4 (8b.4.1, the flow).
- **Model:** default (the worker's default model; this task is fully specified).
- **Covers:** DESIGN.md decisions "Running at scale" and "Speed of the generated run", README "Running at scale".

## What to implement

- `StartTestGenerated({ argv, repoRoot }): Promise<GenerateRunResult>` calls `TestGeneratedFlow` (task 8b.4.1).
- `bin/test-generated-entry.ts` is the command-line entry, written like `bin/specimen-generator-entry.ts`. It finds the
  repo root from its own place (`join(__dirname, '..', '..', '..')`), calls `StartTestGenerated` with `argv.slice(2)`,
  writes `output` to stdout when the exit code is 0 and to stderr otherwise, and sets the exit code. A thrown error
  prints its message to stderr and sets exit code 1. It awaits the promise.
- The startup integration test calls `StartTestGenerated` with the real repo root
  (`join(__dirname, '..', '..', '..', '..')`, the expression `start-specimen-generator.integration.test.ts` uses) and
  never starts Jest. It holds the three refusal cases below.

## Tests

- `INVALID: { argv: [] }` gives exit code 1 and `test:generated needs one top folder, such as 'if/'. The whole suite in one process runs out of memory.`
- `INVALID: { argv: ['if/', 'ternary/'] }` gives exit code 1 and `test:generated takes one folder at a time, such as 'if/'. It was given 2: if/, ternary/.`
- `INVALID: { argv: ['nope/'] }` gives exit code 1 and `test:generated cannot use 'nope/'. Name one folder under smoke-repo/packages/syntax-repository/src, ending in a slash, such as 'if/'.`

## Verify

```
npm run ward -- -- packages/specimen-generator/src/startup/start-test-generated.ts packages/specimen-generator/src/startup/start-test-generated.integration.test.ts packages/specimen-generator/bin/test-generated-entry.ts
```

## Done when

Ward exits 0, and the startup and its test land in one row.
