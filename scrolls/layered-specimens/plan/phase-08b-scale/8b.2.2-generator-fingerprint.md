## Contract

`fingerprintReadBroker({ repoRoot, packageRoot }): string`. `repoRoot` is the repo root, and `packageRoot` is
`packages/specimen-generator` under it. The result is a 64-character hex SHA-256.

## What to implement

The fingerprint must change whenever anything that can change a prediction changes, so a cache hit always returns
exactly what a fresh run computes (worker brief rule 11). Hash, with `createHash` from `#gateway/node/crypto`, in this
order, each item as its path relative to `repoRoot` (or its label), then its content, each followed by `' '`:

1. The bytes of every file under `<packageRoot>/src/` and `<packageRoot>/declarations/` whose name does not end in
   `.test.ts`, `.proxy.ts` or `.stub.ts` (test support never changes a specimen), walked with `walkFilesSync` from
   `#gateway/node/fs`, sorted by relative path (plain string order).
2. The bytes of `<repoRoot>/package-lock.json`: it pins every installed version, TypeScript and the two npm packages
   included, so a reinstall that moves a version changes every key.
3. The bytes of `<repoRoot>/packages/core/index.ts`: a generated harness imports `assayerHarness` from
   `@assayer/core`, which resolves to that file, and the typecheck of a harness specimen reads it.
4. The bytes of every file under `smoke-repo/packages/project-with-types/` and `smoke-repo/packages/project-without-types/`
   (the packages in `typeListStatics.packages`, task 4.1.3), sorted by path.
5. `typescript.version` from `#gateway/npm/typescript`, labelled `typescript`.
6. `process.version` from `#gateway/node/process`, labelled `node`: the prediction runs the specimen in a `vm`
   context, and the Node version decides the built-ins it sees.

A missing file in steps 2 to 4 is an error, never skipped: `fingerprint: cannot read '<path>'. The generation cache
key needs it. Run npm install, or check the path.` Any change to a generator file, the lock file, core's main barrel,
either package, the compiler or Node therefore changes every cache key.

## Tests

The proxy stages a small folder.

- `VALID:` the same files give the same fingerprint.
- `VALID:` changing a file's content changes it.
- `VALID:` adding a `.test.ts` file does not change it.
- `VALID:` renaming a file changes it.
- `VALID:` changing `package-lock.json` changes it.
- `VALID:` changing `packages/core/index.ts` changes it.
- `VALID:` changing `smoke-repo/packages/project-with-types/index.d.ts` changes it.
- `ERROR:` a missing `package-lock.json` throws the message word for word.
- `EMPTY:` empty `src` and `declarations` folders give a fingerprint (of steps 2 to 6 alone).
