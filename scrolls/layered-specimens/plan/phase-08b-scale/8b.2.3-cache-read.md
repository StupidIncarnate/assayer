## Contract

`generationCacheReadBroker({ cacheRoot, key }): { status: 'hit'; verdict: unknown; prediction: unknown } | { status: 'miss' } | { status: 'corrupt'; reason: string }`

## What to implement

An entry is one JSON file, `<cacheRoot>/<key>.json`, holding `{ schema, key, verdict, prediction }`. `verdict` is the typecheck verdict (task 5.2.2) and `prediction` the prediction (task 6.4.1); the build broker (task 9.2.1) parses both with their own contracts, so this broker checks only the envelope.

- No file: `{ status: 'miss' }`.
- A file that is not valid JSON, or whose `schema` is not `runScaleStatics.cache.schema`, or whose `key` is not the requested key, or that lacks `verdict` or `prediction`: `{ status: 'corrupt', reason }`, with a reason such as `cache entry <key>.json is not valid JSON.` or `cache entry <key>.json holds schema <n>, expected <m>.`
- Otherwise `{ status: 'hit', verdict, prediction }`.

A corrupt entry is reported and recomputed, never silently used (task 9.2.1 prints the reason and recomputes).

## Tests

- `VALID:` a good entry is a hit.
- `EMPTY:` no file is a miss.
- `INVALID:` bad JSON is corrupt.
- `INVALID:` a wrong schema is corrupt.
- `INVALID:` a wrong key is corrupt.
- `INVALID:` a missing `prediction` is corrupt.
