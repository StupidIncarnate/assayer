## What to implement

1. The wrapper folder is `legendscribe__lockdown-kit-load-balancer__brokers`: a scoped package and its subpath become `scope__name__subpath`. The wrapper file is a passthrough barrel that re-exports exactly the four brokers the generator uses:
   `export { capacityReadBroker, leaseBeatBroker, leaseReleaseBroker, leaseTakeBroker } from '@legendscribe/lockdown-kit-load-balancer/brokers';`
   with the PURPOSE and USAGE header the neighbouring wrappers carry. A barrel-only subpath needs no stub.
2. The test follows the neighbour's test: it imports the wrapper and asserts that each of the four names is a function.
3. In `packages/@gateway/npm/package.json` (the package `@assayer/npm`), add
   `"@legendscribe/lockdown-kit-load-balancer": "file:../../../../lockdown-kit/packages/load-balancer"` to
   `dependencies`, keeping the keys sorted. Every outside package the gateway wraps is a dependency of the gateway
   package, never of the package that uses the wrapper: the generator already depends on `@assayer/npm`, and its
   `imports` map sends `#gateway/npm/*` to `@assayer/npm/*`, so generator code imports
   `#gateway/npm/legendscribe__lockdown-kit-load-balancer__brokers` and needs no change to its own `package.json`.
   Read the root `package.json` first: it names the same package with a `file:` path relative to the repo root
   (`file:../lockdown-kit/packages/load-balancer`); write the path relative to `packages/@gateway/npm/` so it
   reaches the same folder, and confirm it resolves with `ls` before you write it.
4. Write the barrel by hand. Run `lockdown-kit gateway-sync` only if the barrel cannot be written by hand, and report
   that you did. Never import lockdown-kit's own gateway packages.
