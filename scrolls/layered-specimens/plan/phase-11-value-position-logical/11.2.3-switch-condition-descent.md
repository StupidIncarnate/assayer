## What to implement

`handleSwitchLayerTransformer` (`handle-switch-layer-transformer.ts`) has one descent list: one descent per case
clause, built at lines 137 to 141 with `walkContextTransformer({ context, guardSteps: clause.guards })`. It never descends
into the subject (`node.getExpression()`) or into a case label: it reads the subject only through the condition lens,
so a `&&`, `||` or `??` in the subject is never reached by the walk and never becomes a value-position branch. That is
the behavior the design wants (pieces table: the subject is a condition slot).

So this task changes no line of the handler. It adds the tests below, which pin that shape: if a later change adds a
subject descent, the test fails and says the descent must carry `condition: true`. Update the handler's PURPOSE block
with one sentence saying the subject is read only through the condition lens and has no descent of its own.

## Tests

- `VALID: {switch (a && b) {…}} => the descents are exactly the case clauses; none of them is the subject`
- `VALID: {same switch} => every case-clause descent has inCondition absent`
- `EDGE: {case label expression} => no descent carries the marker`
