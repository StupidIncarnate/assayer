## What to implement

Add exactly one route, placed beside the `ConditionalExpression` route. A node goes to
`handleLogicalValueLayerTransformer` when all of these hold:

- `Node.isBinaryExpression(node)`,
- its operator token kind is `&&`, `||` or `??` (compare `getOperatorToken().getKind()` with
  `SyntaxKind.AmpersandAmpersandToken`, `BarBarToken`, `QuestionQuestionToken`; never text),
- `context.inCondition !== true`.

An operator in a condition keeps the default descent: its leaves are read by the condition lens of the `if`, ternary or
`switch` that owns it. Add one comment above the route saying so. A logical expression that IS an exit never reaches the
walk as a node (`read-conditional-exit` consumes it first), so this route sees only value positions.

An expression statement `ready && go()` is a value position by this rule, so it becomes a branch. Keep it, and name it
in a test.

## Tests

In `dispatch-node-layer-transformer.test.ts`:

- `VALID: {console.log(a && b)} => handled by the logical-value handler (one ternary branch)`
- `VALID: {x = a ?? b} => one branch`
- `VALID: {a || b as an expression statement} => one branch`
- `EDGE: {if (a && b) {…} with the condition descent's context (inCondition true)} => no branch from the operator`
- `EDGE: {return a && b} => no branch from this route (the exit lens consumed it)`. Assert on the whole function walk
  if the unit test cannot reach `read-conditional-exit`; use `walkFileTransformer` the way sibling tests do.
- `EDGE: {a & b (bitwise)} => default descent`
