## What to implement

`applied-params` truncates the parameter list at the first parameter a caller owes nothing for: an `optional` or `rest`
parameter that is `branchingDefault` or that the fill seam cannot build. A parameter whose default is a ternary is left
out of every case, so its `given` route had no test.

Remove the `branchingDefault` clause: an `optional` or `rest` parameter is truncated only when the harness does not name it
and the seam cannot build it (`fillParamTransformer({ param }).kind === 'unfillable'`). So a defaulted parameter the seam
can build is applied in every case, and task 13.4.1 decides per route whether it takes a value (`given`) or `undefined`
(`defaulted`). A defaulted parameter the seam cannot build (a callback default) is still truncated: its default supplies it.

Delete the paragraph of the PURPOSE block about `branchingDefault` and every other mention of it in this file and its
test. Write the PURPOSE block in plain words: a defaulted parameter is applied when it can be built.

## Tests

- `VALID: {size: number, report?: callable} => [size]` (unchanged)
- `VALID: {count: number, label: string with a default (optional: true)} => both applied` (a buildable defaulted parameter is applied)
- `VALID: {cb: callable with a default (optional: true)} => truncated at cb`
- `VALID: {report?: callable, harness: ['report']} => report kept` (unchanged)
- `EMPTY: {no params} => []`
- Delete the cases that built `branchingDefault: true`; they describe no rule.
