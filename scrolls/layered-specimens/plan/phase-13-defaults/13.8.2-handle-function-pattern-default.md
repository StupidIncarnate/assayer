## What to implement

For each parameter whose name is a destructuring pattern, each readout with `form: 'element'` and a `position` of
`source: 'array'` or `source: 'object'` becomes one branch of kind `destructure-default`, `arms: ['present', 'defaulted']`,
in readout order, claimed by this function's scope like the `default` branches.

- **Source.** The source is the parameter itself. The leaf's `operandParamName` is the name `handle-function` already gives
  that parameter's descriptor.
- **Array element at index `i`:** a leaf on the parameter, predicate `length-gt` with literal `i`. `present` holds when the
  array has an element at `i`, so `then` is `present` and `else` is `defaulted`. The array cardinalities steer it.
- **Object element named `n` under path `p`:** a leaf on the parameter with `operandPropertyPath` `[...p, n]`, predicate
  `has-property` literal `n` (task 12.1.3). `then` is `present`. The stub overlay arranges it at run time (section 9). A
  property present as `undefined` also triggers a default; this phase does not arrange that form for a destructuring default.
- **Coverage ID:** `coverageIdTransformer({ scopePath: scoped.scopePath, segment: 'destructure-default:<param>.<path>.<name or index>' })`.
- **Defaulted arm.** The element's initializer descends under the guard step `{ branchCoverageId, arm: 'else' }`, built with
  `walkContextTransformer({ context: preludeContext, guardSteps: [step] })`. Record the `defaulted` arm as a fall-through
  arm with the initializer's span.
- A readout with `position: { source: 'whole' }` (a pattern parameter's own default) only descends, unguarded, as today.
- A parameter pattern inside a nested function or a method is handled by the same code, since each is a function scope.
