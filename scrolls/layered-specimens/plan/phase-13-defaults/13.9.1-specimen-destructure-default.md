## What to implement

`destructure-default.ts` exports three entries, two per card and one for a parameter pattern:

- `firstOrZero = (values: number[]): number => { const [first = 0] = values; return first; }`
- `themeMode = (settings: Settings): string => { const { display: { theme: { mode = 'light' } } } = settings; if (mode === 'dark') { return 'then'; } return 'else'; }`, with `type Settings = { display: { theme: { mode?: string } } };` in the same file.
- `patternParam = ({ count = 0 }: { count?: number }): number => count`, a destructuring default in a parameter list.

The test asserts what is bespoke, from the cards:

- `firstOrZero`: one `destructure-default` branch with arms `present` and `defaulted`; routes `values []` (defaulted) and
  the non-empty arrays (present); fewest runs 2;
- `themeMode`: a `destructure-default` branch and an `if`; the `defaulted` route cannot reach the `then` arm of the `if`
  (the default `'light'` is never `'dark'`), so three arm combinations, not four; the branch is undriven in the file's
  own analysis (an object member) and driven through the stub overlay; fewest runs 2;
- `patternParam`: one `destructure-default` branch with arms `present` and `defaulted`, leaf `has-property` `count` on the
  parameter; two routes (`{}` defaulted, `{ count: <number> }` present), plus the edge routes of the cause rule
  (`{ count: 0 }`, `{ count: NaN }`, `{ count: -1 }`); driven through the stub overlay;
- determinism and formatting immunity.
