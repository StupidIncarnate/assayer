## What to implement

Today the reader returns a flat `Expression[]`: the parameter's own default first, then the default of each pattern
element. A branch for the parameter's own default needs to know which parameter it belongs to, so the reader returns
records:

```ts
type ParameterDefaultReadout =
  | { form: 'parameter'; name: string; initializer: Expression }   // `count = 7`, name from an Identifier name node
  | { form: 'element'; initializer: Expression };                  // a default inside a destructuring pattern
```

- `form: 'parameter'` only when the parameter's name node is an `Identifier`. The `name` is that identifier's text (an
  identifier's text is its name, the one sanctioned `getText()` use, `packages/core/CLAUDE.md` section 5.1). A parameter
  whose name node is a pattern (`{ a } = {}`) gives its own default as `form: 'element'`, so it descends and is not a
  branch of its own (its elements are, task 13.8.2).
- Pattern element defaults keep their order and are `form: 'element'`. Task 13.7.1 adds the element's position.
- The reader keeps its order: own default first, then elements.

`handle-function-layer-transformer.ts` has one call site (line 155 to 158). Adapt it only enough to compile and behave as
today: map each readout to its `initializer`. Do not change any other line of the handler (task 13.3.1 does).

Update the PURPOSE block and the USAGE example in plain words.
