## What to implement

1. **Contract.** Remove `branchingDefault` from `paramDescriptorContract` and from its PURPOSE block, and remove the test
   cases that built it (lines 33 to 38 of the test). After tasks 13.3.1 and 13.3.2 nothing writes or reads it. `discover`
   the whole repo for `branchingDefault` first; if any file still names it, stop and list it in `OPEN` before removing
   anything.
2. **`packages/core/CLAUDE.md` section 4.** Rewrite the entry "Read a parameter's default value" in the present tense, in
   plain words, with no history. It says:
   - `handle-function` emits a `default` branch for each parameter whose name is an identifier and that has an initializer.
     Its arms are `given` and `defaulted` (`BranchNode.arms`, in the order `[then label, else label]`). Its leaf is
     `undefined-neq` on the parameter, because only `undefined` triggers a default, never `null`.
   - The initializer descends under the `defaulted` arm's guard step, so a ternary in a default is met only on that arm.
   - `read-parameter-defaults` lists a parameter's own default (`form: 'parameter'`) and the default of each element a
     destructured parameter unpacks (`form: 'element'`).
   - A `default` branch is steered by structure, not by its leaf: `derive-cases` passes the parameter for `given` and
     `undefined` for `defaulted`.
   Delete the sentences about `branchingDefault` and about a default being "marked" so the default "runs".
3. **`packages/core/CLAUDE.md` section 4, "Decide which parameters a call site actually supplies".** Make it say that a
   defaulted parameter the seam can build is applied, and one it cannot build is truncated because its default supplies it.
4. Add one entry: "**Read a destructuring default**" naming `handle-variable` for variable declarations and `handle-function` for parameter patterns (tasks 13.8.1 and 13.8.2 land them in the same phase; write
   the entry in the present tense once, here, as a statement of what the handlers do: a `destructure-default` branch with
   arms `present` and `defaulted`, a `length-gt` leaf for an array element and a `has-property` leaf for an object element).
5. Section 9's `stub-realize` paragraph needs no change.
