## What to implement

Task 13.2.2 made the reader return `{ form: 'parameter', name, initializer }` and `{ form: 'element', initializer }`.
`handle-variable` (task 13.8.1) and `handle-function` (task 13.8.2) need to know where each element sits in its pattern, so a branch can ask the right
question of the right source. Extend `form: 'element'` with a `position`:

```ts
{ form: 'element'; initializer: Expression; position: ElementPosition }
type ElementPosition =
  | { source: 'array'; index: number; path: string[] }        // `[a, b = 1]`: the element's index in its array pattern
  | { source: 'object'; name: string; path: string[] }        // `{ mode = 'light' }`: the property the element reads
  | { source: 'whole' }                                        // a pattern parameter's own default: `({ a } = {})`
```

- `path` lists the property names of the enclosing object patterns from the outermost one inward, then nothing for the
  element itself. For `const { display: { theme: { mode = 'light' } } } = settings` the element is
  `{ source: 'object', name: 'mode', path: ['display', 'theme'] }`. An array pattern inside an object pattern
  contributes its position to `path` as the index written as a string (`'0'`); keep it simple and report in `OPEN` any
  shape you cannot name.
- `index` counts the pattern's elements from zero. An omitted element (`[, a = 1]`) still counts. A rest element has no
  default and gives no readout.
- A property written with an alias (`{ mode: m = 'light' }`) names the property (`mode`), not the alias. Read the
  property name from the property-name node when there is one, and from the name node when there is not. These are names,
  never source spelling of a literal.
- A pattern parameter's own default (`form: 'element'` since task 13.2.2) gets `position: { source: 'whole' }`. It is not a
  branch; it only descends.
- The order of the readouts is unchanged.

Update the PURPOSE block and the USAGE example in plain words.
