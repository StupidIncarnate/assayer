# 27.1.1 Operator and user: read the answers to the disputed cards

- **Phase:** 27, settle the disputed cards. **Row:** #1, alone.
- **Depends on:** phase 26, and the user's answer to every question in README "Open questions for the user".
- **Model:** operator and user (no worker; the operator edits only the plan's markdown).
- **Covers:** README "What a card check compares" (the exclusion list), "Open questions for the user"; task 7.1.1
  (`card-check-exclusions.harness.ts`).

## Files

| Action | Path | Folder type |
|---|---|---|
| edit | `scrolls/layered-specimens/plan/README.md` | plan document (markdown) |

## Steps

1. Open `packages/specimen-generator/test/harnesses/card-check-exclusions.harness.ts`. List every entry with reason
   `disputed`, with its `question`.
2. For each, read the user's answer. A question the user has not answered keeps its entry: stop and tell the user which
   questions still block this phase. The rest of the plan is done; this phase waits.
3. For each answered question, decide what the answer changes:
   - the user changed DESIGN.md (the user's own edit, never this plan's): the card's group harness needs the new
     transcription;
   - the answer keeps DESIGN.md and changes the generator: the generator file the answer names needs the fix;
   - the answer confirms the generator as it is: nothing changes but the exclusion entry.
4. Write one task file per change for the fan-out row 27.2 (`27.2-fan-out.md` says how), and add the ids to the README
   tracker.
5. Move each answered question from README "Open questions for the user" to "Answered questions", with the answer.

## Done when

Every disputed entry has an answered question, every change it needs is a `27.2.<n>` task, and README records each
answer.
