## What to implement

1. The specimen holds the two cards' code with named entries:

   ```ts
   export const bigOrSmall = (count: number): Promise<string> =>
     Promise.resolve(count).then((value) => (value > 2 ? 'big' : 'small'));

   const load = async (count: number): Promise<number> => {
     if (count < 0) {
       throw new Error('count must be 0 or more');
     }
     return count;
   };

   export const settle = (count: number): Promise<string> =>
     load(count)
       .then((value) => (value > 2 ? 'big' : 'small'))
       .catch(() => 'failed')
       .finally(() => console.log('done'));
   ```

2. The test asserts what is bespoke to this file. Write every expected value by reasoning from the cards.
   - `bigOrSmall`: the `.then` callback is a `through-caller` entry with one ternary (arms `then`, `else`) and no settle step,
     because `Promise.resolve` never rejects. Five cases: `count` 3 takes `then`; 2, 0, `NaN` and -1 take `else`.
   - `settle`: the `.then` callback entry has the ternary and a `settles` step with arms `runs` and `skipped`; the `.catch`
     callback entry has the `settles` step only; the `.finally` callback has no entry (it adds no arm). Five routes per the
     card: `count` -1 rejects, so `.then` is skipped and `.catch` runs; `count` 2, 0 and `NaN` resolve, run `.then` with the
     ternary `else`, and skip `.catch`; `count` 3 takes the ternary `then`.
   - `load` is a private function the entry calls with its own parameter, so it is a `through-caller` entry with one `if`
     (arms `then`, `else`).
   - no dark spot, no undriven entry, no gap and no lint. The file runs clean, so it sits under `happy-path/`.
3. Registry: add one line, declared by reading the file. It owes `access:named`, `access:through-caller`, `branch:if`,
