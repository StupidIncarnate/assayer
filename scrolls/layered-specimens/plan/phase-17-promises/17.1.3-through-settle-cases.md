## Contract

```ts
throughSettleCasesTransformer({ callback, host, method, receiver, label? }): ThroughCallbackCases
// callback: ScopeRecord   the inline function passed to .then / .catch / .finally
// host:     ScopeRecord   the reachable scope that makes the call chain
// method:   'then' | 'catch' | 'finally'
// receiver: { kind: 'resolves'; value: CallArg }                         // Promise.resolve(value): never rejects
//         | { kind: 'call'; callee: ScopeRecord; args: CallArg[] }       // a same-file async function: may reject
```

A callback's parameter is bound to the value the receiver settles with. A **receiver that never rejects** is
`Promise.resolve(<param>)`, and it resolves with that parameter. A **receiver that can reject** is a call to a same-file
function whose cases include a `throw` exit; it rejects on those cases and resolves, with the value its sole `return`
expression names, on the others. When that value is one of the callee's parameters passed straight from the host, the
callback's parameter is bound to the host's parameter.

**Arms.** The settle arms follow the vocabulary table in the README ("The report vocabulary"):

| Method | Receiver can reject | Callback arms |
|---|---|---|
| `.then` | yes | `runs` when the receiver resolves, `skipped` when it rejects, as a pseudo step keyed `<callback scope>/settles` |
| `.then` | no (`Promise.resolve`) | none: the callback always runs and one arm is no branch. The step is not listed |
| `.catch` | yes | `runs` when the receiver rejects, `skipped` when it resolves |
| `.catch` | no | the callback never runs: return no cases and report nothing here |
| `.finally` | any | none: it runs on both outcomes and adds no arm |

**Cases.** One host case per route, each a pair: the receiver's route (for a `call` receiver, each of the callee's cases)
and the callback's own route over its parameter. Resolve the pair into the host's parameters through the shared fill seam:
the two routes can constrain the same host parameter (the callee's guard on `count` and the callback's `value > 2`, with
`value` bound to `count`), so give `causeArrange` the union of both requirement sets and drop a pair whose union is empty.
Parameters nothing constrains go through `fillParamTransformer`. A refusal is returned on `unfillable` against the host, as
`through-callback-cases` does.

**Chains.** In `load(count).then(a).catch(b).finally(c)`, `.catch`'s receiver is the result of `.then`. A chain rejects exactly
when the root receiver rejects (a callback that itself throws is not modelled, and its enclosing chain stays as the root says).
The caller (task 17.3.1) passes the root receiver for every method in the chain.

## Tests

Build scope records and call args by hand with the stubs other `through-*` tests use. Assert the arm lists and counts the cards
give.

- `VALID: card callback/then (receiver resolves with param count; callback value > 2 ? 'big' : 'small') => five cases, none with a settles step, ternary arms then once and else four times (count 3, 2, 0, NaN, -1)`
- `VALID: card callback/then-catch-finally, .then callback => resolves routes carry settles:runs and the ternary arms; the rejects route carries settles:skipped`
- `VALID: the same card, .catch callback => the rejects route carries settles:runs, the resolves routes settles:skipped`
- `VALID: the same card, .finally callback => no settles step on any route`
- `VALID: the rejects route is count -1 (the callee's guard) and the resolves routes are count 2, 0, NaN, 3`
- `VALID: .catch on Promise.resolve => no cases`
- `INVALID: a callback whose parameter the receiver does not bind to a host parameter => its routes are returned undriven, never guessed`
- `ERROR: a host parameter the fill seam refuses => returned on unfillable with the host as owner`
- `EDGE: two requirement sets on one host parameter that cannot both hold => that pair is dropped`
- `EDGE: a callback with no branch (.catch(() => 'failed')) => one case per settle arm, no callback arms`
