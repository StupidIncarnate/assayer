## Read first

The whole of `case-interpret-broker.ts` as task 15.2.5 left it. Today an application that throws, or whose returned promise
rejects, is caught and the case is `errored` with `threw before reaching an exit: <message>`, even when an exit probe of the
entry had already fired. A `throw` exit and an executor that rejects both fire their exit probe first (an exit's probe wraps
its expression in place, section 5.11), so such a case reached exactly the exit it predicted and then ended by throwing.

## What to implement

1. When an application throws, or its result rejects, look at the probe events of that application. If at least one exit event
   of this entry's exits (`exitIds`) fired, the application counts as finished. The case is then judged like any other: it
   passes when its predicted `reachesPath` is the tail of the observed exit path, and fails when it is not.
2. When no exit of the entry fired, the case stays `errored` with the same message as today, including the call-numbered form
   of task 15.2.5.
3. In a call sequence (`calls` above 1), an earlier application that throws after it reached an exit counts as finished and the
   sequence continues. The case is judged on the last application only.
4. The environment restore stays in `finally`, exactly as today.
5. Update the header comment: the "A throw is a real outcome" paragraph says a throw after an exit is a finished application.

## Tests

- `VALID: an entry that fires its exit probe and then throws => passed when reachesPath matches the observed tail`
- `VALID: an async entry whose promise rejects after the exit probe fired => passed`
- `VALID: an entry that fires an exit probe and then throws, with a reachesPath that does not match => failed`
- `VALID: calls 2, the first application fires its exit and throws, the second finishes => the case is judged on the second`
- `ERROR: an entry that throws before any exit probe fired => errored, message threw before reaching an exit: <message>`
- `ERROR: calls 3 and the second application throws before any exit => errored, message threw before reaching an exit on call 2 of 3: <message>`
- `EDGE: an exit probe of a callback the entry called fired before the throw, but none of the entry's own exits => errored`
