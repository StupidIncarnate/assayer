## What to implement

Today a `null` or `undefined` member of a union reaches the type reader's opaque `other` arm
(`read-type-fact-layer-transformer.ts`, the final `return { flavor: 'other', … }`), so it becomes a `TypeDescriptor` of
kind `unknown` whose only identifying field is the checker's display `text`. Reading that text to decide anything
would pull source-like text into analysis (`packages/core/CLAUDE.md` section 5.1). So the reader names the member by
the checker's own type flags instead, on an optional field `nullish: 'null' | 'undefined'`.

Add `nullish: z.enum(['null', 'undefined']).optional()` to the `unknown` arm of `typeDescriptorContract`, and the same
optional field to the `TypeDescriptor` type above it. It is optional and additive, so no reader that switches on
`kind` changes. Say in the PURPOSE block what it means: the member is the `null` type or the `undefined` type, read
from the checker's flags. The stub keeps its default.

## Tests

- `VALID: {kind 'unknown', text 'null', nullish 'null'} => parses`
- `VALID: {kind 'unknown', text 'x'} => parses without nullish`
- `INVALID: {kind 'unknown', nullish 'void'} => throws`
