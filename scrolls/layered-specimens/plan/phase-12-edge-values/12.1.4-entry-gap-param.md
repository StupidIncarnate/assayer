## Contract

`entryGapContract` gains `param: z.string().min(1).brand<'EntryGapParam'>().optional()`. It names the refused parameter,
so the generated test can compare `<entry>.<param>`. It is optional because the contract stays valid for a gap written
before a producer sets it. Task 12.2.4 makes the one producer set it.

Update the PURPOSE block: `name` keys the gap to its entry, `param` names the first parameter the entry could not build,
in declaration order, and `reason` still names every refused parameter.

The stub's default gains `param: 'report'`, so a stub-built gap shows the full shape.

## Tests

- `VALID: {gap with param 'report'} => parses and keeps param`
- `VALID: {gap without param} => parses and has no param key`
- `INVALID: {param: ''} => fails`
