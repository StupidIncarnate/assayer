## Read first

The guard and its PURPOSE block. Tasks 12.2.5 and 12.2.6 make a union's `null` and `undefined` members descriptors of
kind `unknown` with `nullish: 'null'` or `nullish: 'undefined'`. The guard has two uses: `{ type }` asks whether a value
of the type can be built, and `{ type, value }` asks whether a given value is a value of the type.

## What to implement

`cause-arrange` re-checks every value it builds against the parameter's declared type with
`isTypeFillableGuard({ type, value })`. Today a union's `undefined` and `null` members read as `unknown` and refuse. Make
the value check accept, reading only `kind` and `nullish`, never `text`:

- `null` for a descriptor `{ kind: 'unknown', nullish: 'null' }` or a union with such a member,
- `{ $assayer: 'undefined' }` for a descriptor `{ kind: 'unknown', nullish: 'undefined' }` or a union with such a
  member. An optional parameter (`x?: T`) is left out by `applied-params`, so its descriptor needs no member for it,
- `{ $assayer: 'nan' }` for a type that is `number` or a union with a `number` member.

`{ type }` (no value) answers `true` for a descriptor with `nullish`, so a parameter typed
`number | undefined` stays fillable by its `number` member exactly as today. A union whose members are all `unknown` with no `nullish` still refuses. `unknown` and callables stay refused unconditionally (task 25.2.2 changes that for a guard-narrowed `unknown`,
not this task).

Update the PURPOSE block in plain words.

## Tests

- `VALID: {number | undefined, value { $assayer: 'undefined' }} => true`
- `VALID: {string | null, value null} => true`
- `VALID: {number, value { $assayer: 'nan' }} => true`
- `VALID: {number | undefined} with no value => true`
- `INVALID: {number, value { $assayer: 'undefined' }} => false`
- `INVALID: {string, value { $assayer: 'nan' }} => false`
- `INVALID: {unknown} => false` (unchanged)
