## What to implement

`deriveCasesTransformer` enumerates buckets with `inputBucketsTransformer`, arranges each with `causeArrangeTransformer`,
and keeps the cases that are not duplicates. Task 12.3.3 added pinned buckets, and task 12.4.1 made `cause-arrange` apply a
pin. This task connects them:

1. **Pass the pin.** Call `causeArrangeTransformer` with `pin: bucket.pin` for each bucket (absent when the bucket has
   none).
2. **Pass the operands.** Call `inputBucketsTransformer` with `operands` set to the applied parameters (the `applied`
   list this file already computes with `appliedParamsTransformer`), each as `{ name, type }`. The transformer ignores
   them when the entry has a branch or a `returnPredicate`. For a branchless entry with no predicate (card
   `edge/mixed-plus`, `base + extra`), they give one case per edge value of each parameter, one at a time, with every
   other parameter at its first value. A parameter whose type has no scalar edge value (an object, a callable) gets none.
3. **A pinned case keeps the arms of its bucket.** A case's `arms` are the arms its bucket took (`bucket.arms`). A
   pinned bucket is built with the arms its pinned value lands on, so `count 0` on `if (count > 2)` is an `else` case.
   Never label an arm first and then pick an input; never fill in an arm from a default.
4. **De-duplicate in bucket order.** The existing de-duplication by `(exit, arms, arrange)` already keeps the earliest of
   two equal cases, so an ordinary value that is also an edge value is listed once (cause rule step 4). Keep the ordinary
   buckets first, as `input-buckets` orders them. Add a test that pins the order.
5. **Drivability of a pinned case** is the drivability of its bucket's branches (section 5.12). A pinned bucket on an
   undriven branch is an undriven case and never runs.
6. **Fewest runs is unchanged.** `fewestRunsTransformer` receives the larger case list and keeps its own tie-break. Two
   cases with the same arms are one candidate, so edge cases never grow the run set beyond the arms they take.
7. **Rule-named values need no code here.** Task 12.3.3 emits the loose-equality value as a pin. State this in the PURPOSE
   block. The mixed-plus value (`'1'` for a string member of `base + extra`) is not produced here: core records no
   `+` operator fact before phase 21, so `base` takes the string member's ordinary value. Tasks 21.12.1, 21.13.1 and
   21.14.1 add it. Route values are not compared by a generated test, so card `edge/mixed-plus` keeps its nine routes
   either way.

Update the PURPOSE block in plain words: a case set is the ordinary routes first, then one case per pinned edge value.

## Tests

Assert whole case lists (`reachesPath`, `arms`, `arrange`, `driven`, `fewestRuns`) with `toStrictEqual`, written by hand
from the cards.

- `VALID: {returnPredicate count === 7, count: number} => five cases: 7 (return-true), then 8, 0, NaN, -1 (return-false)`; `fewestRuns` marks two (card `eq/alone`)
- `VALID: {if (count > 2) return 'then'; return 'else'} => cases 3 (then), 2, 0, NaN, -1 (else); fewestRuns marks two` (card `route/direct`)
- `VALID: {return name ?? 'anon', name: string | undefined} => 'abc123', '' on the left arm; undefined on the right arm` (card `nullish/alone`)
- `VALID: {returnPredicate value == 0, value: number | string, loose} => seven cases` (card `edge/loose-equality`)
- `VALID: {no branches, base: number | string, extra: number} => one case per edge value of each parameter, others at first value`
- `EDGE: {an ordinary value equals an edge value} => listed once, in bucket order`
- `EDGE: {a pinned bucket on an unsteerable branch} => the case is undriven`
- `EMPTY: {no parameters, no branches} => the single case, as today`
