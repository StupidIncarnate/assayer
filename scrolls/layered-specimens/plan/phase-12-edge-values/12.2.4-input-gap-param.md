## What to implement

`inputGapTransformer` returns one gap per entry. Set the new `param` field on it to the name of the first refused
parameter, in the order the refusals arrive after de-duplication (the first element of `distinct`). `name` stays the entry
name and `reason` stays word for word as it is today, so no existing message test changes.

A refusal owned by a folded private function or callback keeps `name` as the entry the reader can drive; `param` is the
refused parameter's own name. State in the PURPOSE block that an entry with several refused parameters reports the first
in `param` and all of them in `reason`.

## Tests

Add to the existing tests (do not change their expected `reason` text):

- `VALID: {entryName 'entry', one refusal { param: 'check' }} => the gap has name 'entry' and param 'check'`
- `VALID: {two refusals 'a' then 'b'} => one gap, param 'a'`
- `VALID: {a refusal with owner 'helper'} => name is the entry, param is the refused parameter`
- `EMPTY: {no refusals} => []`
