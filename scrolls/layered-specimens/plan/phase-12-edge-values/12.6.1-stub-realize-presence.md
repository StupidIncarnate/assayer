## What to implement

`stub-realize` enumerates the entry's input buckets and arranges each object parameter with `object-arrange`. Task 12.3.3
made some buckets carry a `pin`; task 12.5.3 made `object-arrange` accept it.

1. **Pass the pin.** In the `objectArrangeTransformer` call, add `pin: bucket.pin`. `object-arrange` uses it only for a
   `has-property` requirement whose property key (`<param>.<path>`) equals `pin.operand`, so passing it for every object
   parameter is safe.
2. **Pass the compiler option.** Read `exactOptionalPropertyTypes` once per call of the broker, from the options of the
   tsconfig that owns `relPath` under `root`: `tsconfigOwnerBroker` finds the owner, `analysisOptionsTransformer` cuts its
   options to the analysis list, and `analysisOptionsStatics.arrangement` names the option (task 12.5.4). A file no tsconfig
   owns gets `false`. Pass it as `exactOptionalPropertyTypes` in the `objectArrangeTransformer` call.
3. **A dropped bucket stays dropped.** `object-arrange` returns `unreachable: true` for the present-as-`undefined` form
   under the option, and the broker already drops an unreachable bucket (`entry.unreachable`).
4. **Pinned buckets keep their order and de-duplication.** The signature of a case already includes its arrangement, so a
   pinned bucket whose arrangement equals an ordinary one is listed once.
5. Add the new broker dependency to the proxy the way sibling proxies do, and update the PURPOSE block in plain words.
