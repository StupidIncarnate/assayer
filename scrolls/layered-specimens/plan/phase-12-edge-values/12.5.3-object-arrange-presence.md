## Read first

`object-arrange-transformer.ts`, `arrange-object-properties-transformer.ts` (the recursive picker it delegates to) and
section 9 of `packages/core/CLAUDE.md`. A `'label' in options` check is the object-member read `options.label` with
predicate `has-property` (task 12.2.3), so it reaches this transformer the way `config.mode === 'a'` does.

## What to implement

1. New inputs: `pin?: { operand: string; value: ArrangeValue | null }` (the bucket's pin, task 12.3.3; the operand is
   `<param>.<property path>`) and `exactOptionalPropertyTypes?: boolean` (default `false`; the file's compiler option, read
   by task 12.6.1).
2. Among the own requirements, split off those whose leaf predicate is `has-property` or `lacks-property`. Delegate the
   rest to `arrangeObjectPropertiesTransformer` as today.
3. For each split-off requirement, with the property named by the leaf's `operandPropertyPath` (walk a nested path through
   the arranged `properties`, creating nested objects with `fillValueTransformer` on the declared type):
   - `has-property` wanted `true`, no matching pin: the property is present with a value built by
     `fillValueTransformer({ type: <the property's declared type> })`.
   - `has-property` wanted `true`, with a pin whose `operand` equals `<param>.<path>`: the property is present with
     `pin.value`. A pin value of `{ $assayer: 'undefined' }` is the present-as-`undefined` form; when
     `exactOptionalPropertyTypes` is `true` TypeScript refuses it, so return
     `{ unreachable: true, unfillable: false, properties: [] }` and the caller drops the bucket. Any other pin value (`''`
     for a string property) is the edge value the property takes.
   - `has-property` wanted `false`, or `lacks-property` wanted `true`: the property is missing, removed from the result.
   - A required property named by a `has-property` requirement wanted `false` is `unreachable: true`.
   - Two requirements that disagree about one property make the bucket `unreachable: true`.
4. A corrected property (`corrected`) stays authoritative: a human correction wins over the generated form, and a
   correction that cannot satisfy the requirement is `unreachable: true`, as for every other predicate.
5. Update the PURPOSE block in plain words.
