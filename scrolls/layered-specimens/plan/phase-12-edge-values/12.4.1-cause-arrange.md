## What to implement

1. **A new input.** `causeArrangeTransformer` takes `pin?: { operand: string; value: ArrangeValue | null }` (the bucket's
   pin from task 12.3.3; task 12.5.1 passes it from `derive-cases`). It is typed from `InputBuckets[number]['pin']`.
2. **A pin sets the operand.** When `pin` is present, the operand whose key equals `pin.operand` takes `pin.value`
   instead of the value the domain math picks. A scalar parameter becomes a `param` binding with that value; `{ $assayer:
   'undefined' }` and `{ $assayer: 'nan' }` are valid `param` values (task 12.1.2). A raw env operand becomes an `env`
   binding: `{ $assayer: 'undefined' }` is the binding with no `value` (the variable is unset), `''` is `value: ''`, any
   other string is that string. Every other operand takes the value the domain math gives, exactly as today. The
   re-check `isTypeFillableGuard({ type, value })` that follows still runs on the pinned value.
3. **Replace the array full product** (the `arrayCombos` reduce at line 429). Today an arrangement is built for every
   combination of every array parameter's three sizes, times every scalar binding: with k array parameters the count
   grows as 3^k. Replace it:
   - The **base** arrangement takes every array parameter at its first size, in `arrayCardinalityStatics.order` (or the
     single length a `.length` domain names, as today).
   - Then, for each array parameter A in parameter order, and for each remaining size s of A in order (`one`, `many`,
     and any `extraLengths` an index demand adds), add one arrangement with A at s and every other array parameter at its
     base size. Never combine two parameters' non-base sizes.
   - An array's element values stay what `arrayArrangeTransformer` builds for the one-item array; the many-item array
     mixes elements as it does today. Element-level values (the one-item array holding an element's edge value) arrive as
     a pin on the array parameter itself: when `pin.operand` is an array parameter, `pin.value` is an array, and the
     binding is an `array` binding holding exactly that value, in place of the size fan-out for that parameter. Tasks
     13.4.1 and 14.3.2 create those pins. Cover this with a test.
   - The scalar `bindings` list is crossed with these arrangements as before (one per binding), so a bucket with no
     array parameter is unchanged and a bucket with one array parameter keeps its three sizes.
4. Update the PURPOSE block in plain words.
5. Rewrite the text in `packages/core/CLAUDE.md` that describes the old behaviour, in the present tense and without
   history words: the section 4 entry "Fan an array parameter out over cardinality" (it names "the array-cardinality
   cartesian product folded into `transformers/cause-arrange`") and the sentence in section 5.13 that says every array
   parameter spans its cardinalities. State the new rule: one base arrangement, then one arrangement per remaining size of
   one array parameter, and a pinned operand takes its pinned value. Add a short entry to section 4 for the pin:
   "Give one operand an edge value: touch `input-buckets` (which buckets pin an operand) and `cause-arrange` (which applies
   the pin)".

## Tests

- `VALID: {pin { operand: 'count', value: 0 }} => the arrangement binds count to 0 and every other param as without a pin`
- `VALID: {pin { operand: 'count', value: { $assayer: 'nan' } }} => a param binding carrying the tagged value`
- `VALID: {pin { operand: 'count', value: { $assayer: 'undefined' } }, count: number | undefined} => a param binding carrying undefined`
- `VALID: {env operand MODE, pin { $assayer: 'undefined' }} => an env binding with no value`
- `VALID: {env operand MODE, pin ''} => an env binding with value ''`
- `VALID: {one array param} => three arrangements, sizes empty, one, many, in that order` (unchanged behaviour)
- `VALID: {two array params, a and b} => 1 + 2 + 2 = 5 arrangements: both empty; a one; a many; b one; b many (not 9)`
- `VALID: {three array params} => 7 arrangements`
- `VALID: {pin { operand: 'items', value: [0] }, items: number[]} => an array binding [0] and no size fan-out for items`
- `EDGE: {array param with an index demand extra length 3} => the base plus one arrangement per remaining size, including 3`
- `ERROR: {pinned value that does not satisfy the declared type} => the existing "Assayer contradicted a type it read itself" error`
