## Contract

`inputBucketsContract` gains one optional field on a bucket:

```ts
pin: { operand: string; value: ArrangeValue | null }   // optional
```

- `operand` is the operand key `cause-arrange` already keys the operand's domain by (`operand-key`): the parameter name,
  or the env read-and-steps name. For a `has-property` leaf it is `<operandParamName>.<operandPropertyPath>`
  (`options.label`), the name of the property the `in` check reads.
- `value` is the value that operand takes in this bucket. It is a representative value, or a tagged value from task
  12.1.2 (`{ $assayer: 'undefined' }`, `{ $assayer: 'nan' }`). `null` is the JSON null.
- Absent means the bucket takes its operand values from the domain math, as today.

## What to implement

Today a bucket is one route: one arm, with its short-circuit causes, at every branch the route meets. Keep every bucket
that exists. Add, after them in a fixed order, the buckets that pin one operand. This is the cause rule (README):

1. **Which operands.** A leaf is pinnable when its operand is a plain scalar parameter or a raw env read, and its
   predicate kind is a value comparison or a truthiness or nullish read (`eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `truthy`,
   `falsy`, `non-nullish`, `undefined-eq`, `undefined-neq`, `typeof-eq`, `typeof-neq`, `includes`). A leaf on an object
   member, an array `.length`, or a welded constant is not pinnable (arrays are task 12.4.1's; object members are the
   stub overlay's). The returned comparison (`returnPredicate`) is read the same way. One exception: a `has-property`
   leaf (task 12.2.3 reads `'label' in options` as the object-member read `options.label`) is pinnable, and its
   candidate values are different, see step 2.
2. **Which values.** For one pinnable leaf, the values are, in this order, with duplicates removed:
   - the edge values of its operand type: `edgeValueStatics` (`0`, `NaN`, `-1` for a number; `''` for a string; `false`
     for a boolean), then `undefined` and `null` where the type allows each (a union member, or an optional parameter);
   - one ordinary value per scalar base member of a union type (a `number | string` leaf gets a number and a string),
     read from `typeToRangeTransformer` on the member type alone and `domainValuesTransformer`, so each member lands on
     the arms it can reach;
   - the rule-named value: when the predicate has `loose: true`, its literal is the number `0`, and the operand type has
     a `string` member, the value `edgeValueStatics.ruleNamed.looseEquality`;
   - for a `has-property` leaf only: the property present as `undefined` (`{ $assayer: 'undefined' }`), then each edge
     value of the property's own type (`''` for a string), every one landing on the `true` arm. The ordinary `true`
     bucket is the "present with a value" form and the ordinary `false` bucket is the "missing" form. Whether the
     present-as-`undefined` form is legal depends on `exactOptionalPropertyTypes`, which this transformer does not know;
     the object arranger drops it (task 12.5.3), and `stub-realize-broker` passes the pin to it (task 12.6.1).
3. **Which arm a value lands on.** Evaluate the leaf's predicate on the value with JavaScript's own semantics for that
   kind (for an `eq` with `loose: true`, `==`; otherwise `===`; `NaN > 2` is false; `typeof`; truthiness; `??`
   nullishness; `includes` on a string, false for a non-string). This evaluates a predicate on an INPUT to place it on an
   arm. It never runs the code under test (rule P4). Write the evaluation as a `const` lookup keyed by the predicate kind
   in the transformer's file, and say in the PURPOSE block that `NaN` and `undefined` have no domain point, which is why
   the evaluation exists.
4. **Which route.** The cause rule's step 3, as DESIGN.md decision "Which value the other inputs take in an edge-value
   case" fixes it: while one operand takes the pinned value, every other operand takes the first value that lets the
   pinned operand be read, in then-first order (an operand's then-arm value before its else-arm value). So for a leaf
   L and a value v: among the ordinary buckets that meet L's branch and evaluate L, take R, the one in which every other
   leaf takes its `then` (first) arm where it can, read leaf by leaf in condition order: for `ready && count > 2`, the
   bucket where `ready` is true; for two `if`s in a row on `enabled` and `count`, the bucket where `enabled` takes `then`
   (card `shape/if-if/sequence/two-args`: `enabled true, count 0`). Build the new bucket from R: replace L's requirement by `{ leaf: L, want: landing }`
   where `landing` is step 3's answer, set `pin: { operand, value: v }`, and recompute `arms` for L's branch from the
   condition tree under the new truth value of L (the other leaves keep the `want` R gave them). A branch after it is met
   or not by `isBranchMetGuard` on the new arms. Two inputs never take a pinned value in one bucket.
5. **Consistent pins only.** Drop a candidate when another requirement of the same bucket on the same operand fails for
   the pinned value (evaluate that requirement's predicate the same way). A route whose pinned value contradicts a guard
   is not a route.
6. **Listed once.** Do not emit a candidate whose `(arms, requirements, pin)` equals an existing bucket's. `derive-cases`
   already de-duplicates equal arrangements; this keeps the bucket list small.
7. **No pins for an unread operand.** A parameter no pinnable leaf reads gets none (cause rule step 5).
8. An undriven (`unsteerable`) branch gets no pins: its route is declared, not run. (A `has-property` leaf's branch is
   undriven in the file's own analysis, because an object member is not scalar-arrangeable. Its pins are still emitted:
   the stub overlay drives them at run time. Derive-cases keeps them undriven until then, as it does for
   `config.mode === 'a'`.)
9. **A branchless entry.** Add an optional input `operands?: { name: string; type: TypeDescriptor }[]`. When `branches`
   is empty and there is no `returnPredicate`, emit one pin bucket per value in step 2's first three bullets for each
   operand, in parameter order, after the single empty bucket. These are the value-class cases of a branchless entry
   (card `edge/mixed-plus`'s `base 0`, `base NaN`, `base -1`, `base ''` routes). With a branch or a `returnPredicate`,
   `operands` is ignored. Task 12.5.1 passes it.

Update the PURPOSE block in plain words: the ordinary route buckets first, then the pinned buckets, and why.

## Tests

Build leaves with the leaf stubs; assert whole bucket lists with `toStrictEqual`, written by hand from the cards.

- `VALID: {if (count > 2) as one branch, count: number} => the ordinary then and else buckets, then pins 0, NaN, -1 on else, none on then` (card `ternary/as-value`: `count 3` then; `2, 0, NaN, -1` else)
- `VALID: {ready && count > 2 in an if} => ordinary buckets as today, then count pins 0, NaN, -1 each with ready true and the else arm` (card `and/as-condition`)
- `VALID: {returnPredicate count === 7} => pins 0, NaN, -1 each with predWant false` (card `eq/alone`)
- `VALID: {name ?? 'anon', name: string | undefined} => pin '' lands on the left arm, pin undefined on the right arm`
- `VALID: {count: number | null | undefined, count === undefined then count == null} => pins undefined, null, 0, NaN, -1 on the arms they land on` (card `nullable/undefined-vs-null`)
- `VALID: {value == 0, value: number | string, loose} => pins '' and '0' land true; NaN, -1 land false; one ordinary pin per member type` (card `edge/loose-equality`)
- `VALID: {if (count) , count: number | undefined} => pins 0 and NaN and undefined on the else arm; -1 on the then arm` (card `edge/truthiness`)
- `VALID: {'label' in options, label?: string} => the ordinary then and else buckets, then pins { $assayer: 'undefined' } and '' on then` (card `nullable/optional-property-in`: `{}`, `{ label: undefined }`, `{ label: 'x' }`, `{ label: '' }`)
- `VALID: {no branches, operands base: number | string and extra: number} => the empty bucket, then pins for base (0, NaN, -1, '', one ordinary per member) and extra (0, NaN, -1)`
- `EDGE: {a leaf on config.mode (object member, not has-property)} => no pins`
- `EDGE: {a welded constant leaf} => no pins`
- `EDGE: {pinned value contradicts a second guard on the same operand} => the candidate is dropped`
- `EMPTY: {no branches, no returnPredicate} => the single empty bucket, no pin`
