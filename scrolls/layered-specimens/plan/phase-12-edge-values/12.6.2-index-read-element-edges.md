## What to implement

Task 12.3.3 left a leaf on an array element unpinnable ("arrays are task 12.4.1's"). Task 12.4.1 lets `cause-arrange`
apply a pin whose value is a whole array. This task emits those pins for an index read:

1. **Which leaves.** A leaf whose `operandParamName` is an array parameter and whose `operandPropertyPath` is exactly
   one index segment, `['[<i>]']` (task 12.1.7: `counts[0] > 2` reads as `counts` with the path `['[0]']`). Build the
   pins from those two fields only, never from source text.
2. **Which values.** The element type's edge values (`edgeValueStatics`, then `NaN`, then `undefined` and `null` where
   the element type allows them), as in task 12.3.3 step 2.
3. **Which pin.** For index `i` and value `e`: `pin: { operand: <the array parameter>, value: <an array of length
   i + 1 whose item i is e and whose other items are the element type's ordinary value> }`. Its landing arm is the arm
   `e` takes, by the evaluation of task 12.3.3 step 3.
4. Emit these pins after the ordinary buckets and the scalar pins, in leaf order, then value order. The empty and
   many arrays stay the size fan-out of task 12.4.1, so they are not pinned here.
