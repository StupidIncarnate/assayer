## What to implement

`edgeValueStatics` is the one place core names the scalar edge values. Write it from DESIGN.md's "Edge values" table,
not from the generator's `edge-value-statics.ts`. The two are written independently so they can disagree (rule P4, one
level up).

```ts
export const edgeValueStatics = {
  number: { zero: 0, negative: -1 },
  string: { empty: '' },
  boolean: { falsy: false },
  object: { empty: {} },
  ruleNamed: { looseEquality: '0' },
} as const;
```

- `NaN`, `undefined` and `null` are not entries. JSON cannot hold `NaN` or `undefined`, so core carries them as the
  arrange values task 12.1.2 adds, and `null` is already a representative value. Say this in the file's PURPOSE block.
- `array` sizes are not entries either. `arrayCardinalityStatics` already owns `empty`, `one` and `many`.
- `ruleNamed.looseEquality` is the string that a loose-equality check against the number `0` treats as equal to it
  (`'0' == 0`). It is a case because the edge-value-merge rule "loose equality" names it (DESIGN.md: "`'0'` is not an
  edge value of string. It is a case because the loose-equality rule names it"). Task 12.5.1 reads it.
- The PURPOSE block states, in plain words, what an edge value is and which tasks read this file (12.3.3, 12.4.1,
  12.5.1).
