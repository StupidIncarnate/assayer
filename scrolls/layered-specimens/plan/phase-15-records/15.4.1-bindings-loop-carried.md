## Contract

`readStatementBindingsLayerTransformer` keeps its signature.

| Statement the reader meets | Binding afterward |
|---|---|
| declaration `let x = init` whose write class is `'loop'` | `repeat(per 'pass', loop: <id of the loop>, op, receiver: <flow of init>, args: [<change>])` |
| `x op= rhs` whose class is `'loop'` (the loop-carried write itself, read in the loop body) | `apply(op, <binding of x>, <change>)`: the value after the write in this pass |

`<change>` is the right side read through `readValueExprLayerTransformer` with the bindings in effect, and it must hold
no `select`. One more case: when the loop is a `for…of` and the right side is the loop's head variable, the change is
`element(receiver: <flow of the iterated expression>)`.

The loop id is `deriveLoopIdLayerTransformer({ node: <the loop statement>, scopePath: context.scopePath })`.

## What to implement

1. For a declaration, call `readWriteTrackingLayerTransformer` (task 15.2.1). On `'loop'`, find the one write through the
   declaration name's references (the same checker call task 15.2.1 uses), take the write statement's loop, and build the
   `repeat`. If the write is not a compound operator, or its change is unreadable, the variable gets no binding.
2. For the write statement itself, build `apply(op, <binding of x>, <change>)`.
3. Do not touch the loop statement itself: the reader returns `before` for it. The `repeat` made at the declaration is
   what the loop's condition, its body and the code after it all read. Which count of passes a read means is chosen later
   by `derive-cases` from where the read sits (task 15.5.2).
4. Update the header comment: the loop class and the two bindings.

## Tests

- `VALID: let count = 0 before while (count < limit) { count += 1; } => repeat per pass, receiver lit 0, args [lit 1]`
- `VALID: let total = 0 before for (const item of items) { total += item; } => repeat per pass with args [element(param items)]`
- `VALID: the statements of the loop followed by the loop statement => the binding is unchanged after the loop`
- `VALID: count += 1 as a statement of the loop body => apply(add, repeat, lit 1)`
- `VALID: the loop id in the repeat equals deriveLoopIdLayerTransformer of the loop`
- `INVALID: total += compute(item) => no binding (unreadable change)`
- `INVALID: count += (a ? 1 : 2) => no binding (the change holds a select)`
- `INVALID: a loop variable written twice => no binding`
- `EDGE: the existing assignment, ternary, if-join and task 15.3.2 tests still pass unchanged`
