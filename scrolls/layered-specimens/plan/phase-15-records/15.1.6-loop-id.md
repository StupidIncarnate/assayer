## Read first

`handle-loop-layer-transformer.ts` (task 14.2.1). It builds the loop's coverage id inline as
`coverageIdTransformer({ scopePath: context.scopePath, segment: 'loop:' + projectNodeLayerTransformer({ node: <the test, or the iterated expression> }) })`.
Task 15.4.1 builds a `repeat` value that names the loop by this id, and the statement reader has no handler to ask. One
transformer owns the formula so the handler and the reader cannot disagree.

## Contract

```ts
deriveLoopIdLayerTransformer({ node, scopePath }: { node: ForStatement | ForOfStatement | ForInStatement | WhileStatement | DoStatement; scopePath: ... }): <what coverageIdTransformer returns> | undefined
```

- `for…of` and `for…in`: the node projected is the iterated expression (`getExpression()`).
- `while` and `do…while`: the node projected is the test (`getExpression()`).
- `for`: the node projected is the test (`getCondition()`). A `for` with no test has no loop branch (task 14.2.1), so the
  answer is `undefined`.

## What to implement

1. Create the transformer with the formula above.
2. In `handle-loop-layer-transformer.ts`, replace the inline id with a call to the new transformer. Do not change any other
   line.
3. PURPOSE block in plain words: which node each loop kind projects, and why the formula lives in one file.

## Tests

- `VALID: while (count < limit) {} => the id equals coverageIdTransformer with segment 'loop:' plus the projection of count < limit`
- `VALID: for (const item of items) {} => the projection of items`
- `VALID: for (const key in record) {} => the projection of record`
- `VALID: do {} while (count < limit) => the projection of count < limit`
- `VALID: for (let i = 0; i < n; i += 1) {} => the projection of i < n`
- `VALID: 'while(count<limit)' and 'while ( count < limit )' => identical ids`
- `EMPTY: for (;;) {} => undefined`
