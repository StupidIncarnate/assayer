## Contract

```ts
deriveBranchIdLayerTransformer({ node, scopePath }: { node: IfStatement | BinaryExpression; scopePath: ... }): ...same return as today
```

For a `BinaryExpression` whose operator token kind is `QuestionQuestionEqualsToken`, `BarBarEqualsToken` or
`AmpersandAmpersandEqualsToken`, the id is

```ts
coverageIdTransformer({ scopePath, segment: 'logical-assign:' + projectNodeLayerTransformer({ node: left }) + ':' + <operator token kind name> })
```

`left` is the assignment's left side. The operator part is the token's kind name (`getOperatorToken().getKindName()`),
never the token's text. Any other `BinaryExpression` is a programming error: throw an `Error` whose message is
`deriveBranchId: a binary expression must be a logical assignment, got operator kind <kind name>`.

## Tests

- `VALID: label ??= 'anon' => the id ends with the segment logical-assign:<projection of label>:QuestionQuestionEqualsToken`
- `VALID: the three operators on one left side => three different ids`
- `VALID: this.name ??= 'x' => an id built from the projection of this.name`
- `VALID: 'a??=b' and 'a ??= b' and 'a ??= ( b )' => identical ids` (formatting immunity)
- `VALID: two assignments to different left sides => different ids`
- `ERROR: a += b => throws the message above`
