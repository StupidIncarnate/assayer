## What to implement

1. After `routeResolve`, find each **pair leaf** in `derived`: its `operandFlow` is `apply(subtract, param a, param b)`, its
   predicate compares with `0`, and both `a` and `b` are applied number parameters. The predicate kind (`gt`, `gte`, `lt`,
   `lte`, `eq`, `neq`) is the `kind` passed to `pairCandidatesTransformer`.
2. For the route's wanted arm of that leaf, take each pair from `pairCandidatesTransformer` whose `holds` equals the wanted
   truth value of the leaf. Each such pair is one case. The case keeps the arrangement `causeArrange` gave every other
   parameter, and sets `a` and `b` to the pair. A `NaN` side becomes the arrange value task 12.1.2 defines.
3. Run `derivedGuardWitnessesTransformer` on each case, so any other derived leaf of the route still has to hold.
4. Every pair is its own case in the every-route set even when two pairs take the same arms, because each edge value is its own
   cause (README "The cause rule" step 2). Fewest runs keeps the earliest, which is the anchor pair, so the order of the list
   decides it.
5. A pair leaf whose parameters are not both applied number parameters, or whose predicate has no pair kind, stays a derived
   requirement the existing code admits as undriven. Both arms stay routes. Never drop them.
6. Header comment: the pair rule and the order of the cases.
