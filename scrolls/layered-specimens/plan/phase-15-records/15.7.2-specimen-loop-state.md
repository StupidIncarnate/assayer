## What to implement

1. The specimen has two entries in one file:

   ```ts
   export const countUp = (limit: number): number => {
     let count = 0;
     while (count < limit) {
       if (count === 3) {
         break;
       }
       count += 1;
     }
     return count;
   };

   export const sumAbove = (items: number[]): string => {
     let total = 0;
     for (const item of items) {
       total += item;
     }
     if (total > 10) {
       return 'big';
     }
     return 'small';
   };
   ```

2. The test asserts, per entry, what the cards say. Write the expected values by reasoning from the cards.
   - `countUp`: two branches, a `loop` (arms `skipped`, `runs`) and an `if` (arms `then`, `else`). Five routes: `skipped`
     three times (the cause rule gives `limit` the values 0, `NaN` and -1 on that arm), `runs, else` once, and
     `runs, else, then` once. The route `runs, else, then` needs a pass where `count` is 3, so its `limit` is above 3.
     The fewest-runs set holds 2 cases: one `skipped` and `runs, else, then`.
   - `sumAbove`: the same two branch kinds. Seven routes: `skipped, else` for the empty array; `runs, else` for the
     one-item arrays `[10]`, `[0]`, `[NaN]` and `[-1]`; `runs, then` for `[11]` and for a two-item array whose items add above
     10. The fewest-runs set holds 2 cases: the empty array and `[11]`.
   - no dark spot, no undriven entry, no gap and no lint: the file runs clean, so it sits under `happy-path/`.
   Assert the arm lists and the case counts. Assert an arranged value only where the predicate pins it (`[11]`, an item of
   `10`, `NaN` and `-1`).
