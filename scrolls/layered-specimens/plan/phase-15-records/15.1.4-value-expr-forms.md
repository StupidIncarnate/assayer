## Contract

A value expression says what a local variable holds at the point a branch reads it. Three new forms say what a
write that repeats leaves behind. All three carry `receiver` and `args`, the two fields the `method` form already
has. That keeps the existing readers compiling: `value-expr-params-transformer.ts`,
`value-expr-resolve-transformer.ts` and `value-expr-evaluate-transformer.ts` each end in a branch that reads
`expr.receiver` and `expr.args` after they have excluded `param`, `lit` and `select`.

```ts
// arithmetic on two values: receiver op args[0]
{ kind: 'apply'; op: 'add' | 'subtract' | 'multiply'; receiver: ValueExpr; args: [ValueExpr] }

// receiver is the starting value. args[0] is the change one pass (or one call) makes. The value is the
// starting value with `op args[0]` applied once for every completed pass of `loop`, or once for every
// call made before the current one when `per` is 'call'.
{ kind: 'repeat'; per: 'pass' | 'call'; loop?: string; op: 'add' | 'subtract' | 'multiply'; receiver: ValueExpr; args: [ValueExpr] }

// the item a loop pass reads from the collection `receiver`. Only valid as the change of a 'pass' repeat.
{ kind: 'element'; receiver: ValueExpr; args: [] }
```

Rules the contract states and the producers (tasks 15.3.2, 15.4.1, 15.5.1) and consumers (tasks 15.2.2, 15.3.3) follow:

- `loop` is the coverage id of the `loop` branch (phase 14) and is present exactly when `per` is `'pass'`. Zod 4 allows a
  `.check` on an object member of a discriminated union; use it. If it does not, state the rule in the header
  comment and let the evaluator return `undefined` for a `repeat` that breaks it.
- A form never holds a `select` below a `repeat` or an `element`. A write that depends on a branch (`if (x) count += 1`)
  is not modelled, so the variable is not followed and its branches stay undriven.
- The value after the write in the same pass or call is `apply(op, repeat(...), args[0])`. A read before the write sees
  the bare `repeat`.
