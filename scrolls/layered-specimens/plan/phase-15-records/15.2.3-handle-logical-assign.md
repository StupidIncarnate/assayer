## Contract

Input: a `BinaryExpression` whose operator token kind is `QuestionQuestionEqualsToken`, `BarBarEqualsToken` or
`AmpersandAmpersandEqualsToken`, and the walk context. Output: a `HandlerResult` with `branches`, `nodes` and `descents`.

The branch:

| Field | Value |
|---|---|
| `coverageId` | `deriveBranchIdLayerTransformer({ node, scopePath: context.scopePath })` |
| `kind` | `'logical-assign'` |
| `arms` | `['kept', 'assigned']` |
| `condition` | holds when the old value is **kept**: `??=` a `non-nullish` leaf on the left side; `\|\|=` a `truthy` leaf; `&&=` a `not` over a `truthy` leaf |
| `guardPath` | `context.guardPath` |
| `startLine`, `endLine` | the expression's lines |

The first arm, `kept`, is the one taken when the condition holds. Confirm that against
`branch-arm-options-transformer.ts` as phases 13 and 14 left it. If it reads `arms` another way, follow it and report.

Leaf ids follow `read-condition-tree`: the branch id plus `#leaf`. Build the leaf for the left side through
`buildConditionLeafLayerTransformer` with a readout of `{ operandNode: left, operandName?, predicate }`, so the leaf
carries the same operand facts every other leaf carries (type, flow, env, constant).

Descents:

- the left side, under the enclosing guards with `tail: false`, because it is read before the arm is chosen;
- the right side, under the guard step `{ branchCoverageId, arm: 'assigned' }` with `tail: false`, because it runs only
  when the assignment happens.

The handler emits one walk node of the expression's kind with `handled: true`. It emits no exit and no
completion: an assignment is a statement in a sequence and falls through to the next statement.

## What to implement

1. Write the handler. Read the operator from the token kind. Never read the operator's text.
2. Write the empty proxy, the same shape the other handlers' proxies have.
3. Header comment: the three operators, the arms, why the condition holds on `kept`, and that the right side is guarded
   by `assigned`.
