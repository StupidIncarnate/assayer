The whole of `follow-calls-transformer.ts`: its header lists the ways a private is reached, and `REACHED_FN_REASON` is the
admission a returned inline function gets. Read `throughClosureCasesTransformer` (task 15.6.2) and the closure shape check of
task 15.4.3.

## What to implement

A returned inline function that **takes no parameters** and whose host is a reachable scope with **no branch of its own** is
driven through its host.

1. Detect the shape the way the walk records a returned function (the code that raises `REACHED_FN_REASON`) and add the empty
   parameter list to the test.
2. Call `throughClosureCasesTransformer` and add its analysis to `followedEntries` as a `through-caller` entry named for the
   closure. Add its `unfillable` entries to `refusals` with the host as owner.
3. A returned function that takes parameters, or whose host branches, keeps `REACHED_FN_REASON` unchanged. A returned function
   with no branch is not followed, since the trigger is always a branch.
4. Update the header comment: the returned-closure bullet now says a no-parameter closure is driven through its host, and a
   closure with parameters is undriven because whoever applies it sets them. Update `REACHED_FN_REASON` only if it names the
   no-parameter case.

## Tests

- `VALID: makeCounter(limit) returns () => { uses += 1; if (uses > limit) … } => a through-caller entry for the closure with the host's params`

- `INVALID: return (n) => … => still undriven with REACHED_FN_REASON`
- `INVALID: a host that branches before returning the closure => still undriven`
- `INVALID: a closure with no branch => not followed`
