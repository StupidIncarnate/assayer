# 15.4.3 A returned closure's body reads its host's parameters

- **Phase:** 15, Core: compound assignment, loop-written variables, call sequences. **Row:** #4, in parallel with 15.4.1 and 15.4.2. No task of the row depends on another task of the row.
- **Depends on:** phase 14.
- **Model:** default (the worker's default model; this task is fully specified).
- **Covers:** DESIGN.md section "Shared mutable state" ("a variable a closure captures and changes"); the `closure-capture` value of the shared-state axis; card `callback/returned-closure`.

A function the walk enters starts with its own parameters. A returned closure that takes no parameters reads its host's
parameters by closure (`limit` in `return () => { uses += 1; if (uses > limit) … }`), and `readValueExprLayerTransformer` only
reads an identifier as a parameter when the context's `params` name it. So the closure's `limit` reads as unknown today
and its branch stays undriven.

## Read first

`packages/core/CLAUDE.md` section 2 (a function boundary extends `scopePath`, resets `guardPath` and `bindings`, and brings its own
`params`), section 5.3 (never climb for context), `handle-function-layer-transformer.ts` and `walk-context-transformer.ts`
(its `params` input). Read the shape check in `read-write-tracking-layer-transformer.ts` (task 15.2.1): a returned closure is a
function whose parent is a `ReturnStatement`, or the concise body of an arrow function, and whose parameter list is empty.

## What to implement

1. In `handle-function`, recognise a **returned no-parameter closure** with that shape check, reading the node's own parent once
   (a local property of the function node, not context).
2. For such a closure, build the context of its body with `params: context.params`, the host's parameters, through
   `walkContextTransformer`. Its scope record keeps `params: []`: the closure is not an entry with parameters of its own.
3. Every other function keeps its own parameters and nothing changes for it.
4. Header comment: the closure rule and why the closure's record keeps no parameters.

## Tests

- `VALID: return () => { if (uses > limit) {…} } inside makeCounter(limit) => the body context carries the param limit; the scope record has no params`
- `VALID: a concise arrow body that is a no-parameter closure (const make = (limit) => () => limit) => the same`
- `INVALID: return (n) => … (a closure with a parameter) => the body context carries only n`
- `INVALID: a no-parameter function that is not returned (a local helper) => the body context carries no host params`
- `INVALID: a callback passed to items.map => unchanged`
- `EDGE: a returned closure inside a returned closure => the inner body carries the params of its direct host`
- `EDGE: every existing handle-function test passes unchanged`
