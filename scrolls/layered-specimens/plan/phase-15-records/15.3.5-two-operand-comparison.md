## What to implement

1. **A comparison of two operands, one of them counted.** When `site` is a binary expression whose operator token kind is
   `GreaterThanToken`, `GreaterThanEqualsToken`, `LessThanToken`, `LessThanEqualsToken`, `EqualsEqualsEqualsToken` or
   `ExclamationEqualsEqualsToken`, and the readout's predicate is `unrecognized` because the right side is not a literal:
   - read each side as a value expression. An identifier reads through its binding or as the tracked parameter. A
     `this.<field>` reads through its binding (task 15.2.4). Anything else is unreadable.
   - proceed only when both sides read, both are numbers (the operand type for the left side, the parameter type for a
     parameter, `number` for a `repeat` or `apply`), and at least one side's expression holds a `repeat`. A comparison of
     two plain parameters is left as it is here. Task 15.7.3 reads that case.
   - the leaf then carries `operandFlow = apply(subtract, <left>, <right>)`, `operandType: { kind: 'number' }`, no
     `operandParamName`, `operandPropertyPath` or `operandTypeRef`, and the predicate `{ kind, literal: 0 }` where the kind
     follows the operator: `gt`, `gte`, `lt`, `lte`, `eq`, `neq`. `left - right > 0` is `left > right`.
2. Read the operator from the token kind. Never read the operator's text.
3. Update the header comment: the new case and why a comparison of two plain parameters is not read here (task 15.3.3 can
   only move a comparison onto a parameter when the other side is a counted literal).
