## Contract

`readStatementBindingsLayerTransformer` keeps its signature. A binding maps a declaration's position to the value
expression the variable holds. These are the new bindings.

| Statement the reader meets | Binding afterward |
|---|---|
| `x op= rhs`, `readWriteTrackingLayerTransformer` answers `'plain'` | `apply(op, <binding of x>, <flow of rhs>)` |
| `x ??= rhs`, `x \|\|= rhs`, `x &&= rhs` | `select(branch: <id of the logical-assign branch>, then: <binding of x>, else: <flow of rhs>)` |

`op` comes from the operator token kind: `PlusEqualsToken` is `add`, `MinusEqualsToken` is `subtract`,
`AsteriskEqualsToken` is `multiply`. The target `x` is an identifier or `this.<field>`; its declaration is the
identifier's value declaration, or the field's `PropertyDeclaration`. The branch id is
`deriveBranchIdLayerTransformer({ node: <the assignment>, scopePath: context.scopePath })` (task 15.1.5), the same id the
handler of task 15.2.3 gives its branch.

For `select`, `then` is the arm taken when the branch's condition holds and `else` the other. A `logical-assign` branch
lists its arms as `['kept', 'assigned']` and its condition holds when the old value is kept, so `then` is the old value
and `else` is the right side. This is true for all three operators (task 15.2.3 builds the condition that way).

A write whose class is `'loop'` or `'shared'` is not handled here: this task returns `before` for it. Tasks 15.4.1 and
15.5.1 handle those two classes.

## What to implement

1. Branch on the operator of an `ExpressionStatement`'s `BinaryExpression`: `EqualsToken` (as today), the three compound
   kinds, the three logical-assign kinds. Anything else returns `before` unchanged.
2. Build the binding in the table. A missing prior binding, an unreadable right side, or a class other than `'plain'`
   drops the variable's binding. Dropping is always safe: nothing after it reads a stale value.
3. A logical assignment on a parameter with no binding reads the prior value as `{ kind: 'param', name }`, because the
   parameter is followed when `readWriteTracking` is truthy.
4. Update the header comment: the two new statement kinds and the rule that an unreadable value drops the binding.

## Tests

Parse real source with the helpers the existing test file already uses. Compare each binding with `toStrictEqual` on the
whole object.

- `VALID: let total = 0; total += n; => apply(add, lit 0, param n)`
- `VALID: let label = name; label ??= 'anon'; => select(branch, then: param name, else: lit 'anon')`
- `VALID: ||= and &&= give the same select shape`
- `VALID: count -= 2 and count *= 3 => subtract and multiply`
- `VALID: a parameter written with ??= and no earlier binding => select(branch, then: param, else: the right side)`
- `INVALID: count++ => no binding for count`
- `INVALID: total += compute(item) => no binding (unreadable right side)`
- `EDGE: a logical assignment whose prior binding is missing and whose target is not a parameter => no binding`
- `EDGE: a compound write inside a loop body or on a module-level let => no binding (tasks 15.4.1 and 15.5.1 own those)`
- `EDGE: the existing assignment, ternary and if-join tests still pass unchanged`
