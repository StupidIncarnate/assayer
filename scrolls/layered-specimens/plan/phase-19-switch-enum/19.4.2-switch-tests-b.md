## What to implement

Each test asserts the analysis of one file. Before row #3 it saw one `switch` branch per case clause, each with `then` and `else`.
After row #3 it sees one branch per `switch` statement. For each of the three files:

1. Read the specimen and reason out, from the design, what the analysis holds: the one `switch` branch with its `arms`,
   `armConditions` and `condition`, its `guardPath`, the guard steps on every exit, and the cases.
2. Run a probe (`packages/core/CLAUDE.md` section 7) to see the real coverage ids and field order. Take the **structure** from
   the design and the **spelling of ids** from the probe. Treat any difference in structure as a defect to report, never as a
   value to copy.
3. Rewrite the expected objects. The arms the specimens use are:

   | Specimen | Arms | Cases |
   |---|---|---|
   | `switch/in-function` and `switch/in-class` | `case:get`, `case:post`, `default` | `get`, `post`, and the remaining member `delete` |
   | `env-object/multi-read` | the `if` has `then`, `else`; the `switch` on `Number(process.env.CODE)` has `case:1`, `case:2`, `default`. The leaves carry the environment fields | 2 times 3 routes: each `MODE` outcome with each `CODE` outcome, where the cause rule gives the value for each |

4. In `in-function.test.ts` the exits are now three: one under `case:get`, one under `case:post`, and the `default` exit under the
   `default` step alone. The `default` exit no longer carries a chain of `else` steps.
5. Keep each test's other assertions (parameter types, return types, lines) and update only what the new shape changes.
