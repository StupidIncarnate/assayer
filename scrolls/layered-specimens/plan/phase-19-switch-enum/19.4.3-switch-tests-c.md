## What to implement

Each test asserts the analysis of one file. Before row #3 it saw one `switch` branch per case clause, each with `then` and `else`.
After row #3 it sees one branch per `switch` statement. For each of the two files:

1. Read the specimen and reason out, from the design, what the analysis holds: the one `switch` branch with its `arms`,
   `armConditions` and `condition`, its `guardPath`, the guard steps on every exit, and the cases.
2. Run a probe (`packages/core/CLAUDE.md` section 7) to see the real coverage ids and field order. Take the **structure** from
   the design and the **spelling of ids** from the probe. Treat any difference in structure as a defect to report, never as a
   value to copy.
3. Rewrite the expected objects. The arms the specimens use are:

   | Specimen | Arms | Cases |
   |---|---|---|
   | `switch/no-default` | `case:get`, `case:post`. The parameter is `'get' \| 'post'` and both are labelled, so the switch is exhaustive and has no `no-match` arm | one case per arm; both reach the one enclosing exit, the first in the fewest-runs set and the second not |
   | `switch/pure-statement` | `case:1`, `case:2`, `default`, on `Number(process.env.CODE)`; the leaves carry the environment fields | `CODE` 1, `CODE` 2, and a third value for the default |

4. Keep each test's other assertions and update only what the new shape changes.
