## What to implement

For a branch of kind `switch` with `armConditions`, `branchArmOptions` returns, for each arm label in `arms`:

- each **case arm** `i`: one option per cause of `conditionCauses({ condition: armConditions[i], want: true })`, tagged with the
  guard step `{ branchCoverageId, arm: arms[i] }`. A group `case:a|b` has the condition `or(eq a, eq b)`, so it yields one cause
  per label. Mode `'a'` and mode `'b'` are two options with the same arm. That is how the card `switch/fallthrough` gets
  routes `mode 'a'` and `mode 'b'` on one arm;
- the **last arm**, when `arms` is longer than `armConditions` (`default` or `no-match`): one option per cause of
  `conditionCauses({ condition: branch.condition, want: false })`, tagged `arms.at(-1)`. `branch.condition` is the `or` of every
  group, so wanted false it requires every label to miss. For a literal union the type engine then picks each remaining member
  (the card `switch/no-default`: `mode 'c'`; the type table: `case 7` and no match `8`);
- an **exhaustive** switch has no last arm, so no option exists for it, and no route, case or lint is made for a value that
  cannot occur.

A branch no input can steer (its id is in `unsteerable`) offers one option per arm with no requirement, as the binary form does
today, so every route through it is declared and the caller marks it undriven.

A branch without `armConditions` keeps its current behaviour: two arms, `then` and `else`, or its own `arms` list for the
kinds phases 13 to 18 added.

Update the header comment: the switch form, the order of the options (arms in the order of `arms`, causes in the order
`conditionCauses` returns them, so the every-route and fewest-runs sets stay deterministic).

## Tests

Build the switch branches by hand with the stubs the test file uses (the contract field is optional, so a stub can set it).

- `VALID: arms ['case:a', 'default'] with armConditions [eq a] => options [case:a with eq a wanted true, default with eq a wanted false]`
- `VALID: arms ['case:a|b', 'default'] with armConditions [or(eq a, eq b)] => two options with the arm case:a|b, then default with both labels missing`
- `VALID: arms ['case:a', 'case:b', 'no-match'] => one option per case arm and a no-match option that misses both`
- `VALID: an exhaustive switch (arms equal armConditions in length) => no option beyond the case arms`
- `VALID: the card routes for switch/no-default (mode 'a' | 'b' | 'c'): driving buckets through input-buckets gives three routes, mode 'a', mode 'b', mode 'c'`
- `VALID: the card routes for switch/fallthrough: three routes, mode 'a' and mode 'b' on case:a|b, mode 'c' on default`
- `VALID: an unsteerable switch => one option per arm with no requirements`
- `VALID: a switch nested in a branch's arm => the existing met-by-guard rule still applies`
- `EDGE: a branch with no armConditions => unchanged then/else options`
- `EDGE: every existing test passes unchanged`
