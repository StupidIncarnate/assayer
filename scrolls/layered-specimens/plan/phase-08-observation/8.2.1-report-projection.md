## Contract

`specimenReportProjectionTransformer({ files, buildErrors, stubIndex }): SpecimenReport`

- `files`: one `{ relPath, ownAnalysis, analysis, scopes, run }` per analysed source file of the specimen folder (every direct non-test, non-harness `.ts` child), `entry.ts` first, then the others by `relPath`. `relPath` is specimen-relative. `ownAnalysis` is the file's own analysis, `analysis` the analysis after the five run-time overlays, `scopes` that file's walk scopes, `run` that file's own run result (task 8.3.1 runs every file in the specimen's mirror). `routes`, `fewestRuns`, `caseFailures` and `gaps` come from the `entry.ts` item's run; `branches`, `lints`, `undriven` and `darkSpots` merge every file.
- `buildErrors`: the compile errors for this specimen's folder.
- `stubIndex`: the stub index the mirror compile wrote (task 8.3.1), or `undefined` when the compile wrote none (it returns early on an unresolvable import).

## What to implement

- `branches`: for every item of `files`, every `BranchNode` of its `analysis` and of its `scopes`, merged by coverage id within the file, as `{ file: relPath, kind, line: startLine, arms }`. The branches of all files are concatenated.
  - For `if` and `ternary`, `arms` is `['then', 'else']`.
  - For any other kind, `arms` is the node's own `arms` list when the node has that field, otherwise the labels its cases take. Core phases 13 to 19 add the field.
  - A callback's `skipped` and `runs` steps, whose id matches no `BranchNode`, make one listed branch of kind `callback` at the start line of the scope the id names, in that scope's file.
  - `return-true` and `return-false` steps are never listed.
- `routes`: one row per case in the `entry.ts` item's `analysis.functions[].cases`. `arms` comes from `routeStepsLayerTransformer` (task 8.1.1), given maps built from every file of `files` so a step naming a branch in a sibling file gets that file. `driven` is the case's flag.
- `fewestRuns`: the number of cases with both `driven` and the fewest-runs flag true.
- `caseFailures`: each case of the `entry.ts` item's run whose status is not `passed`.
- `lints`: for every item of `files`, each lint of that item's `run.lints` (its run carries the export lints of task 20.5.3, which need the resolved index only a run reads). Each becomes `{ rule, severity, file: relPath, startLine, trace }`. A lint on an export of a sibling (card `consume/dead-export`: `isHuge`) therefore carries `file: 'helpers.ts'`. `trace` is the lint's `trace` when the lint has that field, otherwise `[]`. `severity` is the value `assayerConfigContract.parse({})` (from `@assayer/shared/contracts`) gives the toggle the rule rides, because the smoke repo uses the default config (DESIGN.md decision "Lint severity"): `deadSurface` for `unreachable-exit`, `dead-surface` and `never-read`, and `edgeValueMerge.<key>` for each `edge-merge-*` rule (the key table of task 21.1.2). Until phase 21 adds `edgeValueMerge`, an `edge-merge-*` rule never appears in a run, so the projection maps only the rules that exist; task 21.12.3 adds the six keys to the map.
  This severity check catches only drift between the generator's statics (`reportVocabularyStatics.lintSeverity`, task 1.1.4) and core's config defaults. It cannot catch a run that applies the wrong severity, because the observation reads the default from the config contract, not from what the run did with the lint.
- `undriven` and `darkSpots`: from the `ownAnalysis` of every file, each as `{ file: relPath, startLine }`, concatenated.
- `gaps`: each of the `entry.ts` item's `run.gaps` as `{ name }`. `name` is `<entry>.<param>` when the gap has a `param` field, otherwise `<entry>`.
- `buildErrors`: each as `{ file, line, reason, trace }`. `reason` is the error's `reason` when it has one, otherwise `observeStatics.unclassifiedReason`. `trace` is the error's `trace` when it has one, otherwise `[]`.
- `stubValues`: from `stubIndex`, one row per demanded property and per environment stub that a branch of the specimen reads, at the path task 1.4.1 defines. An object stub's key names a type; its path starts at the entry parameter declared with that type (`job.priority`), with `[]` after a parameter that is an array of it (`items[].count`). A nested demand adds each property name. An environment stub's path is its property name (`SIZE`). Each value of the demand is written as TypeScript literal text; a property the demand marks optional and left out is `missing`, and an environment value that stands for unset is `unset`. A property whose demand is `unknown` adds no row. With no `stubIndex`, `stubValues` is `[]`.
- Sort every list the way the prediction sorts it (task 6.4.1): `branches` by file (`entry.ts` first, then the other files by path), line, then kind; `lints`, `undriven` and `darkSpots` by file then line; `stubValues` by path, each `values` list sorted.

The four "when the node has that field" reads are small typed type guards inside the transformer file, written with `'arms' in node` style checks. Never use `as unknown as`. They let later core phases add the fields without any change to the generator. Task 13.2.1 replaces the `arms` guard with the typed field. Task 25.1.2 replaces the other three.

## Tests

Build `FileAnalysis` and `RunResult` values with the shared stubs (`@assayer/shared/contracts/<name>/<name>.stub`).

- `VALID:` an `if` with two cases.
- `VALID:` two files, `entry.ts` and `check-limit.ts`, each with an `if`: `branches` holds both with their `file`, `entry.ts` first, and a route step naming the sibling's branch carries `file: 'check-limit.ts'`.
- `VALID:` a callback pseudo branch.
- `VALID:` a return comparison.
- `VALID:` an undriven case.
- `VALID:` a failed case.
- `VALID:` a lint with and without a `trace`.
- `VALID:` a `never-read` lint in a sibling's `analysis.lints` carries that sibling's `file` and `severity: 'error'`.
- `VALID:` a stub index with `Job.priority` demanding `[5, 6]` and an entry parameter `job: Job` gives `stubValues: [{ path: 'job.priority', values: ['5', '6'] }]`.
- `VALID:` an environment stub `SIZE` gives a row with path `SIZE`.
- `EMPTY:` no `stubIndex` gives `stubValues: []`.
- `VALID:` a gap with and without a `param`.
- `VALID:` a build error with and without a `reason`.
- `VALID:` a branch of another kind with its own `arms`, and one without.
- `EMPTY:` nothing found.
