## Contract

`reportLayerBroker({ smokeRoot, folder }): Promise<SpecimenReport>`. `folder` is `src/and/as-condition`.

## Why a mirror

Assayer must read one specimen as a repo of its own, and a stub correction must sit at the root of the repo Assayer
analyses (DESIGN.md decision "Where a generated stub correction lives"). Compiling the whole smoke repo instead is
wrong three ways: `compileRunBroker` returns early on any unresolvable import in the repo (line 183) and then writes
no stub index (line 231); environment stubs are keyed `process.env#<PROP>`, so one specimen's `SIZE` values would
union with every other specimen's; and Jest resets module memory per test file, so a "once per process" compile runs
again for every specimen anyway. A per-specimen mirror avoids all three.

## What to implement

1. **The mirror root.** One fixed path per process: `join(tmpdir(), `assayer-specimen-mirror-<pid>`)` (through
   `#gateway/node/os` and `#gateway/node/path`). Rebuild it for every call: remove it, then write, through the fs
   gateway (`#gateway/node/fs`):
   - `packages/syntax-repository/package.json`: a byte copy of `smokeRoot`'s `packages/syntax-repository/package.json`;
   - `packages/syntax-repository/tsconfig.json`: `{ "extends": "<absolute path of smokeRoot's packages/syntax-repository/tsconfig.json>", "include": ["src/**/*"] }`, so every path alias resolves against the real config;
   - `packages/syntax-repository/<folder>/<name>.ts` for each **direct** `.ts` child of the specimen folder, listed with
     `readdirSync` on that one folder (no recursion and never `fileWalkBroker` on a folder: specimen folders nest, as
     `src/const/in/for-of-body` holds `src/const/in/for-of-body/if-then`). `*.test.ts` files are left out;
     `*.harness.ts` is copied, because Assayer reads a harness beside its source;
   - the specimen's stub correction, if the generator wrote one, at the same path relative to the mirror root as it
     has under `smokeRoot`: `assayer/stubs/objects/packages/syntax-repository/src/<folder>/entry.ts/<Type>.json`.
   One stable path per process keeps ts-jest to one compiler config (`packages/core/CLAUDE.md` section 8: a new path
   is a new config).
2. **Compile the mirror.** Write `observeStatics.configFile` at the mirror root with `repoRoot: '.'` and no other
   setting, so the run uses the default config (DESIGN.md decision "Lint severity"). Run `compileRunBroker` with the
   mirror root. Keep its errors. Read the stub index it wrote under `<mirror>/.assayer/cache/stubs/` (the one
   `<namespace>.json` there) with `stubIndexContract`; when the file is missing (the compile returned early), the stub
   index is `undefined`.
3. **Run every source file.** For each direct `.ts` source of the mirror's specimen folder that is not a harness,
   `entry.ts` first, then the others sorted: walk it with `fileWalkBroker` (one file, never a folder), analyse it with
   `analyzeFileBroker` (its own analysis), and run it with `runUnitBroker` with `repoRoot` the mirror root,
   `cacheDir` `<mirror>/.assayer/cache`, and a run id that is a hash of `folder` plus the file's name. The run applies
   the five overlays, and with the mirror's `.assayer/cache` as `cacheDir` it reads the resolved index the compile
   wrote, so task 20.5.3's export lints reach every file: the export lints of a sibling such as card
   `consume/dead-export`'s `helpers.ts` come from that sibling's own run. This is the chosen way to give siblings
   their lints: run each file.
4. **Paths in the report.** Every file inside the specimen folder is written relative to the folder (`entry.ts`,
   `helpers.ts`), and the stub correction relative to the mirror root, which equals its path under `smokeRoot`.
5. **Project** with `specimenReportProjectionTransformer` (task 8.2.1), passing `files` (one item per source file, with
   its `relPath`, own analysis, overlaid analysis, scopes and run), the build errors and the stub index.

The generated test compares the whole report, the stub values Assayer derives included, so the broker returns exactly
what the projection returns. Each specimen compiles its own mirror once per test, so a generated run costs one small
compile per specimen; speed is not optimised in this design (DESIGN.md decision "Speed of the generated run").

## Tests

Follow the existing observe broker's test pattern for staging.

- `VALID:` a single-file specimen gives its report; the mirror holds `package.json`, the `extends` tsconfig and `entry.ts`.
- `VALID:` a folder with a sibling runs both files, and the report lists the sibling's branches and its export lints with the sibling's `file`.
- `EDGE:` a nested specimen folder inside the folder is not copied, and its files are not analysed.
- `EDGE:` a `*.test.ts` in the folder is not copied; a `*.harness.ts` is copied and not analysed as a source.
- `VALID:` a specimen with a stub correction copies it to the same relative path and reports the correction's build errors.
- `VALID:` a specimen with an object parameter reads the stub index the mirror compile wrote, and the report holds its `stubValues`.
- `EDGE:` a specimen whose import cannot resolve: the compile returns early, the stub index is `undefined`, and `stubValues` is `[]`.
- `VALID:` two calls in a row reuse the one mirror path and leave no file of the first specimen behind.
- `ERROR:` a walk failure is reported as a build error.
