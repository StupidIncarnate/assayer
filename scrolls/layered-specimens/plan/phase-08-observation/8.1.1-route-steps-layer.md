## Contract

`routeStepsLayerTransformer({ steps, branchesById, scopeLinesById, exitFile, exitLine }): ArmStep[]`

- `steps`: one derived test case's steps, as the shared `guard-step` contract holds them.
- `branchesById`: a map from coverage id to `{ file, kind, line }` for every `BranchNode` of every analysed file of the specimen (the projection, task 8.2.1, builds it). `file` is the specimen-relative path.
- `scopeLinesById`: a map from a coverage id that names no `BranchNode` to `{ file, line }`, the file and start line of the scope it names (a callback).
- `exitFile` and `exitLine`: the file and start line of the exit the case reaches first, for the pseudo steps `return-true` and `return-false`.

## What to implement

For each step, write one `ArmStep` (`{ file, kind, line, arm }`):

- A step whose id is in `branchesById` gives the branch's `file`, `kind` and `line` and the step's arm label.
- A step whose id is in `scopeLinesById` is a callback step: kind `callback`, the scope's file and line, and the label `skipped` or `runs`.
- A `return-true` or `return-false` step is kind `return-comparison`, file `exitFile`, line `exitLine`, and that label.
- A step whose id is in neither map throws `route-steps: step '<id>' names no branch and no scope.`

Sort the result and remove duplicates the way task 6.4.1 sorts a route's arms.

## Tests

- `VALID:` an `if` case with two steps gives two arm steps.
- `VALID:` a callback step takes the scope line.
- `VALID:` a `return-true` step takes `exitFile` and `exitLine`.
- `VALID:` a step naming a branch in `check-limit.ts` gives an arm step with that file, sorted after the `entry.ts` steps by the file rule.
- `VALID:` two steps naming the same branch and arm give one arm step.
- `ERROR:` a step naming nothing throws the exact message above.
- `EMPTY:` no steps gives an empty list.
