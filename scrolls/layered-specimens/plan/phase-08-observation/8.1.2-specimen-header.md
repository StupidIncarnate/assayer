## Contract

`specimenHeaderTransformer({ plan, report, today }): string`

`today` is the list of today rows the specimen matches. Each row has `id`, `today` (the sentence) and `closedBy` (a phase number), as task 1.1.5 declares them. The result is a `/** ... */` block with no trailing newline. It is used by the build broker (task 9.2.1) and replaces `specimenExpectationCommentTransformer`, which task 9.6.x deletes.

## What to implement

Write one idea per line, each line starting with ` * `, in this order:

1. `Specimen: <folder>`
2. `Focus: <focus piece>, varying <axis> = <value>, level <level>`
3. `Uses: <pieces>` (every piece in the plan, focus first, each once, comma separated)
4. `Expected branches:` then one line per branch, `  <kind> on <file> line <n>: <arms comma separated>`
5. `Every route (<n>):` then one line per route, `  <arms as 'file:line:label' comma separated>`, with ` (undriven)` appended when the route is not driven
6. `Fewest runs: <n>`
7. `Lints:` then one line per lint, `  <rule> on line <n>`, and for a lint with a trace ` via <file>:<line> > <file>:<line>`; or `none`
8. `Undriven admissions:`, `Dark spots:`, `Gaps:` (the gap names) and `Build errors:` (`<reason> at <file>:<line>`), each followed by its lines, or `none` on the same line when empty
9. For each today row, in id order: `Today: <the row's today sentence> (closed by <phase>)`, where `<phase>` is
   `closedBy` with its hyphen written as a space: `'phase-15'` prints `phase 15`. `closedBy` already holds the word
   `phase`, so the line never says "phase phase".

Never write `*/` inside the block: replace it with `* /`. The line numbers in the header are the lines of the final file. Task 9.2.1 computes them by adding the header's own line count, so this transformer prints the numbers it is given.

A specimen the engine refuses gets no folder, so the header never prints a refusal.

## Tests

- `VALID:` the header for card `loop/for-of`'s predicted report with its today id, full text with `toBe`.
- `VALID:` a report with a branch in `check-limit.ts` prints `on check-limit.ts line <n>` and `check-limit.ts:<n>:<label>` in the route lines.
- `VALID:` a report with a known-value lint prints the `via` trace.
- `VALID:` a report with a build error and a gap.
- `VALID:` a today row with `closedBy: 'phase-15'` prints `(closed by phase 15)`, asserted with `toBe` on the line.
- `EMPTY:` a report with every channel empty prints `none` on each.
