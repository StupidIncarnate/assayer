## What to implement

`get-testing-patterns` lets an integration test import harnesses and stubs only, so the card expectations live in `packages/specimen-generator/test/harnesses/`.

1. Make sure the package's `tsconfig.json` includes `test/**/*.ts`, so ward typechecks and lints the harnesses. Add it to `include` when it is missing, and keep every other entry.
2. Create `design-card.harness.ts`. It exports `designCardHarness`, a factory returning three functions:
   - `card(card)`: returns its argument unchanged, typed as `DesignCard` (below). Every group harness in row #2 builds its expectations through it, so all nine share one shape.
   - `printed({ source })`: the source text printed through the TypeScript printer from `#gateway/npm/typescript` (parse with `createSourceFile`, print with `createPrinter`). Formatting never decides a comparison.
   - `lineOf({ source, text })`: the 1-based line of the first line of `printed({ source })` that contains `text`. It throws when no line contains `text`, with the message `lineOf: the printed source has no line containing '<text>'.`
3. Create `card-check-exclusions.harness.ts`. It exports `cardCheckExclusionsHarness`, a factory returning `{ exclusions, openQuestions }`. `openQuestions` is the list of ids of README "Open questions for the user" that are still open, starting as `[]`; the operator edits it whenever it adds or closes a question. `exclusions` is a list of `{ folder: string; reason: 'generator-fix' | 'disputed'; question?: string }`. The list starts empty. A `disputed` entry names an open question of README "Open questions for the user" in `question` (an id the operator adds there when it adds the question). A `generator-fix` entry has no `question`. Task 7.3.1 fills the list; each 7.4 task removes its cards; task 7.5.1 checks it.

## Contract

```ts
type DesignCard = {
  folder: string;                       // 'src/and/as-condition'
  sameAs?: string;                      // the folder of the earlier card with the same code
  source: string;                       // the card's entry.ts code, verbatim
  files: { relPath: string; source: string }[];   // the card's other files, e.g. is-big.ts, and a stub JSON at the card's own path
  branches: { file: string; kind: string; arms: string[] }[];   // sorted by file (entry.ts first), then line; file is specimen-relative, 'entry.ts' for the entry
  routes: { arms: [number, string][]; driven: boolean }[];   // arm = [branch ordinal, label]; -1 for a pseudo arm
  fewestRuns: number;
  lints: { rule: string; severity: 'warn' | 'error'; file: string; branch: number | null; line: number; trace: [string, number][] }[];   // file and line: where the lint lands
  undriven: { file: string }[];         // one per undriven admission, the file whose own analysis admits it
  gaps: string[];                       // '<entry>.<parameter>'
  buildErrors: { reason: string; file: string; line: number; trace: [string, number][] }[];
  stubValues: { path: string; values: string[] }[];   // task 1.4.1's path rules; values as TypeScript literal text, plus 'missing' and 'unset'
  today: string[];
};
```
