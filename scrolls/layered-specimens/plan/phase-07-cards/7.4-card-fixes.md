# 7.4 Make the generator agree with every card (fan-out `7.4.<n>`)

- **Phase:** 7, the DESIGN.md cards. **Row:** #4, a fan-out row.
- **Depends on:** 7.3.1.
- **Model:** opus.
- **Covers:** Whatever cards 7.3.1 lists as `generator-fix`.

## How the fan-out works

This file describes the tasks `7.4.<n>`. There is no task `7.4` itself. The operator reads 7.3.1's grouped failure report and records one task `7.4.<n>` per group in the README tracker. Each task is an `opus` worker.

A task touches at most 3 files:

1. up to 2 generator files the group points at: a piece under `packages/specimen-generator/declarations/pieces/`, a transformer or broker under `packages/specimen-generator/src/`, or a group harness under `packages/specimen-generator/test/harnesses/` when the transcription is wrong; and
2. `packages/specimen-generator/test/harnesses/card-check-exclusions.harness.ts`, from which the task removes the cards it fixes.

When a fix needs more than 2 generator files, the operator splits the group into more tasks. Every `7.4.<n>` task edits the exclusion file, so the operator dispatches them one at a time, in the order of the report. A generator file's own tests are updated by the same task (a file and its test count as two, so such a task names at most one generator file with its test).

## What each worker does

1. Run `npm run generate:specimens -- --show=<one failing folder>` and compare it with the card in DESIGN.md.
2. Find which generator file is wrong.
3. Fix the generator file, never the card. A transcription error in a group harness is fixed against the DESIGN.md card text.
4. When the card itself looks wrong, or two cards contradict each other, or a fix would change a row of DESIGN.md's decisions table, stop and report it. The operator records the card on the exclusion list with reason `disputed` and a question from README "Open questions for the user", and takes it to the user. Never edit DESIGN.md.
5. Remove the fixed cards from the exclusion list.

Rule P4 holds: a fix never reads Assayer's output, and never makes the prediction copy what Assayer does today. A gap Assayer has today is recorded by a today id, not by changing a prediction.

## Verify

- `npm run ward -- -- <every file the task changed>`
- `npm run ward -- --only integration -- packages/specimen-generator/src/startup/start-specimen-generator.integration.test.ts`
- `npm run generate:specimens -- --check` exits 0 (the committed smoke repo still matches the old pipeline until row 9.4).

## Done when

The cards of the group pass the card check and are off the exclusion list, and every verify command exits 0.
