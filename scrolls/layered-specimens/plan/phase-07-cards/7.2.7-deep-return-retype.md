## What to implement

For every card of the group, in DESIGN.md order:

1. **A composition card** in the compositions file, in the shape task 1.3.4 sets: the card's `folder`, a one-line `description` (the card's title), and a `tree` of piece names, slots and leaves that renders to the card's code. Use the leaf names and literal values the card's code uses. Then:
   - When the card's code equals an earlier card's code, write `sameAs: '<that folder>'` instead of a tree.
   - A function, type alias or enum the card declares above its entry is a card `helper` (a tree, `typeAlias` or `enumMembers`).
   - Name a value with a node's `rename` (`{ isBig: 'checkLow' }`) when the piece's own names differ from the card's.
   - Code that no piece describes and that holds no branch (`new Counter(count)`, `counter.count = count;`) is a `snippet` leaf. A snippet that holds a branch is refused, so prefer a piece whenever one fits.
   - A card that shows more than one file sets `siblings` (one entry per extra file, each with its own tree, helpers or `reexport`).
   - A card that shows a harness file sets `axis` to the companion-files value that adds a harness (the name task 1.1.2 gives it).
   - A card that shows a stub correction JSON sets `stubCorrection`.
2. **A card expectation** in the harness, transcribed from the card by hand, never from the generator's output. Use the shape task 7.1.1 defines:

```ts
designCardHarness().card({
  folder: 'src/and/as-condition',
  source: `<the card's entry.ts code, verbatim>`,
  files: [],                                                  // the card's other files: { relPath, source }
  branches: [{ file: 'entry.ts', kind: 'if', arms: ['then', 'else'] }],   // "Expected branches", sorted by file (entry.ts first), then line; labels from README "The report vocabulary"
  routes: [{ arms: [[0, 'else']], driven: true }],            // "Every route": one row per listed route, each arm as [branch ordinal, label]
  fewestRuns: 2,                                              // "Fewest runs"; "none" is 0
  lints: [],                                                  // "Other expected reports", lint rows: { rule, severity, file, branch, line, trace }
  undriven: [],                                               // one { file } per undriven admission the card names
  gaps: [],                                                   // '<entry>.<parameter>' for each gap the card names
  buildErrors: [],                                            // { reason, file, line, trace } for each P1 the card names
  stubValues: [],                                             // one { path, values } per "Stub values Assayer derives" item, sorted by path
  today: [],                                                  // the ids listed above for this card, sorted
})
```

Rules for the fields:

- A branch's `file` is the specimen-relative path of the file its syntax sits in: `entry.ts` for the entry, and the sibling's own path for a branch in a sibling file (card `known/env-two-files`: `checkLimit if` is `file: 'check-limit.ts'`). A branch ordinal is the branch's position among the card's listed branches, sorted by file (`entry.ts` first, then the other files by path), then line. A pseudo arm that is not a listed branch (`return-true`, `return-false`) uses the ordinal `-1`.
- A route's `arms` is the set of arms its whole run takes, across loop passes and repeated calls. Where a card says "8 routes" without listing them, write all eight. A `sameAs` card repeats the named card's expectation under its own folder and sets `sameAs`.
- **Route wording.** A card's route line may hold words that are not arms: an exit's value (`exits big`, `yields 'small'`), a settlement (`resolves`, `rejects`, `throws`), a side effect (`logs`, `does nothing`), a callback that has no listed branch (`callback runs` in `callback/then`, `check true` in `companion/callback/with-harness`), or a call count (`1 call`). Drop every word that is not an arm of a listed branch, and keep the arms. When a card names an arm with a word of its own (`then (break)`, `else only`, `outer else`), translate it to the arm label.
- A lint's `rule` and `severity` come from the card's "Other expected reports" line: `lint, warn: …` is `severity: 'warn'`, `lint, error: …` is `severity: 'error'`, and a lint line with no severity word (`lint: unreachable exit …`) takes its rule's default, `error` for `unreachable-exit` (DESIGN.md decision "Lint severity"). Its `file` is the specimen-relative file the lint lands in (card `consume/dead-export`: `helpers.ts`). Its `branch` is the ordinal of the listed branch that starts on the lint's line in that file, or `null`. Its `line` is the line the lint lands on, in that file. Its `trace` is the path trace of a known-value lint, one `[fileRelPath, line]` pair per step, and `[]` for every other rule.
- `undriven` has one `{ file }` per undriven admission the card names, the file whose own analysis admits it (`undriven: in entry.ts's own analysis` is `{ file: 'entry.ts' }`). The card names no line, so the check compares files only.
- `stubValues` has one `{ path, values }` per item of the card's "Stub values Assayer derives" line. The path follows task 1.4.1's rules: "`count` on each item" of `items` is `items[].count`, and "`order.prices` on each order" of `orders` is `orders[].prices`. `values` holds each value the line names, as TypeScript literal text, sorted, with `missing` for a property left out and `unset` for an environment variable left unset. Drop the words that say which arm a value is for.
- Write every line number with `designCardHarness().lineOf({ source, text })`, which returns the 1-based line of the first line of the printed source that contains `text`. Counting by hand is wrong whenever the printer moves a line.
- Translate the card's words to labels with README "The report vocabulary": "outer else" is the `else` of the first `if`; "stops at left" of `&&` is `else`; "left" of `??` is `then`; "case 'a'" is `case:a`; "case Low" of an enum is `case:0`, the member's value; "skipped" and "runs" stay. When a card's wording cannot be translated without a decision, stop and report the card in your reply. The operator takes it to the user. Never guess, and never edit DESIGN.md.
- A card keeps its own export name. Most cards export `entry` or `class Entry`, but `state/this-field` exports `class Counter`, `known/env-two-files` exports `result`, and `const/in/module` exports nothing (`export {};`). Write the card's code as it is; task 1.3.4's `exportName` field carries the name.
