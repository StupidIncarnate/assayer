## What to implement

`design-cards.harness.ts` exports `designCardsHarness`, a factory returning:

- `cards`: every card from the nine group harnesses (tasks 7.2.1 to 7.2.9), sorted by `folder`.
- `showFolder({ card })`: `card.sameAs ?? card.folder`.
- `normalize({ show })`: turns one `--show` result (task 6.4.2: `{ folder, files, report, today }`) into the card shape:
  - each branch's line becomes its ordinal among the report's branches in report order (file with `entry.ts` first, then line), so `branches` is `{ file, kind, arms }[]` and keeps its ordinals;
  - each route arm becomes `[ordinal, label]`, found by its file, line and kind (`-1` for a pseudo arm); each route is `{ arms, driven }`;
  - `lints` become `{ rule, severity, file, branch, line, trace }`, where `line` is the lint's `startLine` in its own `file`, and `branch` is the ordinal of the listed branch starting on that line in that file, or `null`; `trace` becomes `[file, line]` pairs;
  - `undriven` becomes one `{ file }` per admission (the card names no line); `gaps` are the gap names; `buildErrors` are `{ reason, file, line, trace }`; `stubValues` is `report.stubValues`;
  - arms inside a route are sorted by ordinal, then label; routes are sorted by their JSON text; lints and `undriven` by file then line; `today` is sorted; `stubValues` is sorted by path, each `values` list sorted.
  - The same function normalizes a card's expectation, so the order a transcriber wrote never decides.
- `printedFiles({ show })`: each rendered file of the show result, keyed by relPath. A `.ts` file is its text printed through the TypeScript printer, so formatting never decides. Any other file (a stub correction's JSON) is its bytes, unchanged, and is compared byte for byte with the card's file at the same relPath.
- `knownTodayIds`: a fixed list, written in the harness by hand, of every id in README "Today gaps": `await-throw-point`, `barrel-follow`, `call-sequence`, `compound-assign-untracked`, `default-param-branch`, `default-param-ternary-passed`, `derived-stub-values`, `destructure-default-branch`, `edge-merge-lint`, `edge-values`, `enum-case-unread`, `env-in-function`, `gap-param-name`, `guard-narrows-unknown`, `known-value-consumption-point`, `known-value-cross-file`, `loop-dark-spot`, `loop-written-variable`, `never-read-lint`, `optional-chain-nested`, `optional-property-presence`, `p1-reason-token`, `promise-callback-arms`, `promise-executor-exits`, `switch-shape`, `template-literal-env-chain`, `try-dark-spot`, `two-param-comparison`, `unresolved-import-admits`, `value-position-logical`. It never reads `todayStatics`, so it still holds an id after a close task removes that id from the statics.
- `liveToday({ today })`: the card's `today` list filtered to the ids `todayStatics.gaps` still holds (task 1.1.5). A close task removes an id from `todayStatics` ("Every phase's last row"), and the generator's own match stops reporting it in the same commit. Comparing the card's whole list would turn the check red on every close, so the check compares the filtered list. The harness imports `todayStatics` from `src/statics/today/today-statics.ts`: a test harness may import statics.

In the integration test, add `describe('DESIGN.md cards')`:

1. A `beforeAll` runs `StartSpecimenGenerator` once with `--show=<every distinct showFolder, comma separated>` and parses the JSON. A refused specimen prints `{ folder, refused }`; the test fails that card with the refusal text.
2. `it.each(<cards whose folder is not in the exclusion list>)('VALID: {card: %s} => the generator renders and predicts what the card says', ...)` asserts with one `toStrictEqual` on an object holding all three: the printed card source and card files equal `printedFiles` of the rendered files (TypeScript printed, any other file as bytes); the normalized report, `stubValues` included, equals the normalized expectation; the today ids equal `liveToday` of the card's list.
3. `it('VALID: {exclusions} => every excluded folder is a card, and every disputed one names an open question', ...)`. An open question is an id of README "Open questions for the user"; `cardCheckExclusionsHarness().openQuestions` holds that list of ids (task 7.1.1). Add `it('ERROR: {card today ids} => every id a card names is in knownTodayIds', ...)`: for every card, the ids of its `today` list that are not in `knownTodayIds`, asserted with `toStrictEqual` to be `[]`; a misspelt id fails with the card's folder and the id in the diff. Add `ERROR:` cases through the same harness data: an excluded folder that is no card fails with `card-check exclusion '<folder>' names no DESIGN.md card.`; a `disputed` entry with no `question` fails with `card-check exclusion '<folder>' is disputed and names no open question.`; a `generator-fix` entry with a `question` fails with `card-check exclusion '<folder>' is a generator-fix and must not name a question.`

## Landing green

The first run is expected to fail on many cards. Do not fix the generator here. Run the check once, and add every failing card to `card-check-exclusions.harness.ts` with reason `generator-fix`. Run it again; it must pass. Report, in your reply:

- the failing folders grouped by the field that differs (source, files, branches, routes, fewestRuns, lints, undriven, gaps, buildErrors, stubValues, today), with one line of the difference for each group;
- for each group, the generator files the difference points at (a piece declaration, the planner, the renderer, candidate inputs, probe source, route grouping, lint or admission prediction, or a card transcription). The operator turns each group into a `7.4.<n>` task.
