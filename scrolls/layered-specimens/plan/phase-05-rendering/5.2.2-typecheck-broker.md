## What to implement

Keep the current call shape working for the old pipeline: `files` of `{ relPath, content }`. The current broker keeps
every pre-emit diagnostic (`specimens-typecheck-broker.ts:74`). Add an optional `groups` input:

```ts
groups?: {
  folder: string;
  files: { relPath: string; content: string }[];
  compilerOptions?: Record<string, boolean>;
  fileBoundary?: string;   // an axisStatics file-boundary value
}[]
```

1. Files of one group resolve each other by relative import through the in-memory host.
2. Groups that share compiler options typecheck in one program. Each distinct option set is one more program.
3. `@assayer/core` resolves to the file named by `specimenTypecheckStatics.corePathSegments`, through a `paths` entry
   in the program's options, so a harness file typechecks.
4. A built-in import resolves through the default host. A package import (`project-with-types`, `project-without-types`) resolves from `smoke-repo/node_modules`, where `npm install --prefix smoke-repo` links the smoke repo's workspace packages (tasks 9.1.7, 9.1.8).
5. A group whose `fileBoundary` is one of `unresolvable-specifier`, `unresolvable-dynamic` or
   `unresolvable-no-types` imports something that cannot resolve on purpose. Skip a diagnostic of that group only
   when its code is in `specimenTypecheckStatics.expectedDiagnostics[<value>]`. Any other diagnostic in the group
   still refuses it. A group with another `fileBoundary` value, or none, has no expected diagnostics.
6. A diagnostic in any file of a group refuses the whole group. The result maps the refusal to the group's folder.
