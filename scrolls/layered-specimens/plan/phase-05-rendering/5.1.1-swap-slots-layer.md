## Contract

`swapSlotsLayerTransformer({ node, piece, fills, armKind, position }): ts.Node`

- `node`: a clone of the piece's code arrow function.
- `piece`: the `LoadedPiece`.
- `fills`: `Record<slotName, ts.Node[]>`. The nodes are already rendered by task 5.2.1, one statement or expression
  per child.
- `armKind`: how the slot that holds this piece writes an arm's own statement: `'return' | 'log' | 'yield' | 'push' | 'throw'`.
- `position`: the position the piece takes.

## What to implement

1. **Hole.** A hole (a `code` parameter) is swapped for the node its slot's child renders to. Only the identifier
   bound to that exact parameter is a hole.
2. **Statement slot.** A `$stmts('<slot>')` statement is replaced by the slot's children in order, each a statement.
   An empty slot removes the marker statement.
3. **Parameters.** `$params` is replaced by the parameter declarations of every `parameter-list` child, plus the
   params map. A `parameter-list` piece renders its code arrow's parameter declarations only, never its body.
4. **Arm statement.** `$arm('<name>')` used as a statement becomes the slot's arm statement, from `armKind`:
   `return '<name>';`, `console.log('<name>');`, `yield '<name>';`, `seen.push('<name>');` or
   `throw new Error('<name>');`. A `push` arm also records that the container's body starts with
   `const seen: string[] = [];` and ends with `return seen;` (task 5.3.1 places them). `$arm('<name>')` used as an
   expression becomes the string `'<name>'`. In the `exit` position each arm becomes its own exit. In the `value`
   position the arms flow on.
5. **Rename.** A node's `rename` renames the listed identifiers in the piece's code before the piece is placed (the
   `synthesize-node-transformer` rename, applied once per name).
6. **Entry names.** `$Entry` becomes `specimenLayoutStatics.names.entry` (or `entryClass` for a class). `$R` becomes
   the result type. `$exportDefault` is refused with
   `the marker $exportDefault is not used by any piece. Remove it from the declaration.`
7. **Helpers.** This layer does not collect helpers. Task 5.2.1 adds each piece's `helpers` statements to its
   `helpers` map.

## Tests

- `VALID:` the `if` code with a `gt` condition renders to the text of card `route/direct`'s body.
- `VALID:` a ternary in the exit position renders `count > 2 ? 'big' : 'small'`.
- `VALID:` each of the five `armKind` values writes its statement (`return`, `log`, `yield`, `push`, `throw`), with
  `throw new Error('then');` asserted word for word.
- `VALID:` `push` records the `seen` array declaration and the final `return seen;`.
- `VALID:` a `rename` renames the identifier in the code.
- `EMPTY:` an empty statement slot removes its marker.
- `ERROR:` `$exportDefault`, message word for word.

Assert printed text with `toBe`.
