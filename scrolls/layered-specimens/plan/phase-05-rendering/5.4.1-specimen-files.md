## What to implement

- `entry.ts`: `pieceTreeRenderTransformer` of `plan.tree`, `plan.helpers` and `plan.exportName` (task 5.3.1).
- Each sibling: `<file>` rendered from its `tree`. A sibling with a `reexport` is a barrel: `index.ts` holding
  `export { isBig } from './is-big';` (the name and path come from the `reexport`). A sibling that moves a type
  alias for the file-boundary axis is `types.ts` (`typeListStatics.files.types`). The entry imports it with
  `import type`.
- `harness`: `entry.harness.ts`, written as card `companion/callback/with-harness` writes it:
  `import { assayerHarness } from '@assayer/core';` then
  `assayerHarness({ inputs: { entry: { <param>: <value> } } });`. A callable parameter's value is an arrow that
  compares its first parameter with `>` against `layeredMatrixStatics.readerLiteral` for its type and returns the
  result (`(value: number): boolean => value > 2`). A parameter typed `unknown` gets the number known value from
  `typeListStatics`.
- `stub-agrees`, `stub-missing-property`, `stub-contradicts`: one JSON file under
  `specimenLayoutStatics.files.stubsFolder`, named and shaped the way `packages/core`'s
  `stub-overlay-load-broker` reads a correction. Read that broker (`stub-overlay-load-broker.ts:28-29` reads
  `${repoRoot}/assayer/stubs/objects`) and the shared stub-overlay contract before writing this. A stub correction
  lives at the root of the repo Assayer analyses (DESIGN.md decision "Where a generated stub correction lives"), so
  the file is `assayer/stubs/objects/packages/syntax-repository/src/<folder>/entry.ts/<Type>.json`, a path relative to the smoke repo root `smoke-repo/`, not to the specimen folder, with
  `"type": "packages/syntax-repository/src/<folder>/entry.ts#<Type>"`. It is the one rendered file whose `relPath`
  starts with `assayer/stubs/`; the write and check brokers resolve such a path against `smoke-repo/` (tasks 9.1.3 and
  9.1.4). Agrees: values that satisfy each arm
  of the branch reading the property. Missing property: a property name the type does not have. Contradicts: values
  none of which satisfies the guard (STUBS.md example: `mode` corrected to `['b']` when the code checks `mode ===
  'a'`).
- `plan.stubCorrection` (card `known/stub-correction`): the same JSON file, written from the card's explicit
  `{ type, property, values }`. Write the values as the card gives them (`[1, 2, 3]`), never derived.
- `compilerOptions`: `tsconfig.json` that extends the package's `tsconfig.json` by a relative path, sets the flags,
  and includes `*.ts`.

Card `known/stub-correction` prints exactly this path and type key
(`assayer/stubs/objects/packages/syntax-repository/src/known/stub-correction/entry.ts/Job.json`), and the card check
(task 7.3.1) compares the JSON byte for byte.

## Tests

One `VALID:` per file kind the section above names, asserting every file's `relPath` and `content` with
`toStrictEqual`. The list below holds one test for each, so the text and the tests name the same kinds:

- `VALID:` a plain plan gives only `entry.ts`.
- `VALID:` a plan with `exportName: 'Counter'` gives an `entry.ts` that exports `class Counter`.
- `VALID:` a sibling with a tree gives `is-big.ts`, and the entry imports `./is-big`.
- `VALID:` a barrel sibling gives `index.ts` with the re-export and the entry imports `./index`.
- `VALID:` a moved type gives `types.ts` and an `import type` line in the entry.
- `VALID:` `harness` gives `entry.harness.ts` with the callable value `(value: number): boolean => value > 2`.
- `VALID:` `harness` on an `unknown` parameter gives the number known value from `typeListStatics`.
- `VALID:` `stub-agrees` gives values that satisfy each arm.
- `VALID:` `stub-missing-property` gives a property name the type does not have.
- `VALID:` `stub-contradicts` gives values that satisfy no arm.
- `VALID:` `stubCorrection` of card `known/stub-correction` gives `assayer/stubs/objects/packages/syntax-repository/src/known/stub-correction/entry.ts/Job.json`
  with `"type": "packages/syntax-repository/src/known/stub-correction/entry.ts#Job"` and `values` `[1, 2, 3]`.
- `VALID:` `compilerOptions` gives a `tsconfig.json`.
