## Contract

## What to implement

| source | Writes | Records |
|---|---|---|
| `param` | the identifier | a parameter `name: type` |
| `binding` | the identifier | nothing |
| `literal` | the value (the logic of `literal-node-layer-transformer.ts`, moved here) | nothing |
| `const` | the identifier | a top-of-file `const name: type = <known value>;` |
| `env-load` | the identifier | a top-of-file `const name = <type-info env text with KEY renamed>;` |
| `env-call` | the identifier | a statement at the start of the entry's body: `const name = <env text>;` |
| `argv` | the identifier | a top-of-file `const name = <type-info external text>;` |
| `prop` | `box.<name>` | a parameter `box: { <name>: type }` |
| snippet (`PieceSnippet`) | the snippet parsed with `parse-snippet-expression` or `parse-snippet-statements` | nothing |
| `random` | refused: `the random source is not generated yet. Remove it from the plan.` | |

The first leaf to use a name keeps it. A later leaf with a taken name is named from its owner and slot, as the old
leaf layer does. `env-call` needs a statement slot at the start of the entry. Record it in `decls` under the key
`bodyStart`, which task 5.3.1 places.

The `literal` source covers the call site `decide(3)` of the source table: task 4.3.2 puts a `literal` leaf in the
call's argument, and this layer writes the number. The `param` of the helper `decide` is a `param` leaf in the
helper's own tree.

## Tests

`ERROR:` `random` (message word for word). `EDGE:` two leaves with one name. `VALID:` a `literal` leaf of type
