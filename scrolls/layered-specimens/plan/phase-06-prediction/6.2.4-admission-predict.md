## Rules

- **undriven**, the file's own analysis: one admission per branch no test can steer from this file alone, on that
  branch's own line. A module scope that earns no case is one admission on line 1. The branch is unsteerable from the
  file's own analysis when it is decided by:
  - an `argv` read (`process.argv`);
  - a returned closure's parameter (card `callback/returned-closure`);
  - a call to a callee in a sibling file (the own analysis cannot see across files; card `boundary/sibling`. It is
    driven when the test runs, through the cross-file overlay, which the routes already show);
  - a property of an object parameter (the own analysis cannot arrange one property; `packages/core/CLAUDE.md`
    section 5.12; driven at run time from the stub view);
  - an opaque write: a value assigned from a call whose result no analysis can fold, such as
    `calls = Math.round(Math.random() * 10)` (shared-state value `opaque-write`). A named state would close it, and
    named states are outside this design.
  - A specimen whose import cannot resolve has **no** undriven admission and no routes: Assayer reports the P1 build
    error alone (DESIGN.md decision "An import that cannot resolve").
- **darkSpots:** always `[]`. A card predicts what Assayer should do (DESIGN.md step 8).
- **gaps:** `<entry>.<param>` when `refused` is set and no harness pays it (`entry.raw`, `entry.check`). `<entry>` is
  `specimenLayoutStatics.names.entry`.
- **buildErrors:**
  - `file-boundary` `unresolvable-specifier`: `{ file, line: <import line>, reason: 'cannot-resolve-specifier', trace: [] }`.
  - `unresolvable-dynamic`: `{ file, line: <line of the import() call>, reason: 'dynamic-or-computed-specifier', trace: [] }`.
  - `unresolvable-no-types`: `{ file, line: <import line>, reason: 'no-usable-types', trace: [] }`.
  - companion `stub-missing-property`: `{ file: 'assayer/stubs/objects/packages/syntax-repository/src/<folder>/entry.ts/<Type>.json', line: 1, reason: 'stale-stub', trace: [] }`.
  - a `build-error` result of task 6.1.6 (a companion `stub-contradicts`, or the card `known/stub-correction`):
    `{ file: <consumption.file>, line: <consumption.line>, reason: 'contradicting-stub', trace: <trace> }`, at the entry
    parameter's line, with the trace from the first step (the stub file) to the dead arm.
  - Every reason token is in README "The report vocabulary". Core phases 23 and 24 make Assayer emit them.
