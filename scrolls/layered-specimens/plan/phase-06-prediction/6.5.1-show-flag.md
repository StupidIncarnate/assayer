## What to implement

`--show=<folder>[,<folder>]` plans everything with `specimensPlanBroker` (task 4.6.1). For each named folder it
renders the files with `specimenFilesTransformer` (task 5.4.1) and predicts with `specimenPredictBroker` (task 6.4.1).
It prints `showTextTransformer`'s text (task 6.4.2) and exits 0. A refused specimen is printed as
`{ folder, refused }` and does not change the exit code.

An unknown folder is refused with exit 1:
`the folder '<folder>' is not in the plan. Run --count to see the top folders, or check the folder against DESIGN.md.`

`--show` combines with no other flag except `--piece` and `--axis`. Any other combination is refused with the existing
"cannot read the argument" wording. `--check` refuses `--show` as it refuses `--piece`: extend its refusal text to name
`--show`. Append `--show=<folder,folder>` to the accepted-flags text after the flags task 4.7.1 left in it, . Update every assertion of that text word for word in the responder test. Task 6.5.2 updates the two
integration tests.

## Tests

- `VALID: {argv: [--show=src/if/alone]}` => exit 0 and the output parses as a JSON array with one `folder`.
- `VALID: {argv: [--show=src/if/alone,src/ternary/alone]}` => two objects, in the given order.
- `INVALID: {argv: [--show=src/nope]}` => exit 1 with the unknown-folder message, word for word.
- `INVALID: {argv: [--show=src/if/alone, --check]}` => the "cannot read the argument" refusal.
- `INVALID: {argv: [--check, --show=src/if/alone]}` => the extended `--check` refusal.
- `VALID: {argv: [--show=src/if/alone, --piece=if]}` => exit 0.
