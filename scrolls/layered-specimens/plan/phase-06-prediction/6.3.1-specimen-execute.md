## Contract

```ts
specimenExecuteBroker({ table, inputs, entry, standIns }): CandidateTrace[]
```

One trace per input, in input order. `CandidateTrace` is the contract of task 1.2.7 (`input`, `arms`, `causes`,
`reads`, `cause`, `settable`, `outcome`).

- `table`: the probe table (task 1.4.3). Its `sources` are the probed files.
- `inputs`: the candidate inputs of task 6.2.1.
- `entry`: `{ reach, exportName, constructorArity, member?, closureParamTypes }`. `exportName` is the name the run
  reads off `entry.ts`'s exports: the plan's `exportName` when it is a string (`Counter`, `result`), else `entry` or
  `Entry`. A `module-load` entry reads the module only, so a `null` export name is never read. `reach` is the root piece's `reach` value (`call`,
  `call-and-await`, `call-and-iterate`, `construct`, `construct-then-call`, `construct-then-read`,
  `construct-then-assign`, `call-static`, `call-member`, `module-load`). `constructorArity` splits a class
  entry's `args` into constructor arguments and method arguments. `member` is the method or property name.
  `closureParamTypes` are the declared types of a returned closure's parameters.
- `standIns`: `Record<string, unknown[]>`, keyed `<specifier>#<exportName>`, the values an opaque callee answers in turn.
  Task 6.4.1 fills it from each callee's declared return type: the ordinary and edge values of that type.

## What to implement

For each input, in a fresh `vm` context (through `#gateway/node/vm`), so module state never leaks between inputs:

1. Transpile every `table.sources` entry with `ts.transpileModule` (through `#gateway/npm/typescript`) to CommonJS.
2. The sandbox's `require` answers a relative specifier from the transpiled set (`./is-big`, `./index`). A package or
   Node built-in specifier answers a stand-in: a function whose k-th call in a run returns
   `standIns[key][(inputIndex + k) % length]`. Every trace in which a stand-in answered is `settable: false`. A harness
   is never run here, because its values are already in the input. Any other specifier is an error:
   `the specimen '<folder>' imports '<specifier>', which no stand-in or sibling answers. An unresolvable import predicts no routes, so the predict broker never runs it.`
3. Set the sandbox `process.env` from `input.env` (`null` removes the key) as a `Proxy` that records each key read.
   Set `process.argv` to `['node', 'jest', ...input.argv]`. A read of an `argv` element past the end gives
   `undefined`. A trace for an input with a non-empty `argv` is `settable: false`.
4. Give the sandbox its own `Math` whose `random` answers `executeStatics.opaque.randomCycle[(inputIndex + k) %
   length]`. A trace in which `random` was called is `settable: false`.
5. Install the recorder functions of task 1.4.3's header: `__arm`, `__reach`, `__leaf`, `__read`, `__pass`. `__leaf`
   records `<leafId>=<class>:<typeof>` with the class function of that header. `__read` records the input name.
   `__pass(id, 'loop')` throws the cap sentinel (`executeStatics.opaque.capSentinel`) past
   `executeStatics.limits.passCap` passes of one id. `__pass(id, 'call')` does the same past `callDepthCap`. The run
   stays `capped` even when the specimen catches the sentinel: record the cap in the run state, not only in the throw.
6. Reach the entry the way `entry.reach` says, `input.calls` times in a row on one module and, for a class, one
   instance. A shared-state specimen's second call sees the state the first left. Then follow what the entry returns: call
   each method of a returned object, in name order, the first element of a returned array when it is a function, and a
   returned closure once for each value of `closureValues` built from `entry.closureParamTypes` (each type's
   `typeListStatics` known value, then its `edgeValueStatics` values). Those traces are `settable: false`, because an
   outside caller sets those parameters (card `callback/returned-closure`).
7. Run with `microtaskMode: 'afterEvaluate'`, so a promise chain settles before the script returns without making
   this broker async. Iterate a returned generator to its end, taking at most `executeStatics.limits.generatorStepCap`
   values.
8. Resolve complements before returning each trace: for a probe with a `complement`, add `<probeId>=<otherwise>` to
   `arms` when `__reach` ran for it and `<probeId>=<observed>` did not.
9. A thrown error is an outcome (`threw`, or `rejected` for a promise), never a broker failure. Read it with
   `isNativeError` from `#gateway/node/util__types`, never `instanceof`, because it belongs to the sandbox. A run that
   hit a cap has the outcome `capped`.
10. `reads` is the sorted `<name>=<display>` pairs for the input names `__read` recorded and the env keys the proxy
    recorded, taking each display from `input.displays`. For `calls` above 1 add `calls=<n>`.

There is no timeout. Every limit is a count (task 6.1.3).

## Tests

The proxy needs nothing staged: `vm` and the TypeScript transpiler are not I/O, so they run real. Build each probe
table by hand in the test, or with `probeSourceTransformer` (task 6.2.2) on the card's code.

- `VALID:` card `if/alone` gives two traces, `then` for `true`, `else` for `false`.
- `VALID:` card `state/module-let` with `calls: 2` gives `else` then `then` for `limit` 1, and a fresh module for each input.
- `VALID:` card `callback/then` settles before the broker returns: the ternary arm is recorded.
- `VALID:` card `callback/then-catch-finally`: `count -1` records `.then` skipped and `.catch` runs (the complement is
  resolved).
- `VALID:` a generator is iterated to its end.
- `VALID:` a thrown error has outcome `threw`. A rejected promise has outcome `rejected`.
- `VALID:` `process.env.SIZE` set, unset (`null`) and empty give three different traces, and the read of `SIZE` is in
  `reads`.
- `VALID:` `process.argv[2]` is `undefined` for an input with no `argv`, and `settable` is true. An input with an `argv`
  entry has `settable: false`.
- `VALID:` card `callback/returned-closure`: two traces from the closure calls, both `settable: false`.
- `VALID:` an opaque write (`Math.round(Math.random() * 10)`) gives different arms for different inputs and
  `settable: false`.
- `VALID:` a package stand-in answers `standIns` values in turn and marks the trace `settable: false`.
- `VALID:` `reads` for card `and/as-condition` with `ready false` holds `ready=false` and no `count`.
- `ERROR:` a loop that never ends (`while (true) {}`) returns outcome `capped` after `passCap` passes, with no timeout.
- `ERROR:` a recursive function returns outcome `capped` after `callDepthCap` entries.
- `ERROR:` a specimen that catches the cap sentinel in a `try` is still `capped`.
- `ERROR:` an unknown import specifier throws the message above, word for word.
