## Contract

```ts
routeGroupTransformer({ table, inputs, traces }): {
  routes: Route[];
  causes: string[];
  unreachedArms: { probeId: string; arm: string }[];
}
```

- `inputs`: the candidate list of task 6.2.1 (`CandidateInput[]`, imported from
  `contracts/candidate-input/candidate-input-contract.ts`, task 1.2.8).
- `traces`: one `CandidateTrace` (task 1.2.7) per input, in the same order. A trace holds `arms` as `<probeId>=<arm>`
  strings with every complement arm already resolved by the broker (task 6.3.1), `causes` as
  `<leafId>=<class>:<typeof>` strings, `reads` as sorted `<input>=<display>` pairs, `settable`, `cause` and `outcome`
  (`returned`, `threw`, `resolved`, `rejected` or `capped`).

A combination of arms that contradicts itself never shows up, because no input produces it. That is how this engine
drops it (DESIGN.md step 5).

## What to implement

1. **Arm sets.** The arm set of a trace is its `arms`, sorted and unique. Look each up in `table.probes` to get the
   route's `ArmStep`s: `file`, `kind`, `line`, and the reported arm label. A probe's `file` is the specimen-relative
   path of the file the construct sits in, so a branch in `check-limit.ts` gives a step in that file. A route's `arms`
   are sorted by file (`entry.ts` first, then the other files by path), then line, then kind, then arm (task 1.3.1).
2. **Ordinary routes (cause rule step 1).** Take the traces of the inputs without `edgeOf` and with `settable` true.
   A trace's key is its arm set plus its `causes`. Keep the first trace for each key, in input order. Each kept
   trace is one route. This is why `ready && count > 2` has three ordinary routes: `ready false` (the leaf class of
   `ready`), and `ready true` with `count > 2` false or true.
3. **Edge routes (steps 2, 3, 5).** Group the traces with `edgeOf` by `(edgeOf.input, the edge candidate's value)`.
   For each group, in the order of the kept ordinary routes:
   - Drop a candidate whose `reads` do not include `edgeOf.input`. If every candidate is dropped, the group makes no
     route: nothing read the input, so it owes no edge value (step 5). This is also where a parameter that only feeds
     an unread local gets no edge routes.
   - Among the rest, keep the first candidate in input order (DESIGN.md decision "Which value the other inputs take
     in an edge-value case"). The inputs are the product of each input's then-first list (task 6.1.1), with the first
     parameter varying slowest, so the first remaining candidate is the one whose other inputs take the first value
     of their lists that still lets the edge-valued input be read.
   - Only a candidate whose base is a kept ordinary route is considered.
   - For a group whose edge cause is `many` (an array with many items), the rule above is replaced: keep the candidate
     whose run takes the most distinct arms, and on a tie the last one in input order. A many array mixes its items so
     one run takes as many arms as it can (README cause rule step 3), and the route that takes the most arms is the
     one a reader wants to see (card `const/in/for-of-body/if-then`: `items [1, 2], enabled true, count 3`).
4. **Listed once (step 4).** A route's identity is its arm set plus its `reads`. When an ordinary route and an edge
   route have the same identity, keep the ordinary one only. An edge value that is also an ordinary value is one
   route. An input the run never read does not appear in `reads`, so it never makes a route of its own.
5. **Undriven routes (step 6).** Take the traces with `settable` false. List each arm set once, and only when no
   driven route has that arm set. The route has `driven: false`. Such a route has no edge routes. Candidates built on a
   non-settable ordinary candidate are ignored.
6. **Order.** Sort routes by their arm list as text, then driven before undriven. Routes with equal arms keep their
   input order, so the output is the same every run.
7. **Causes.** `causes` is the sorted set of cause class names over the driven routes: each route's input `cause`
   unless it is `ordinary`, plus the class part (before the `:`) of each entry of its trace `causes` unless it is
   `ordinary`. Task 6.2.6 matches today ids against it.
8. **Unreached arms.** `unreachedArms` lists every arm of every probe in `table.probes` that appears in no trace at all,
   whatever its outcome and whether or not it is settable. An arm only an undriven run reaches is reached. Task 6.1.6
   decides what each unreached arm means.

A trace with outcome `capped` is not used here. The broker refuses the specimen before this transformer runs (task
6.4.1).

## Tests

Write the inputs and traces by hand as small tables in the test, one row per input, from the card. Assert the whole
result with `toStrictEqual`.

- `VALID:` card `and/as-condition`: four ordinary inputs and twelve edge inputs reduce to 6 routes: `ready false`,
  `ready true count 2`, `ready true count 3` and `count 0`, `NaN`, `-1` on the `ready true` base with arms `else`.
- `VALID:` card `and/as-exit`: 6 routes, five of them with the arm `evaluates-right`.
- `VALID:` card `nullable/optional-param-fallback` (`count`, `limit?`): 10 routes, the four ordinary and six edge ones
  the card lists. The edge routes for `count` pair with `limit 2`, and those for `limit` with `count 11`.
- `VALID:` card `optional-param/alone`: 7 routes; `label ''` pairs with `count 3` (`if else, ternary then`).
- `VALID:` card `shape/if-if-if/sequence/three-args`: 12 routes; the edge routes of `count` pair with `enabled true, label 'x'`.
- `VALID:` card `edge/mixed-plus`: 9 routes with no arms; `causes` holds `negative`, `nan`, `empty-string`, `rule-named`,
  `zero`.
- `VALID:` card `edge/loose-equality`: 7 routes, three of them `return-true`.
- `VALID:` card `retype/guard`: 8 routes, 4 with `then`.
- `VALID:` card `callback/then`: 5 routes; only the ternary has arms.
- `VALID:` card `const/in/for-of-body/if-then`: 8 routes: `[]`, three ordinary one-item routes, three `count` edges, and a
  many array on the `enabled true, count 3` base.
- `VALID:` card `shape/if-if/sequence/two-args`: 7 routes, four ordinary arm combinations and three `count` edges on the
  `enabled true` base (then-first: `enabled true` is `enabled`'s first ordinary value).
- `VALID:` card `shape/if-if/sequence/three-args-one-unused`: 7 routes, because `label` is never in `reads`.
- `VALID:` card `known/env-two-files`: the arm steps of the `checkLimit if` in `check-limit.ts` carry `file: 'check-limit.ts'` and sort before or after the `entry.ts` steps by the file rule.
- `VALID:` card `consume/never-read`: one route with no arms, no edge routes.
- `VALID:` card `state/module-let`: 5 routes, one of them `else, then` from a run with 2 calls.
- `VALID:` card `loop/for-of`: 7 routes, `[]` takes only `skipped`, `[2, 3]` takes `runs`, `else` and `then`.
- `VALID:` card `callback/returned-closure`: the two traces are not settable, so two undriven routes, one per arm set.
- `VALID:` an argv specimen: the settable trace gives a driven route for the arm it takes, a non-settable trace gives an
  undriven route for the other arm.
- `VALID:` card `known/call-site-literal`: one route (`label then`), and `unreachedArms` names `label`'s `else`.
- `VALID:` an arm reached only by a non-settable run is not in `unreachedArms`.
- `EDGE:` an edge candidate equal to an ordinary one (the same `reads`) is listed once, as the ordinary route.
- `EDGE:` the input list in a different order that keeps the same ordinary candidates first gives the same routes.
- `EMPTY:` no traces gives no routes, no causes, and every arm unreached.
