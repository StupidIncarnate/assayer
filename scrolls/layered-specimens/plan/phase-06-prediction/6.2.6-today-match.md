## Contract

`todayMatchTransformer({ rows, plan, report, causes, paramKinds, leafReads, twoParamLeaves }): string[]` returns the sorted, unique
ids of every row of `rows` whose `match` holds. The caller passes `todayStatics.gaps` (task 1.1.5) as `rows`, so the
tests can pass small rows of their own.

- `report`: the predicted `SpecimenReport` (task 6.4.1 builds it before it calls this).
- `causes`: every cause class on a driven route (the `causes` of task 6.2.3).
- `paramKinds`: the kinds of the entry's parameters, read from the generator's own parse of `entry.ts`: `unknown`,
  `enum`, `literal-union`, `callable`, `optional-property`.
- `leafReads`: the write classes of the variables a predicted leaf reads, from the generator's own parse:
  - `compound-write`: written by a compound or logical assignment (`+=`, `??=`);
  - `loop-write`: written inside a loop body, a `const` declared fresh on each pass included (card
    `const/in/for-of-body`: `const size = count` in the body);
  - `shared-state`: a field or variable that a function or method writes and a later call reads: a module-level
    `let`, a class field, or a variable a returned closure captures, written by the entry or a method it calls and
    read by a later call of the entry (cards `state/call-sequence`, `state/module-let`, `state/this-field`). A write
    in a constructor or a setter does not count: it runs once, when the instance is built or assigned, so no later
    call depends on an earlier one (cards `class/constructor-to-method`, `reach/class-setter`).
- `twoParamLeaves`: `true` when one predicted comparison has two operands that are both entry parameters, such as
  `count > limit`. The caller reads it from the generator's own parse of `entry.ts`.

## What to implement

A row's `match` is a list of alternatives. The row matches when any alternative holds. An alternative holds when every
key in it holds. The keys are those of README "Today gaps":

| Key | Holds when |
|---|---|
| `pieces` | any listed piece appears in the plan: the entry tree, a sibling or a helper |
| `piecePositions` | a node of that piece sits in that position |
| `slotFills` | `[host, slot]`: a node of the host has that slot filled. `[host, slot, child]`: filled by that child piece |
| `axisValues` | the plan's axis equals one of the pairs |
| `paramTypes` | `paramKinds` holds one of the listed kinds |
| `leafReads` | `leafReads` holds one of the listed write classes |
| `causes` | `causes` holds one of the listed classes |
| `lintRules` | the report has a lint with one of the rules. A rule ending in `*` (`edge-merge-*`) matches by prefix |
| `buildErrors` | `true` and the report has a build error |
| `buildErrorReasons` | the report has a build error with one of the reasons |
| `gaps` | `true` and the report has a gap |
| `siblingFiles` | `true` and the plan has a sibling file |
| `twoParamLeaves` | `true` and the `twoParamLeaves` input is `true` |
| `stubValues` | `true` and the report's `stubValues` list is not empty |

## Tests

- One `VALID:` per key, each with a one-row `rows` list written in the test: `pieces`, `piecePositions`, `slotFills`
  (with and without the child), `axisValues`, `paramTypes`, `leafReads`, `causes`, `lintRules` (an exact rule, and
  `edge-merge-*` by prefix), `buildErrors`, `buildErrorReasons`, `gaps`, `siblingFiles`, `twoParamLeaves`, `stubValues`.
- `VALID:` the real rows. A plan with an `and` in the `value` position matches `value-position-logical`. A route with
  cause `zero` matches `edge-values`. A plan with the `in-check` piece matches `optional-property-presence`. An entry
  with an `unknown` parameter and the `type-guard-call` piece matches `guard-narrows-unknown`. An input with
  `twoParamLeaves` true matches `two-param-comparison`. A report with one `stubValues` row matches
  `derived-stub-values`. A class whose constructor writes a field a method reads (card `class/constructor-to-method`)
  has no `shared-state` read; a method that writes `this.calls` and reads it (card `state/this-field`) has one. A
  `const` declared in a `for…of` body and read by an `if` there is a `loop-write` read.
- `VALID:` an alternative with two keys holds only when both do (a row with `pieces` and `axisValues`).
- `VALID:` a row with two alternatives matches when either holds.
- `EMPTY:` a plain `if` specimen matches nothing.
- `VALID:` the ids come back sorted and unique.
