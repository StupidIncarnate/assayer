## Contract

```ts
valueCandidatesLayerTransformer({ input, conditions, options }): {
  ordinary: Candidate[];
  edge: Candidate[];
  refused?: { input: string; reason: 'unknown' | 'callable' };
}
```

- `input`: `{ name, typeText, optional, hasDefault, path, envConvertsTo?, harnessValue?, stubValues? }`. `name` is a
  parameter, an environment variable or a property path (`options.label`, `STRICT`). `typeText` is the declared type
  as text. `envConvertsTo` is the base type an environment read converts to (`number` for `Number(process.env.SIZE)`).
  `harnessValue` is the value a companion harness supplies. `stubValues` is the list a stub correction gives.
- `conditions`: the arm conditions that read this input, in source order. Task 6.2.1 builds them from its own parse of
  the specimen. The kinds are in the table below.
- `options`: `{ exactOptionalPropertyTypes: boolean; inReadsProperty: boolean }`.
- `Candidate`: `{ value: unknown; display: string; cause: CauseClass; arm?: string; leftOut?: true }`. `CauseClass` is
  a name from `edgeValueStatics.causes` (task 1.1.3). `value` may be `NaN` or `undefined`.

An `ordinary` candidate is derived from an arm condition. An `edge` candidate is a value from `edgeValueStatics` for
the input's type. A value that is both is listed once, in `ordinary` (README cause rule, step 4). Each list is ordered
and de-duplicated by `display`.

## Ordinary values by condition

Each list is in the order DESIGN.md decision "Which value the other inputs take in an edge-value case" fixes: the
value for the then arm (or the first arm) first, then the value for the else arm (`count > 2` gives `3`, then `2`).
Task 6.2.1 and task 6.2.3 rely on that order: when an input takes an edge value, every other input takes the first
value of its list that still lets the edge-valued input be read. The table below names each pair's values; write each
list then-first, whatever order a row names them in.

| Condition kind | Ordinary values |
|---|---|
| `compare >` literal `n` | number: `n`, `n + 1`. string: `n`, `n` followed by `typeListStatics.neighbourSuffix` |
| `compare >=` `n` | `n - 1`, `n` |
| `compare <` `n` | `n`, `n - 1`. string: `n`, the empty string |
| `compare <=` `n` | `n + 1`, `n` |
| `compare ===` or `!==` `v` | a neighbour of `v`, then `v`. Number neighbour `v + 1`. String neighbour `v` plus the suffix. Boolean neighbour `!v`. `null` and `undefined` take the type's known value as neighbour |
| `compare ==` or `!=` `v` | as `===`. For a union that holds a string and a number, also the string member's known value on the false arm, then the string form of `v` on the true arm, cause `rule-named` (`edgeValueStatics.ruleNamed['loose-equality']`, `'0'` for `value == 0`) |
| `compare-inputs` (`count > limit`, neither a literal) | the right operand takes `layeredMatrixStatics.readerLiteral[type]` (2). The left operand takes that value, then that value plus one (2, 3) |
| `compare-state` | a comparison with a shared-state variable: the variable's value on the first call is the literal (card `state/module-let`: `calls` is 1 on the first call, so `limit` gets `1`, then `0`) |
| `bound` (a loop counter against this input) | the counter's start literal (the loop is skipped), that literal plus one (one pass), and each literal the body compares the counter with, plus one (the pass that takes that arm). Card `state/loop-counter` gives `0`, `1`, `4` |
| `truthiness` | then: `typeListStatics[type].known` (3, `'abc'`, `true`). Else: the first falsy value in the type's edge list: `0`, `''`, `false`, then `null` or `undefined` where the type allows them |
| `nullish` (`??`, `?.`, `== null`) | left: the type's known value. Right: the first nullish member the type allows (`undefined`, else `null`) |
| `length` `>` `n` | a string or array of `n + 1` items, then one of `n` (items come from the first sample) |
| `typeof` with the compared member | one ordinary value per member base type: the members the comparison rejects first (each member's known value), then the compared member |
| `in` `property` | the property present with its type's known value, then the property missing |
| `switch` with labels | each label, then one no-match value: number label `7` gives `8`, string `'xyz'` gives `'a'` (`'b'` when `'a'` is a label), a literal union or enum gives none (every member is a label) |
| `guard` `v is T` | else: the first base type in `edgeValueStatics.unknownRejects` (a string, `typeListStatics.string.known`). Then: the known value of `T` |
| `default` (a parameter default) | left out (cause `left-out`, arm `defaulted`), then the type's known value (arm `given`). For `T | null` also `null` (arm `given`, cause `null`) |
| `operand` (`+`, `==` operand with no literal) | one ordinary value per member base type of a union. For `+` the number member is `1` as the left operand and `2` as the right operand (so the sum is `3`, card `edge/mixed-plus`). For `==` and any other operand it is `typeListStatics.number.known`. The string member's value is `'abc'`, except for `+` on a union that holds a string and a number: there it is the rule-named `'1'` (`edgeValueStatics.ruleNamed['mixed-plus']`), cause `rule-named` |
| no condition reads the input | one value: the type's known value |

A parameter that is optional or has a default gets `left-out` (cause `left-out`) as an `ordinary` candidate when a
`truthiness` (falsy side), `nullish` or `default` condition reads it, and as an `edge` candidate otherwise.
Leaving a parameter out and passing `undefined` are one thing at run time, so only `left-out` is listed (DESIGN.md
"Optional and nullable values").

## Edge values by type

Read the lists from `edgeValueStatics.edgeValues` (the token `'NaN'` becomes `Number.NaN`):

- `number`: `0`, `NaN`, `-1`. `string`: `''`. `boolean`: `false`.
- `null` and `undefined` where the type allows each, each its own candidate (cause `null`, `undefined`).
- A literal union or enum: each member (cause `member`).
- An array: `[]` (cause `empty`) and a many array (cause `many`, task 6.2.1 mixes its items). The one-item array is the
  ordinary shape. Its element takes the element's ordinary values as `ordinary` candidates and the element's edge
  values as `edge` candidates with the element's cause. The element's values appear only in the one-item array.
- An object type that allows it: `{}` (cause `empty-object`).
- An optional property: `missing` (cause `missing`). Present as `undefined` (cause `present-undefined`) only when
  `options.inReadsProperty` is true and `options.exactOptionalPropertyTypes` is false. Under
  `exactOptionalPropertyTypes` TypeScript refuses it, so it is never listed.
- An environment read: `unset` (the key is removed; cause `unset`), `''` (cause `empty-string`), and the string form
  of each ordinary and edge value of `envConvertsTo` (`'3'`, `'2'`, `'0'`, `'-1'`). `NaN` is `unset`, so it is not
  listed twice. Card `const/in/module` gives six: `'3'`, `'2'`, `'0'`, `'-1'`, `''` and unset.
- A union of base types (`number | string`): each member's edge values, tagged with the member.

## Refusals and companions

- A parameter typed `unknown` with no `guard` condition and no `harnessValue` returns `refused` with reason
  `unknown`. A callable parameter with no `harnessValue` returns `refused` with reason `callable`. A cast does not
  change this (DESIGN.md "A cast from `unknown`"). `x!` builds from the declared type, so `count!` on
  `number | undefined` still lists `undefined`.
- A `guard` condition makes `unknown` buildable: the then side from `T` with `T`'s edge values, the else side from
  `unknownRejects`: a string with its edge value `''`, then `null` and `undefined`. Card `retype/guard` gives 8.
- A `harnessValue` makes the list that one value, cause `ordinary`.
- `stubValues` makes the list exactly those values, cause `stub-value`, and no edge values. A stub correction is a
  human's claim about real data, so the engine tries only what it allows (README "Known values").

## Tests

Each is a `VALID:` with the ordinary and edge lists asserted whole with `toStrictEqual`, written by hand from the
card named.

- `{number, compare > 2}`: ordinary `[3, 2]`, edge `[0, NaN, -1]`.
- `{number | undefined, truthiness}` (card `edge/truthiness`): ordinary `[3, 0]`, edge `[NaN, -1, undefined]`.
- `{string | undefined, nullish}` (card `nullish/alone`): ordinary `['abc', undefined]`, edge `['']`.
- `{number | string, compare == 0}` (card `edge/loose-equality`): ordinary `[0, 1, '0', 'abc']`, edge `[NaN, -1, '']`.
  The `'0'` has cause `rule-named`.
- `{number | string, operand +, left}` (card `edge/mixed-plus`, input `base`): ordinary `[1, '1']`, edge `[0, NaN, -1, '']`. The `'1'` has cause `rule-named`.
- `{number, operand +, right}` (same card, input `extra`): ordinary `[2]`, edge `[0, NaN, -1]`.
- `{number | string, typeof}` (card `retype/typeof`, `typeof value === 'string'`): ordinary `['abc', 3]`, edge `[0, NaN, -1, '']`.
- `{unknown, guard v is number}` (card `retype/guard`): ordinary `[3, 'abc']`, edge `[0, NaN, -1, '', null, undefined]`.
- `{number, hasDefault, default}` (card `default-param/alone`): ordinary `[3, left-out]` (`given` is the default branch's first arm), edge `[0, NaN, -1]`.
- `{string | null, hasDefault, compare === null}` (card `nullable/default-and-null`): ordinary
  `[null, 'abc', left-out]` (given before defaulted, and within given the `=== null` then value first), edge `['']`.
- `{number[], compare > 2 on the element}` (card `loop/for-of`): ordinary `[[3], [2]]`, edge
  `[[], [0], [NaN], [-1], many]`.
- `{optional property, in}` with `exactOptionalPropertyTypes` false: `missing`, `present-undefined` and a value. With it
  true: no `present-undefined`.
- `{env SIZE, converts to number, compare > 2}` (card `const/in/module`): the six values above.
- `{literal union 'a' | 'b', switch}`: ordinary `['a', 'b']`, edge empty after de-duplication.
- `{number, compare-inputs right}` (card `shape/if/two-args-one-check`, input `limit`): ordinary `[2]`.
- `{number, bound}` (card `state/loop-counter`, start 0, inner literal 3): ordinary `[1, 4, 0]` (the values that run the loop first, then the start literal that skips it).
- `INVALID: {unknown, no guard}` returns `refused` with reason `unknown`. `INVALID: {callable}` returns reason
  `callable`. `VALID: {callable, harnessValue}` returns that one value.
- `VALID: {stubValues [1, 2, 3]}` returns those three with cause `stub-value` and no edges.
- `EMPTY: {number, no condition}` returns ordinary `[3]`.
