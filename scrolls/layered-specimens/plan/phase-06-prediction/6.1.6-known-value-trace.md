## Contract

`knownValueTraceTransformer({ files, table, unreachedArms, stubCorrection }): TraceResult[]`

- `files`: `{ relPath, content }[]`, the unprobed text of every `.ts` file of the specimen and the stub JSON file
  (`assayer/stubs/objects/packages/syntax-repository/src/<folder>/entry.ts/<Type>.json`, a path relative to `smoke-repo/`, task 5.4.1) when the plan has a stub correction. `entry.ts` is the declared
  entry point (task 9.1.5): its exports are callable from outside the specimen, no other file's exports are.
- `table`: the probe table (task 1.4.3), to find each unreached arm's branch.
- `unreachedArms`: `{ probeId, arm }[]` from task 6.2.3, the arms no derived input took.
- `stubCorrection`: `{ type, property, values }` or `undefined`.

```ts
type TraceResult =
  | { arm: { probeId: string; arm: string }; channel: 'lint' | 'build-error';
      consumption: { file: string; line: number }; trace: { file: string; line: number }[] }
  | { arm: { probeId: string; arm: string }; refused: string };
```

The result has one element per unreached arm, in the order of `unreachedArms`. Parse the files with the TypeScript
factory (through the gateway). Never read Assayer (rule P4).

## What to implement

For each unreached arm:

1. **Find the branch** from the probe (`file`, `line`, `form`). Supported forms are `if`, `ternary`, `and`, `or`,
   `switch`, `loop` (a `while` or `for` condition) and `return-comparison`. The arm names the truth the branch
   condition needs: `then`, `evaluates-right` (for `&&`), `return-true` and `runs` need the condition true;
   `else`, `stops-at-left` (for `&&`), `return-false` and `skipped` need it false; for `||` swap them;
   `case:<label>` needs the subject to equal the label; `default` and `no-match` need it to equal none. An exhaustive
   switch has no `no-match` arm at all (task 6.1.4), so it never reaches this transformer as an unreached arm and is
   never reported as dead.
   Any other form (`try`, `default-param`, `logical-assign`, a callback) cannot be killed by a known value, so the
   arm is refused (step 6).
2. **Collect the known set of each variable the condition reads.** A condition is built from literals, parameters of
   the branch's own function, `const` locals, `.length`, property reads of a parameter (`job.priority`),
   comparisons, `!`, `&&`, `||` and truthiness. The known set of a variable is the first source that applies, in
   this order:
   - **stub correction.** The variable is a property path of a parameter whose declared type is `stubCorrection.type`
     and the path is `stubCorrection.property`. The known set is `stubCorrection.values`. Channel `build-error`.
     Consumption point: the line of the entry parameter whose type the correction covers.
   - **const.** The variable is a `const` whose initializer is a literal, or a ternary, `||` or `??` of literals
     (`process.env.STRICT ? 5 : 10` gives `{5, 10}`). The known set is the literal values.
   - **call sites.** The variable is a parameter of a function `F` that is not exported from `entry.ts`. Find every
     call of `F` in the specimen's files (a call by `F`'s name, in its own file or in a file that imports it through a
     relative specifier). The known set is the union of the known sets of the argument at that position in every
     call. If one call's argument has no known set, there is none. A parameter of an exported function of `entry.ts`
     has none from this source, because an outside caller can pass any value.
   - **type.** The variable is a parameter whose declared type is a union of literals only (`'a' | 'b'`). The known
     set is the members. A type with any non-literal member has none (DESIGN.md "Does a type count as a known
     value?").
   - **type, never missing.** The variable is a parameter whose declared type is an array or an object type, with no
     `undefined` or `null` member (`items: number[]`, `box: { count: number }`). Every value of such a type is
     truthy, so its known set for a truthiness check is the single value `truthy`. It decides only a truthiness
     condition (`if (items)`, `items ? a : b`, `!items`); any other condition reads it as `unknown`. This is the
     edge-value merge rule "always truthy", which DESIGN.md says is already the unreachable-exit lint, so the
     channel is `lint` with rule `unreachable-exit`.
3. **Evaluate.** Take every assignment in the product of the known sets of the variables the condition reads. Evaluate
   the condition under each, with three-valued logic: `true`, `false` or `unknown` (a variable with no known set, or
   an operation the evaluator does not support, is `unknown`). The arm is dead when, under every assignment, the
   condition is definitely the opposite of what the arm needs. One `unknown` or one assignment that allows the arm
   keeps it alive.
4. **Consumption point** (README table):
   - a literal argument at a call site: the call (`measure(5)`).
   - a `const`: the first call that passes it on (`applyLimit(limit)`), or the branch's own read when the branch is in
     the const's own function.
   - a type, or a type that is never missing: the line of the parameter that declares the type (DESIGN.md decision
     "Where a type known value is reported").
   - a stub correction: the entry parameter's line, channel `build-error`.
   When several sources feed the variable, report at the first one in sorted `(file, line)` order.
5. **Trace.** `{ file, line }` steps from the consumption point to the dead arm: the consumption point, then each
   call that carries the value one function deeper (the call inside the callee that passes the parameter on), then
   the branch condition's line. For a stub correction the first step is the stub JSON file at line 1, then the
   consumption point's line, then the hops. For a type, the first step is the parameter's line and the last is the
   branch line (the same line when they share a function and the steps are listed once each).
6. **Refuse** when no source kills the arm. This is the engine's refusal of a specimen: no derived input reaches an arm
   that no known value proves dead (README cause rule, step 6). Return `refused` with exactly:
   `the specimen reaches no input for the '<arm>' arm of the <kind> on line <line> of <file>, and no known value in it proves that arm dead. Rewrite the piece so an input reaches the arm, or give it a known value that kills it.`
   The caller (task 6.4.1) refuses the whole specimen with that sentence and never predicts a lint from "no input
   reached the arm".

## Tests

Write the files of each card as `files` and assert the whole result with `toStrictEqual`. Line numbers are those of
the card's code as printed.

- `VALID:` card `known/call-site-literal`. The unreached arm is the `else` of `label`'s `if`. Result: channel `lint`,
  consumption `{ entry.ts, 10 }` (the call `measure(5)`), trace `[10, 8, 2]` (the call, the call `label(size)` inside
  `measure`, the `if (size > 2)`).
- `VALID:` card `known/env-two-files`. The unreached arm is the `then` of `checkLimit`'s `if`. Result: channel `lint`,
  consumption `{ entry.ts, 5 }`, trace `entry.ts:5`, `apply-limit.ts:3`, `check-limit.ts:2`.
- `VALID:` card `known/stub-correction` with `stubCorrection` `{ type: 'Job', property: 'priority', values: [1, 2, 3] }`.
  Result: channel `build-error`, consumption `{ entry.ts, 12 }`, trace `assayer/stubs/objects/packages/syntax-repository/src/known/stub-correction/entry.ts/Job.json:1`,
  `entry.ts:12`, `entry.ts:10`, `entry.ts:4`.
- `VALID:` a literal-union parameter `mode: 'a' | 'b'` with `if (mode)`: the `else` is dead, channel `lint`,
  consumption the parameter's line, trace the parameter then the `if`.
- `VALID:` `if (mode.length)` on `'a' | 'b'`: `.length` of each member is 1, so `else` is dead.
- `VALID:` `if (items)` on `items: number[]`: the `else` is dead, channel `lint`, consumption the parameter's line,
  trace the parameter then the `if`.
- `VALID:` `if (box)` on `box: { count: number }`: the same, for an object.
- `EDGE:` `if (box)` on `box: { count: number } | undefined`: no known set, so the `else` is reached by
  `undefined` and is never in `unreachedArms`; a hand-built call with it unreached is refused.
- `VALID:` a `const x = 5;` read by `if (x > 2)` in the same function: the `else` is dead at the branch's own line.
- `EMPTY:` card `known/no-known-value`: every arm is reached, so `unreachedArms` is empty and the result is `[]`.
- `EDGE:` an exported `entry(size: number)` calling `label(size)`, with an arm in `label` unreached: refused, because
  `size` is unknown. The refused sentence is asserted word for word.
- `EDGE:` a call whose one argument is a literal and another call's is a parameter: no known set, refused.
- `EDGE:` a `try` arm unreached: refused.
- `EMPTY:` card `type/enum`: the switch is exhaustive, so `unreachedArms` holds no `no-match` and the result is `[]`.
