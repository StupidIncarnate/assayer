## Contract

```ts
candidateInputsTransformer({ plan, files, table }): {
  inputs: CandidateInput[];
  refused?: { input: string; reason: 'unknown' | 'callable' };
}

// CandidateInput is imported from contracts/candidate-input/candidate-input-contract.ts (task 1.2.8).  // set on an edge candidate
};
```

`files` is the specimen's unprobed files. `table` is the probe table (task 6.2.2 builds it before this task runs).
`base` in `edgeOf` is the index, in `inputs`, of the ordinary candidate the edge candidate was built from.

**This task emits the candidate list. It does not decide which candidates become routes.** It cannot know which
inputs a run reads, because that is a fact of the run. Task 6.2.3 keeps the first ordinary candidate for each arm
combination and cause, and keeps an edge candidate only when its target input was read (README cause rule steps 3
and 5). Say this split plainly in the file header.

## What to implement

1. **Find the inputs.** Parse `entry.ts` with the TypeScript factory. An input is each entry parameter (for a class
   entry: each constructor parameter, then each parameter of the method the plan reaches), each `process.env.KEY`
   read, and each property path a leaf reads (`table.leaves[].path`). An object parameter is built from its
   property inputs, with the properties no leaf reads set to their type's known value. An array parameter is the
   one-item array of its element input, plus its size candidates. Parameters that no leaf, probe or `__read` can
   reach get one value, the type's known value, and no edge candidates (README cause rule step 5).
2. **Find each input's conditions.** For each leaf in `table.leaves`, classify its expression into a condition kind
   of task 6.1.1 (`compare`, `compare-inputs`, `compare-state`, `bound`, `truthiness`, `nullish`, `length`, `typeof`,
   `in`, `switch`, `guard`, `default`, `operand`) and attribute it to an input. Attribute through a `const` or `let`
   that is a bare alias or destructuring of an input, through a same-file call that passes an input as an argument,
   through `x ?? literal` (the literal becomes the comparison's literal while the input is left out), and through a
   local written from an input (`total += item`, a `for…of` element): the comparison applies to the input that feeds
   the local. A shared-state variable written `+= k` from a literal `i` has value `i + k` on the first call.
3. **Candidates per input.** Call `valueCandidatesLayerTransformer` (task 6.1.1) for each input, passing its
   conditions, its companion (`harnessValue` from the harness the plan writes, `stubValues` from `plan.stubCorrection`
   or the stub file the plan writes) and its options (`exactOptionalPropertyTypes` from `plan.compilerOptions`;
   `inReadsProperty` when an `in` leaf reads the property). The first input to return `refused` makes this transformer
   return it with no inputs. The caller turns it into a gap or a refusal (task 6.2.4).
4. **Ordinary inputs (cause rule step 1).** The product of the `ordinary` lists, in parameter order with the first
   parameter varying slowest and each list in its own order, so the first combination uses every input's first
   ordinary value. Each is one `CandidateInput` with cause `ordinary`. When `plan.callSequence` is above 1, the
   product also crosses `calls` from 1 to `plan.callSequence` (`layeredMatrixStatics.callSequence.maxCalls`),
   and a shared-state specimen's candidates carry `calls`.
5. **Edge inputs (steps 2 and 3).** For each input `p` and each `edge` candidate `e` of `p`: one `CandidateInput` for
   each ordinary candidate `b` built with `p` replaced by `e`, with `edgeOf: { input: p, base: <index of b> }` and
   cause `e.cause`. Two inputs never take edge values in one candidate. An array's `[]` and many edge candidates take
   every other input from the ordinary candidate `b`. The many array mixes its items: for an element read by a
   condition, the items are that element's ordinary values in order (`[2, 3]` for `item > 2`), so one run takes every
   arm the loop body has. An element's edge values appear only inside the one-item array.
6. **Env and argv.** An `env` candidate sets `env[KEY]` to the string or `null` (unset). An input that reads
   `process.argv` is fixed in a test worker: its first candidate is `undefined` (settable), and every other candidate is
   `settable: false`, supplied as `argv`.
7. **No cap.** The transformer returns every ordinary and edge candidate, however many there are (DESIGN.md
   decision "Matrix size": there is no cap). It never cuts the list and never refuses a specimen for its size.
   The only guard against runaway code is the run's deterministic pass and depth counts (task 6.1.3).

The `display` string joins `<name> <display>` pairs in parameter order (`count 3, ready true`).

## Tests

Hand-write each expected input list from the card.

- `VALID:` card `and/as-condition` (`ready: boolean`, `count: number`): ordinary candidates `ready true/false` crossed
  with `count 3/2` (four, then-first), edge candidates `count 0, NaN, -1` on each of the two `ready` values. Task 6.2.3's tests
  cover how they reduce to the card's 6 routes.
- `VALID:` card `edge/mixed-plus`: ordinary `base 1/'1'` with `extra 2`, edges `base 0, NaN, -1, ''` and `extra 0, NaN, -1`
  (2 + 7 = 9 candidates).
- `VALID:` card `edge/loose-equality`: ordinary `0, 1, '0', 'abc'` (each member's true-arm value first), edges `NaN, -1, ''` (7).
- `VALID:` card `nullable/optional-param-fallback` (`count`, `limit?`): `count` ordinary `[11, 10, 3, 2]` (from the literal
  10 inside `limit ?? 10`, then from the comparison with `limit`, each pair then-first), `limit` ordinary `[2, left out]`
  (given is the left arm of `??`, its then arm), edges `count 0, NaN, -1` and `limit 0, NaN, -1`.
- `VALID:` card `const/in/module` (env `SIZE`): ordinary `'3'`, `'2'`, edges unset, `''`, `'0'`, `'-1'`.
- `VALID:` card `state/module-let`: `limit` ordinary `[0, 1]` (then-first: `calls > 0` takes then on the first call) crossed with `calls` 1, 2, 3.
- `VALID:` card `state/loop-counter`: `limit` ordinary `[1, 4, 0]`, edges `NaN`, `-1`.
- `VALID:` card `loop/for-of`: ordinary `[3]`, `[2]`; edges `[]`, `[0]`, `[NaN]`, `[-1]` and a many array `[2, 3]`.
- `VALID:` card `retype/guard`: ordinary `3`, `'abc'` (the guard's then arm first); edges `0, NaN, -1, '', null, undefined`.
- `VALID:` card `shape/if-if/sequence/three-args-one-unused`: `label` has one value and no edge candidates.
- `VALID:` an argv source: the first candidate is settable, every other is `settable: false`.
- `VALID:` card `companion/callback/with-harness`: `check` takes the harness value only.
- `VALID:` card `known/stub-correction`: `job.priority` takes exactly `1, 2, 3` with cause `stub-value`.
- `INVALID:` card `retype/as-from-unknown`: returns `refused` with input `raw`, reason `unknown`.
- `INVALID:` card `companion/callback/no-harness`: returns `refused` with input `check`, reason `callable`.
- `VALID:` an entry with five `number` parameters returns the whole product of ordinary candidates plus every edge
  candidate, with no cap and no refusal.
- `EMPTY:` an entry with no parameter gives one input with no args.
