## What to implement

Task 6.5.1 already updated the expected accepted-flags string in the "refused arguments" test, so leave that alone.
Add a `describe('show mode')` beside the existing ones with:

- `VALID: {argv: [--show=src/if/alone]} => exit 0, and the report of card if/alone`. Parse the output with
  `JSON.parse` and assert with `toStrictEqual` the whole `report`, written by hand from the card: one branch `if`
  with arms `then` and `else`, two driven routes (one taking `then`, one taking `else`), `fewestRuns` 2, and every
  other channel empty. Assert `today` is `[]` and `report.stubValues` is `[]`.
- `VALID: {argv: [--show=src/or/as-condition]} => 3 routes`. This is the systematic specimen the planner writes
  for `or` in a condition: `if (left || right)` with two `boolean` parameters. Its routes are `left true`,
  `left false, right true` and `left false, right false` (README "The cause rule": each short-circuit cause of
  an arm is its own route, and `false` is both a boolean's ordinary else value and its edge value, so it is listed
  once). Assert `report.routes.length` is 3 and `report.fewestRuns` is 2, each with `toBe`. Never name
  `src/and/as-condition` here: the systematic specimen at that folder has 3 routes too, but phase 7 declares the
  DESIGN.md card at that folder (6 routes), and a card wins its folder (task 4.5.1), so a test naming it would
  turn red in phase 7.
- `INVALID: {argv: [--show=src/nope]} => exit 1 with the unknown-folder message`, asserted word for word.

The tests name two specimens only. They never assert counts of the whole matrix.

## Verify

`npm run ward -- -- packages/specimen-generator/src/startup`

As the phase gate, `npm run generate:specimens -- --show=src/if/alone` prints the card's report.
