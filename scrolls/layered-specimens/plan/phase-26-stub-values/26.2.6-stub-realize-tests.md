## What to implement

Task 26.2.2 changes the values a property demand holds, in the same row. Every assertion in these test files that
names a whole demand list, or a value an arrangement took from one, changes with it. Rewrite each such expected
value by applying the value rule of task 26.2.2, written here again so this task does not wait for that one:

**The value rule.** For each branch leaf that reads the property, the demand holds the ordinary value of each of
the leaf's two arms, and nothing else: the first value `domainValuesTransformer` realizes for that arm's domain, the
same value `cause-arrange` gives that arm's ordinary case (README "The cause rule" step 1: `count > 2` gives `3` for
`then` and `2` for `else`). An arm whose domain names no point of its own takes `edgeValueStatics.plain` for the
property's type (task 26.1.4). No edge value and no extra representative value is added. Values are de-duplicated and
sorted, as today.

Edit only the expected values. Change no test name, no input and no other assertion. Read the test's input, apply the
rule by hand, and write the result (brief rule 19). The `stub-realize` source files are not in this task.
