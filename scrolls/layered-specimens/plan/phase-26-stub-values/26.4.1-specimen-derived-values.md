## What to implement

`derived-values.ts` holds three entries, written from the cards:

```ts
type Options = { label?: string };

export const byCount = (box: { count: number }): string => {
  if (box.count > 2) {
    return 'then';
  }
  return 'else';
};

export const byLabel = (options: Options): string => {
  if ('label' in options) {
    return 'set';
  }
  return 'unset';
};

export const bySize = (): string => (Number(process.env.SIZE) > 2 ? 'big' : 'small');
```

The test follows `happy-path/object-member` neighbours (`discover` them first). It compiles a temporary mirror of this one folder (the method of task 8.3.1: a `package.json` copy, a `tsconfig.json`
that `extends` the real one, and the folder's direct `.ts` files), not the whole manual smoke repo, because
environment stubs are keyed `process.env#<PROP>` and would union with every other specimen that reads `SIZE`. It
reads the stub index that compile wrote, and asserts, by
reading the file and the cards, never from a run:

- an object stub keyed `<relPath>#byCount.box` whose `count` demand is `values: [2, 3]`;
- the stub keyed on `Options` whose `label` demand is `values: ['x']` with `missing: true`;
- an env stub `SIZE` with `values: ['2', '3']` and no `unset`.

Write the registry line by reading the file (brief rule 21): the access, branch, parameter and env traits the
neighbours of `happy-path/object-member` use. This is the only task in the row that edits the registry.
