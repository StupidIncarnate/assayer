# 16.1.3 The walk context marks exits that do not leave the scope

- **Phase:** 16, Core: `try` and `await`. **Row:** #1, in parallel with 16.1.1 and 16.1.2. No task of the row depends on another task of the row.
- **Depends on:** phase 15.
- **Model:** default (the worker's default model; this task is fully specified).
- **Covers:** pieces table row `try…catch…finally` ("A return in finally overrides the others"); `packages/core/CLAUDE.md` section 2.

A `throw` inside a `try` block that has a `catch` clause never leaves the scope: the `catch` block runs instead. If the `finally`
block always returns, no `return` or `throw` in the `try` and `catch` blocks leaves the scope either. The walk must know this when
it reaches the `throw` or `return` statement, and the walk carries every such fact down in its context (section 2).

## Contract

```ts
absorbs: z.enum(['throw', 'exit']).optional(),
```

- `'throw'`: a `throw` statement below this point is caught by a `catch` clause of the same scope, so it is not an exit of the
  scope. A `return` below is still an exit.
- `'exit'`: every `return` and `throw` below this point is replaced by a `return` or `throw` in a `finally` block, so none of
  them is an exit of the scope.
- Absent: every `return` and `throw` is an exit, as today.
