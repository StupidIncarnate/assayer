## What to implement

Add one rule for `TryStatement`, before the final `return false`:

- the statement is terminal when its **finally block** is terminal, whatever the other blocks do: a `return` or `throw`
  in `finally` replaces every outcome of the try and catch blocks, so nothing after the statement runs;
- otherwise it is terminal when its **try block** is terminal and its **catch clause is absent or terminal**. A try block
  that always exits with no catch clause lets the exception leave the scope, which is an exit too.

Recurse through the existing `readTerminalLayerTransformer` for each block. A catch clause's block is
`catchClause.getBlock()`. Do not scan. Update the header comment with the rule.

`read-accounted` needs no edit: a terminal try is accounted for through its first line, and a try that is not terminal falls
through to its last `return false`, so the enclosing scope still owes its own end-of-scope exit (the two arms converge on
the code after the statement). State that in your reply. If you find a reason the rule belongs in `read-accounted` instead,
stop and report it without editing `read-accounted`: that file is not in this task.
