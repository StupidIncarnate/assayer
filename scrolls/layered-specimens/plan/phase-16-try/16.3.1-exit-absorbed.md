## What to implement

1. A statement is **absorbed** when `context.absorbs` is `'exit'`, or when it is `'throw'` and the statement is a `throw`.
2. For an absorbed statement the handler mints no exit and no probe site. It still emits its walk node with `handled: true`
   and still descends into the expression under the enclosing guards, so a call in `throw makeError(x)` reaches `handle-call`
   and a ternary reaches `handle-ternary`. Skip the per-arm split `read-conditional-exit` makes: that reader is not called.
3. A statement that is not absorbed behaves byte for byte as today.
4. Header comment: the absorbed rule, and why an absorbed statement still descends.

## Tests

- `VALID: throw inside a context that absorbs 'throw' => no exit, no probe site, the node is handled`
- `VALID: return inside a context that absorbs 'throw' => the exit and its probe site as today`
- `VALID: return and throw inside a context that absorbs 'exit' => no exit for either`
- `VALID: an absorbed throw whose expression holds a call => the call is still a descent`
- `VALID: an absorbed throw of a ternary => no per-arm exits; the ternary is a descent`
- `EMPTY: no absorbs => every existing expectation holds`
- `EDGE: every existing handle-exit test passes unchanged`
