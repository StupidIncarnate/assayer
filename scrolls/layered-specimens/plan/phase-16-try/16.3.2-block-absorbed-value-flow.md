# 16.3.2 A block keeps its value-flow split off an absorbed exit

- **Phase:** 16, Core: `try` and `await`. **Row:** #3, in parallel with 16.3.1, 16.3.3 and 16.3.4. No task of the row depends on another task of the row.
- **Depends on:** row #2 (the context rule of task 16.2.1).
- **Model:** default (the worker's default model; this task is fully specified).
- **Covers:** pieces table row `try…catch…finally`; `packages/core/CLAUDE.md` section 8 (value-flow rides the exit split).

`handle-block` collapses `const x = cond ? y : z; return x` into the per-arm split of `return cond ? y : z`, and mints
those exits itself, so the exit handler of task 16.3.1 never sees them. Inside an absorbed context that split must not mint
exits.

## What to implement

1. Before the value-flow check, decide whether the block's last statement is **absorbed**: `context.absorbs` is `'exit'`, or it
   is `'throw'` and the last statement is a `throw`.
2. When it is absorbed, skip the value-flow split and return `handlerResultLayerTransformer({ descents })`. The pair then walks
   as two ordinary statements: the `const` is a descent and the exit statement is absorbed by task 16.3.1.
3. A block whose last statement is not absorbed splits exactly as today, so the same syntax reads the same way in and out of a
   `try` (section 5.12).
4. Header comment: the absorbed case.

## Tests

- `VALID: const x = c ? a : b; throw x inside a context that absorbs 'throw' => no value-flow exits; two descents`
- `VALID: const x = c ? a : b; return x inside a context that absorbs 'throw' => split into per-arm exits as today`
