## What to implement

1. Add `'try'` to the `kind` enum of `branchNodeContract`. A `try` branch lists its arms as `arms: ['finishes', 'catches']`
   (task 16.3.3 sets them). The first arm, `finishes`, is the one taken when the branch's condition holds. State that in the
   contract's header comment in one sentence.
2. Add one entry to `uncataloguedTraits`, keeping the keys alphabetical:

   ```ts
   'branch:try': 'a `try` statement with a `catch` clause. No specimen exercises it yet.',
   ```

   Task 16.5.1 deletes this entry when it adds the specimen. Task 16.1.2 adds the matching name to the `SyntaxTrait` union in
   the same row.
3. In `branch-node-contract.test.ts`, add the valid cases below. If the existing invalid case uses the kind `'try'`, change it
   to a kind no phase adds, `'try-catch'`.

No code reads `BranchNode['kind']` in a `switch` or an exhaustive `if` chain (verified on 2026-10-11). Two files copy `kind`
through unchanged and need no edit: `packages/core/src/brokers/compose/cross-file-predicates/compose-cross-file-predicates-broker.ts`
(line 134) and `packages/core/src/transformers/compose-predicates/compose-predicates-transformer.ts` (line 91) (each line number is the line of `return branchNodeContract.parse({`, where the file rebuilds a branch field by field). Run
`discover({ grep: "kind === '|case '(if|switch|ternary|loop|logical-assign)'" })` once more. If it finds a reader that switches on the kind, do not edit it: it is not in this task's Files table. Stop and
report the file and line in your reply, and the operator adds a task for it.
