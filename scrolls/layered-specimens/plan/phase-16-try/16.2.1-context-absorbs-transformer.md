## Read first

`walk-context-transformer.ts`: `guardPath` and `bindings` already show the two rules (an arm extends what the walk carried down,
and entering a scope starts again), and the transformer omits a key rather than setting it to `undefined`, so a context with
no value is strictly equal to one that never had the key.

## What to implement

1. A new optional input `absorbs?: 'throw' | 'exit'`.
2. Without `scopeSegment` (an arm, a block, a statement): the result carries the context's own `absorbs`, unless the input
   names a value. A given `'exit'` always wins. A given `'throw'` never replaces an existing `'exit'`.
3. With `scopeSegment` (entering a function): the result carries no `absorbs`. A function defined inside a `try` block does not
   run inside the `catch` clause's protection.
4. Omit the key when there is no value.
5. Update the header comment.

## Tests

- `VALID: absorbs 'throw' given => the child context carries 'throw'`
- `VALID: a context that carries 'throw', a child with no input => the child carries 'throw'`
- `VALID: a context that carries 'exit', a child given 'throw' => the child carries 'exit'`
- `VALID: a context that carries 'throw', a child given 'exit' => the child carries 'exit'`
- `VALID: a scopeSegment given => the child carries no absorbs, whatever the parent carried`
- `EMPTY: nothing given and nothing carried => the result has no absorbs key`
- `EDGE: every existing test passes unchanged`
