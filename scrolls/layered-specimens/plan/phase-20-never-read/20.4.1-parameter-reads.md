## What to implement

In `handle-function-layer-transformer.ts`, for each parameter that is a plain identifier, ask the checker whether the symbol has a read inside the function. Use the same question `read-write-tracking-layer-transformer.ts` asks: `nameNode.findReferences()`, then `reference.isDefinition() !== true && !reference.isWriteAccess()`. A parameter with no such reference is unread. Never scan the body, and never read source text.

- A parameter that only a nested function reads counts as read.
- A parameter that is only written (`count = 3`) counts as unread.
- A destructured parameter (`{ a, b }`) records one binding per element name, each with its own line.
- A rest parameter and an optional parameter are checked like any other.
- A name that starts with `_` gets no exemption. There are no per-site waivers.
- A method declared in an `interface`, an abstract method and an overload signature have no body and record nothing.

Return each unread parameter in the handler result's `unreadBindings` (kind `parameter`, `UnreadBinding` from task 20.1.3, with the parameter's own start and end line). The scope the handler opens claims them (task 20.3.2).

## Tests

- `VALID: {const entry = (a, b) => a} => b is unread, a is read`.
- `VALID: {a parameter read only inside a nested arrow} => read`.
- `VALID: {a parameter that is only assigned} => unread`.
- `VALID: {destructured parameter with one unread element} => one binding for that element`.
- `EDGE: {a parameter named _unused} => still unread`.
- `EMPTY: {a function with no parameters} => no bindings`.
- `EMPTY: {an interface method signature} => no bindings`.
- Formatting immunity: a reformatted copy of the source gives the same bindings.
