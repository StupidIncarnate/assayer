## What to implement

The package `exports` or `main` of a fixture repo decides which files are entry points. A fixture repo that a harness writes to a temporary folder and compiles has a `package.json` (or none). From task 20.5.3 a run reports every export that nothing imports as `never-read`, so an integration test that asserts an exact `lints` list breaks when its fixture exports a function nobody imports. This task fixes the fixtures first, so the row of task 20.5.3 lands green.

1. Read the harnesses named below and list the fixture repos they write, with the files each test drives.
2. Give each fixture's `package.json` (the harness writes it; edit the harness, never a test's expectations) an `exports` map that names the entry files the test drives. Example: `"exports": { "./*": "./src/*.ts" }` when every file under `src` is a subject, or `"main": "src/subject.ts"` for one file. If the fixture has no `package.json`, the harness writes a minimal one: `{"name":"fixture","version":"1.0.0","private":true,"exports":{...}}`.
3. Do not weaken an assertion. Do not add a way to silence a lint.

The app harnesses that write fixture sources are `packages/app/test/harnesses/cache-only-source-app.harness.ts`, `empty-surface-app.harness.ts` and `unresolvable-namespace-app.harness.ts`. Give each fixture they write the `package.json` with an `exports` map (step 2). `smoke-cache.harness.ts` compiles the manual smoke repo, which task 20.4.3 covers, and `no-cache-app.harness.ts` writes nothing, so neither needs an edit.
