## What to implement

`handleVariableLayerTransformer` already visits each variable statement and each declaration. For every declaration whose name is a plain identifier, ask the checker the same question task 20.4.1 asks: does the symbol have a reference that is not its definition and not a write? Use `nameNode.findReferences()`. A declaration with none is an unread local.

Record each unread local in the handler result's `unreadBindings` with kind `local`. Its `startLine` and `endLine` are the lines of the whole variable statement (`node.getStartLineNumber()` and `node.getEndLineNumber()`), so task 20.5.1 can drop every branch that sits inside it.

Rules:

- A `const` or `let` that is read only by a nested function is read.
- A `let` that is only assigned is unread.
- An exported `const` (`export const x = …`) is not a local. It is an export, and task 20.5.3 decides its fate. Record nothing for it.
- A destructuring pattern (`const { a, b } = obj`) records one binding per unread element name.
- A name starting with `_` gets no exemption.
- A `for…of` head variable is handled by the loop task, not here. This task records nothing for it.
- Keep the existing value-use and exported-binding behavior unchanged.

The channel is built by tasks 20.2.1 to 20.2.3 and 20.3.1 to 20.3.3. This task adds a producer.

## Tests

- `VALID: {const label = count > 2 ? 'big' : 'small'; never read} => one local binding with the statement's lines`.
- `VALID: {const used = 1; return used} => no binding`.
- `VALID: {let n = 0; n = 1; never read} => unread`.
- `VALID: {export const x = 1} => no binding`.
- `VALID: {const { a, b } = obj; only a read} => one binding, for b`.
- `EDGE: {a local read only by a nested arrow} => read`.
- `EDGE: {a local named _scratch, never read} => still unread`.
- `EMPTY: {a statement with an initializer-less let that is later read} => no binding`.
- All existing value-use and exported-binding tests stay as they are.
