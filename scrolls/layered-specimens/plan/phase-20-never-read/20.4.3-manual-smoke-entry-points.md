## What to implement

1. In `package.json` add the field `"exports": { "./*": "./src/*.ts" }` beside `scripts`. Every `.ts` file under `src/` is then an entry point, so no specimen export is flagged. This keeps the catalogue's existing specimens clean. The new `sad-path/dead-surface/never-read` specimen (task 20.6.1) shows the parameter and local rule. The export rule is proved by the unit tests of tasks 20.2.6 (which exports nothing reaches) and 20.5.3 (export lints reach the run), and by the `dead-export` specimen (tasks 20.7.1 and 20.8.1), whose folder holds its own `package.json`, because this `exports` map reaches every other file of the repo.
2. `mixed-union.ts` is a happy-path specimen about a union descriptor, and its parameter `target` is never read. After task 20.5.1 the file would report a `never-read` lint and stop being clean. Read the parameter without changing the branches or the exits. Change the then arm to `return count + target.toString().length;` and keep the `else` arm `return 0;`. The coverage IDs, the arms and the exits stay the same, because they key on the condition, not on the returned expression. The specimen stays in `happy-path/`: its verdict is clean, which is what the bucket judges.
3. In `mixed-union.test.ts` change nothing unless a recorded call or value use shows in an assertion. Run it. If an assertion fails, fix only the expected value that the new return expression moved, by reading the specimen, never by copying the analyzer's output.
