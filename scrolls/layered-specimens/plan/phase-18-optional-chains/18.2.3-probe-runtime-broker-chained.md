## Read first

The `oc` function in `probe-runtime-create-broker.ts`: a nullish receiver fires `elseId` and returns `undefined`; a present
receiver reads `access(receiver)`, fires `thenId` and returns the value.

## What to implement

1. The runtime keeps one flag in the closure that builds it: `shortCircuited`, `false` at the start and after `reset()`.
2. `oc(thenId, elseId, receiver, access, chained)`:
   - receiver nullish and `chained === true` and `shortCircuited`: the previous link already fired the chain's `else` exit.
     Fire nothing, keep `shortCircuited` true, return `undefined`.
   - receiver nullish otherwise: fire `elseId`, set `shortCircuited` true, return `undefined`.
   - receiver present: read `access(receiver)`, fire `thenId`, set `shortCircuited` false, return the value.
3. A `chained` call whose receiver is nullish because the previous link's member value was nullish (not because it
   short-circuited) fires its own `elseId`: that is the right exit, since the previous link was present.
4. Header comment: the flag and why a chain fires one `else` exit.

## Tests

- `VALID: oc with a present receiver => fires thenId, returns the value (unchanged)`
- `VALID: oc with a nullish receiver => fires elseId (unchanged)`
- `VALID: inner oc short-circuits, then a chained outer oc with the undefined result => only the inner elseId fired`
- `VALID: inner oc present with a nullish member value, then a chained outer oc => the outer elseId fired`
- `VALID: three links, the first short-circuits => exactly one else event`
- `VALID: after reset() => the flag is false`
- `EDGE: chained true on a present receiver => fires thenId as usual`
