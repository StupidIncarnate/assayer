## Words used here

A **link** is a property access, an element access or a call that carries a `?.` token: `.b` in `a?.b`, `[0]` in `a?.[0]`, `()`
in `fn?.()`. Its **receiver** is the expression to the left of the token. In `a?.b?.c` there are two links: `a?.b` with receiver
`a`, and `(a?.b)?.c` with receiver `a?.b`. A step without the token, such as `.c` in `a?.b.c`, is not a link: it adds no branch,
and when an earlier link short-circuits it never runs.

## What to implement

1. **Collect the links.** From the exit expression, recurse into the receiver of each property access, element access and call,
   innermost first, and keep the nodes for which the token is present (`hasQuestionDotToken()`). The recursion stops at any
   other node kind. Read the token from the node, never from text. A `?.()` call whose callee is a property or element access
   (`obj.method?.()`) is not a link: the runtime rewrite would lose `this` (task 18.2.4). A chain with no link is not this case:
   return the `{ conditional: false }` sentinel as today.
2. **One branch per link.** Each link is a `ternary` branch on the non-nullishness of its receiver, read through
   `readNullishLeafLayerTransformer`. Its coverage id keys on the structural projection of the link expression, as the
   single-level case does today (`ternary:` followed by the projection), so the id of a one-link chain does not move. Link `k`
   is met only when links `1 … k-1` took their `then` arm: its `guardPath` is the context's plus those steps.
3. **Arms.** DESIGN.md decision "`?.` arms" applies: `present` and `absent` are internal names only, and the report
   vocabulary table reports them as `then` (present) and `else` (absent). The branch therefore keeps the guard steps `then`
   and `else`, which `exit-causes` and every consumer read (`want = arm !== 'else'`). Say so in the header comment.
4. **Exits.** `n` links give `n + 1` exits of the caller's own kind: one on the `else` arm of each link (the value is
   `undefined`), and one on the `then` arms of all of them (the full access). Each exit's guard path is the context's plus the
   steps that lead to it. Mint ids with `exitCoverageIdTransformer`.
5. **Receivers of any kind.** A link's receiver may be any expression, not only an identifier. Whether the receiver can be
   steered is decided once, in `derive-cases`, so this reader never gates on the receiver's kind (section 5.12).
6. **Probe sites.** Each link has its own `optional` site (task 18.2.4 rewrites it). The site's span starts at the start of the chain
   and ends where the link's **segment** ends: after the link and every non-link step that follows it, before the next link's
   token. The last link's segment ends at the end of the chain. So for `a?.b.c?.d` the site of link 1 spans `a?.b.c` and the
   site of link 2 spans the whole chain. Nested spans overlap, and the instrumenter rewrites inside out. A site's `id` is the
   exit reached when this link and all before it were present: for the last link it is the full-access exit, and for an earlier
   link it is an id minted with `exitCoverageIdTransformer` for that link's `then` arm that no exit carries, so the interpreter
   ignores the event. The site's `elseId` is the link's `else` exit.
7. **Descents.** The innermost receiver runs before any branch is decided, so it descends under the enclosing guards with
   `tail` cleared. A call in an argument of a link, or in an element-access index, descends under the `then` guard of that
   link.
8. Update the header comment: the links, the `n + 1` exits, the arm names, and what a step without the token does.
