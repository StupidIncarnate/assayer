# 18.1.3 An object arranger leaves a level out when a chain wants it missing

- **Phase:** 18, Core: nested optional chains. **Row:** #1, in parallel with 18.1.1 and 18.1.2. No task of the row depends on another task of the row.
- **Depends on:** phase 17 (and tasks 12.1.2 and 12.5.3 for the `undefined` arrange value and the omitted property).
- **Model:** default (the worker's default model; this task is fully specified).
- **Covers:** README "The cause rule" step 2 (each missing `?.` level is an edge value and its own cause); card `param › ?. › ?. › ?. › if` (`src/deep/optional-chain-3`); `packages/core/CLAUDE.md` section 4 "Drive an object-member branch using the stub view".

A condition `order?.customer?.address?.country === 'NZ'` reads three `non-nullish` leaves, on `order.customer`, on
`order.customer.address` and on the final `country`. A route for "`customer` is missing" wants the leaf on `['customer']` false.
`arrangeObjectPropertiesTransformer` builds every property it is given a requirement for, and fills the rest, so it cannot leave
`customer` out today.

## What to implement

For a requirement whose leaf predicate is `non-nullish` and whose path ends at this property (`operandPropertyPath.length === 1`
after the shift):

1. **Wanted false.** The property is left out of `properties` when it is optional (`customer?:`). When it is required but its
   type allows `undefined`, its value is the `undefined` arrange value of task 12.1.2. When its type allows only `null`, its value
   is `null`. When its type allows none of these, the bucket is `unreachable`. A committed correction that holds no nullish
   value contradicts a wanted-false requirement: the bucket is `unreachable`.
2. **Wanted true.** The property is built as for any other requirement: a value the narrowed domain admits, or the seam's fill.
   A nested requirement below it (`['customer', 'address']`) also needs it present, so its recursion runs as today.
3. **Both on one property.** A wanted-false requirement on a property and a nested requirement below it in one bucket cannot both
   hold: the bucket is `unreachable`. (A chain never asks for both, because a later leaf is not met when an earlier one fails.)
4. Update the header comment: the `non-nullish` case and the three outcomes of a wanted-false requirement.
