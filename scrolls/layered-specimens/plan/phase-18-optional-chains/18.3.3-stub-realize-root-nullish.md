## Read first

The whole of `stub-realize-broker.ts`: it drives an entry only when every leaf of every branch is an object-member read of one
of its parameters (`candidateEntries`, near line 80), resolves each type reference to its declared shape, enumerates the input
buckets, and arranges each object parameter per bucket with `objectArrangeTransformer`. Read `isRootNullishLeafGuard` (task
18.2.5) and the missing-level rule of `arrangeObjectPropertiesTransformer` (task 18.1.3).

## What to implement

1. **Candidate rule.** A leaf also qualifies when `isRootNullishLeafGuard({ leaf })` is true for a parameter of the entry. The
   rest of the rule is unchanged.
2. **Type reference.** The chain's member leaves carry `operandTypeRef` `Order` for `order: Order | undefined` (task 18.2.2). The
   root leaf carries none, so take the type name for the whole parameter from the member leaves of the same parameter.
3. **A bucket that wants the root nullish.** When a bucket requires the root leaf false, bind the parameter to the `undefined`
   arrange value of task 12.1.2 (`null` when the union holds `null` and not `undefined`), and do not call
   `objectArrangeTransformer` for it. A bucket that requires the root leaf true arranges the object as today, with the
   requirements below it.
4. **A parameter with no member leaf.** A root leaf on a parameter no member leaf reads has no declared shape to arrange. Such
   an entry is not a candidate.
5. Header comment: the root-nullish bucket and which entries qualify.
