## Read first

`probe-runtime-contract.ts`: `oc: (thenId, elseId, receiver, access) => unknown` observes `a?.b` and fires one exit. In a chain
`a?.b?.c`, when `a` is nullish the inner link fires its `else` exit and returns `undefined`, and the outer link then sees an
`undefined` receiver and would fire its own `else` exit too. Two `else` exits would fire on one run, and the case would not
match its predicted single exit. The outer call must know that its receiver is a link that already reported.

## Contract

```ts
oc: (thenId, elseId, receiver, access, chained?: boolean) => unknown
```

`chained` is `true` when `receiver` is the value of another `oc` call of the same chain. The runtime behaviour is task 18.2.3's.

## What to implement

1. Add the optional fifth parameter to the `oc` type and describe it in the header comment.
2. Update `probe-runtime.stub.ts` so its `oc` accepts the parameter and behaves as the real one will (task 18.2.3 holds the
   rule: a chained call whose receiver is nullish because the previous link short-circuited fires nothing).
3. Update the contract test.
