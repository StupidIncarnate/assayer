## What to implement

Today the leaf names its operand only when it is a bare identifier. A chain link's receiver is often a property access
(`order.customer` in `order?.customer?.address`). Read an object-member receiver the way `read-condition` reads an
object-member operand, so the leaf carries the facts the stub stitch joins on:

- `operandParamName`: the root identifier's name, when the root of the property chain is an identifier;
- `operandPropertyPath`: the `.member` names from the root outward (`['customer']`), from
  `readPropertyPathLayerTransformer`;
- `operandTypeRef`: the type-reference name the root parameter declares, read off the parameter's type node through
  `readTypeRefNameLayerTransformer` (task 18.1.2), so `Order | undefined` gives `Order`;
- `operandType`: the type of the receiver expression itself (the property's type), read through
  `readOperandTypeLayerTransformer` with the node and no `name`, never the root parameter's type.

A receiver whose root is not an identifier (`this.config`, a call result) gets none of the first three fields, so the
derivation admits its branch undriven. A bare identifier is unchanged: its output is byte for byte what it is today. The
predicate stays `{ kind: 'non-nullish' }`.
