## What to implement

The broker resolves a specifier to one file and walks it. A barrel lands on its `index.ts`, which publishes no predicate, so the compose step silently leaves the branch undriven. Follow the re-export to the file that defines the name.

1. Add an optional parameter `importedName?: string` and an optional `seen?: readonly string[]` (absolute paths already visited). Without `importedName` the broker behaves as before; the three callers pass it in tasks 23.2.6 to 23.2.8, the next row, so the tree stays green.
2. After it walks the resolved file, read the file's module edges of kind `reexport` (`walked.moduleEdges`). When the file defines `importedName` itself (an entry or a scope with that exported name), return it as before. Otherwise take the first `reexport` edge that carries the name: a `named` binding whose `name` or `alias` is `importedName` (use the original `name` for the next hop), or a `star` binding. Resolve that edge's specifier with `importSpecifierResolveBroker` under the **barrel's own** owner tsconfig (`tsconfigOwnerBroker({ absPath: <the barrel> })`), then call this broker again with the barrel as `containingFile`, the original name for the next hop, and the barrel's absolute path added to `seen`.
3. A path already in `seen` stops the hop and the broker answers `undefined`, so a cycle leaves the callee unresolved. Recursion only, no loop.
4. The result gains `definedName: string`, the name in the defining file (equal to `importedName` unless a hop renamed it).
