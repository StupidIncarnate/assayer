## What to implement

The seam is the per-file analysis, not the compile result. An undriven admission is built by
`undrivenBranchTransformer` (`packages/core/src/transformers/undriven-branch/undriven-branch-transformer.ts:125-135`,
the generic opaque-operand admission), called by `analyzeFileBroker` at
`packages/core/src/brokers/analyze/file/analyze-file-broker.ts:223`. The compile writes per-file blobs that stay pure
(`packages/core/CLAUDE.md` section 9), and the build error itself is built at `compile-resolve-graph-broker.ts:295`.
So the analysis is told which of the file's import specifiers cannot resolve, and drops what those imports caused.

Add an optional input `unresolvedSpecifiers?: string[]` to `undrivenBranchTransformer`. A branch whose opaque operand
is the result of a call to a name the file imports from one of those specifiers (the call site's raw `import` callee
arm names the specifier and the imported name, section 9) gets no undriven admission: the build error at the call site
replaces it. Every other admission, and every branch when the input is absent, is unchanged. Update the PURPOSE block.
