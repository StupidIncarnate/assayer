## What to implement

The seam is the per-file analysis, not the compile result. An undriven admission is built by
`undrivenBranchTransformer` (`packages/core/src/transformers/undriven-branch/undriven-branch-transformer.ts:125-135`,
the generic opaque-operand admission), called by `analyzeFileBroker` at
`packages/core/src/brokers/analyze/file/analyze-file-broker.ts:223`. The compile writes per-file blobs that stay pure
(`packages/core/CLAUDE.md` section 9), and the build error itself is built at `compile-resolve-graph-broker.ts:295`.
So the analysis is told which of the file's import specifiers cannot resolve, and drops what those imports caused.

Add an optional input `absPath?: string` to `analyzeFileBroker`. When it is given:

1. For each raw import specifier the walked file records (its module edges, section 9), resolve it the way
   `resolve-sibling-callee-broker.ts:37-38` does: `tsconfigOwnerBroker({ absPath })` for the options, then
   `importSpecifierResolveBroker({ specifier, containingFile: absPath, options })`. A specifier that does not resolve,
   one that is not a string literal (a computed `import()`), and a called package that ships no types (the same test
   `compile-resolve-graph-broker.ts` makes for `no-usable-types`) are unresolvable.
2. Pass that list as `unresolvedSpecifiers` to the `undrivenBranchTransformer` call at line 223.
3. Drop every case of an entry whose route reads the result of a call into one of those imports: the build error
   replaces the cases, and `assayer unit` for the file runs none of them.

Without `absPath` the broker behaves as today. Tasks 23.5.1 and 23.5.2 pass it.
