## What to implement

Add one field to each item of `errors` in `compileResultContract`:

```ts
reason: z.enum([
  'cannot-resolve-specifier',
  'dynamic-or-computed-specifier',
  'no-usable-types',
  'stale-stub',
  'contradicting-stub',
  'harness-key',
  'parse-failure',
]).optional(),
```

The field is optional because the result is also read back from a cache written without it. The producers set it in row #2. Add a paragraph to the PURPOSE block naming what each token means, in the present tense:

| Token | The failure |
|---|---|
| `cannot-resolve-specifier` | an import path that names no file or package |
| `dynamic-or-computed-specifier` | a dynamic `import()` whose path is computed at runtime |
| `no-usable-types` | a called dependency that ships no usable type information |
| `stale-stub` | a stub correction that names a type, property or variable that does not exist |
| `contradicting-stub` | a stub correction whose values cannot satisfy a branch guard |
| `harness-key` | a harness that names a wrong entry or parameter, or fails to load |
| `parse-failure` | a source file that fails to parse |

Messages keep their text. The stub keeps its defaults and adds no `reason`.
