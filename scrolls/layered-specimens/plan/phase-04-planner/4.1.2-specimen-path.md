## Contract

`specimenPathTransformer({ focusFolder, kind, segments, axis, pair }): string` returns the folder relative to the
smoke repo package, starting with `src/`.

- `focusFolder`: the focus piece's folder name (`and`, `const`, `ternary`).
- `kind`: one of `alone`, `position`, `placed`, `holds`, `sequence`, `axis`, `shape`.
- `segments`: the slot segments, outermost first (`['for-of-body', 'if-then']`).
- `axis`: for `kind` `axis`, the `AxisValue` (axis name and value). For `kind` `position`, the position name.
- `pair`: for `kind` `shape`, `{ pieces: string[]; relation: 'nested' | 'sequence'; args: string }`.

It replaces `specimen-folder-name-transformer.ts` at task 9.6.x.

## Rules

Read the words from `specimenLayoutStatics.segments` (task 1.1.7) and the axis folder names from `axisStatics`
(task 1.1.2):

| kind | folder | example from DESIGN.md |
|---|---|---|
| `alone` | `src/<focus>/alone` | `src/if/alone` |
| `position` | `src/<focus>/as-<position>` | `src/and/as-condition` |
| `placed` in an exit slot | `src/<focus>/exit/<segment>` | `src/ternary/exit/function-return` |
| `placed` anywhere else | `src/<focus>/in/<segment>/<segment>...`; a piece at level 0 directly in the module is `in/module` | `src/const/in/for-of-body/if-then` |
| `holds` | `src/<focus>/holds/<child folder>` | `src/const/holds/ternary` |
| `sequence` | `src/<focus>/sequence` | `src/ternary/sequence` |
| `axis` | `src/<axis folder>/<focus>/<value>` | `src/type/gt/string` |
| `shape` | `src/shape/<piece>-<piece>[-<piece>]/<nested\|sequence>/<args>` | `src/shape/if-if/nested/two-args` |

The `axis` rule is generic. The file-boundary axis has seven values, so it yields seven folders per focus:
`sibling`, `barrel`, `package`, `builtin`, `unresolvable-specifier`, `unresolvable-dynamic` and
`unresolvable-no-types`. For the focus `call` that is `src/boundary/call/unresolvable-specifier` and its two
siblings. The README and the smoke repo's `tsconfig.json` (task 9.1.5) both rely on the glob
`src/boundary/*/unresolvable-*/**`, so the unresolvable values must keep the `unresolvable-` prefix.

A composition card keeps the folder it declares (task 4.4.1). This transformer is never asked for one.

## Tests

One `VALID:` test per row of the table, each asserting the exact folder with `toBe` and using the DESIGN.md
example. Add three `VALID:` tests for `kind` `axis` with axis `file-boundary` and the three unresolvable values,
asserting `src/boundary/call/unresolvable-specifier`, `src/boundary/call/unresolvable-dynamic` and
`src/boundary/call/unresolvable-no-types`.

`INVALID: {kind: placed, segments: []}` throws the message
`a placed specimen needs at least one slot segment. Pass the host slot it sits in.`
