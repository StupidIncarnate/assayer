## Contract

`valueAxisVariantsTransformer({ pieces, focus, base }): { tree: PieceTree; axis: AxisValue; helpers: PlanHelper[] }[]`

`base` is the focus's alone tree from task 4.2.1. The result has one entry per (declared axis, non-default value).
Only the axes in the focus's `axes` list are crossed (DESIGN.md step 4), so the result is the sum of the axes'
values. `PlanHelper` is the `helpers` element type of `PiecePlan` (task 1.4.2).

## What each axis does to the base tree

| Axis | Value | Change |
|---|---|---|
| `type` | `number`, `boolean`, `string` | the instance with that type argument, when the piece allows it and it is not the piece's `defaultType` (the default is the alone specimen). A combination TypeScript refuses is still planned. The typecheck lists it in `REFUSED.md` (see "Cells TypeScript refuses" below) |
| `type` | `literal-union` | the hole's type becomes `typeListStatics.literalUnion.type`. A literal union never crosses `>` (the `gt` piece's type constraint is `number \| string`) |
| `type` | `enum` | helper `typeListStatics.helpers.enum.text` and the hole typed `Level`. A `switch` label becomes `Level.Low` (card `type/enum`) |
| `type` | `discriminated-union` | helper `typeListStatics.helpers.discriminatedUnion.text` and a `property-read` of `kind` (card `type/discriminated-union`) |
| `type` on `switch` | each base type | `number` gives `case 7` with no-match `8`. `string` gives `case 'xyz'` with no-match `'a'`. A literal union gives one case per member. `boolean` never builds a `switch`: DESIGN.md says "A `switch` on a boolean is an `if`", so that entry is omitted |
| `nullability` | `optional`, `or-undefined`, `or-null`, `or-null-or-undefined` | the param leaf's declaration: `x?: T`, `x: T \| undefined`, `x: T \| null`, `x: T \| null \| undefined` |
| `nullability` | `optional-property` | the param becomes `options: { x?: T }` read through `property-read` |
| `wrapper` | each value | the param becomes the wrapper type and the read goes through the reach-in piece the "Wrapped types" table names: array gives `index-read`, `length-read` and `at-read` (three entries), object gives `property-read`, optional object gives `optional-chain`, nested object gives two `property-read`, `nested-object-3` gives three `property-read` through three named types (`order.customer.address.country`, card `deep/object-3`: objects go to level 3, DESIGN.md "How the matrix is built" step 1), array of objects gives `for-of` then `property-read`, class instance gives `getter-read`, `setter-write` and `method-call-read` (three entries: the table's "a getter, a setter, a method call"; task 3.1.28 declares the last two) |
| `source` | every value below | the axis applies to every leaf of the base, one leaf at a time (DESIGN.md axis table: Source crosses "every leaf"). Each (leaf, source value) pair is one entry: that leaf takes the source, and every other leaf stays a parameter. A base with two leaves, such as `count > limit`, gives two entries per source value |
| `source` | `literal` | the base's body moves into a same-file helper `decide(x)` (a plan helper tree), and the entry becomes `export const entry = (): string => decide(<literal>)` with no parameter. The literal is `layeredMatrixStatics.sourceLiteral` for the leaf's type (the call site `decide(3)` of DESIGN.md's source table, which takes the reader's then arm) |
| `source` | `const` | `const <name> = <known value>;` at the top of the file, read in place of the parameter |
| `source` | `env-load` | `const <name> = <type-info env text>;` at the top of the file |
| `source` | `env-call` | the same read as the first statement of the entry's body |
| `source` | `argv` | `Number(process.argv[2])` at the top of the file (`typeListStatics.number.external`) |
| `source` | `prop` | the param becomes `box: { x: T }` and the leaf reads `box.x` |
| `routes` | `const`, `let`, `destructure`, `ternary-binding`, `same-file-call` | the param reaches the focus through that binding first (cards `route/*`). `let` is crossed here too, with a later reassignment before the read |
| `consumption` | `stored-then-returned`, `passed-to-call`, `compared`, `never-read` | `const x = <focus>; return x;`, `return shout(x)` with a helper `shout`, `return x === 'big'`, or stored and never read (card `consume/never-read`). `let` takes the same four values |

## Cells TypeScript refuses

The planner never filters a cell because TypeScript would reject it. It plans the cell, and the typecheck (task
5.2.2) writes the refused ones to `REFUSED.md`. The only cells left out are the three the type table marks "Not generated": `>` (the `gt` piece) with
`boolean` ("The piece leaves `boolean` out") and with a literal union, and `switch` with `boolean`. These cells are
planned and land in `REFUSED.md`:

- `x.length` (the `length-read` piece) with `type` `number` and with `type` `boolean`.

The tests below assert that these entries exist, so a later edit cannot drop them.

`source` never offers `random` (`layeredMatrixStatics.excluded.sources`).

## Tests

One `VALID:` test per row above on a small hand-built piece set, asserting the changed tree (`toStrictEqual`, pieces
mapped to names) and the helpers. Add:

- `VALID: {focus: gt, axis type}` has `number` and `string` entries and no `boolean` or `literal-union` entry.
- `VALID: {focus: length-read, axis type}` has `number` and `boolean` entries (both land in `REFUSED.md`).
- `VALID: {focus: switch, axis type}` has `number`, `string`, `literal-union` and `enum` entries and no `boolean`.
- `VALID: {focus: gt, source literal}` => entry with no parameter, helper `decide`, call `decide(3)`.
- `VALID: {focus: gt with two parameter leaves, axis source}` => two entries per source value, one per leaf; in each, the other leaf stays a parameter.
- `VALID: {focus: property-read, wrapper nested-object-3}` => three `property-read` nodes over three named types.
- `VALID: {focus: getter-read, wrapper class-instance}` => three entries: `getter-read`, `setter-write`, `method-call-read`.
- `VALID: a focus with two axes` => the sum of their values, never their product.
- `EMPTY: a focus with no axes` => `[]`.
