## Contract

`iterativeShapesTransformer({ pieces, branching }): { tree: PieceTree; focus: string; shape: string; folderPieces: string[] }[]`

`branching` is every piece that declares arms in its default position and crosses the `iteratives` axis: `if`,
`ternary`, `and`, `or`, `nullish`, `optional-chain`, `nullish-assign`, `or-assign`, `and-assign`, `parameter` (when
its default is filled), the destructures, the callbacks with arms, the switches, the loops and `try`.

## What to implement

For every ordered pair of branching pieces (A, B), including A with itself, one entry per shape from
`axisStatics.axes.iteratives.values`:

| Shape | Tree |
|---|---|
| `nested-two-args` | B in a slot of A that declares `under` (the arm B runs under). A reads arg 1, B reads arg 2 |
| `sequence-two-args` | A then B in a row. Each reads its own arg |
| `sequence-one-arg-overlap` | A then B. Both read arg 1 with literals whose true ranges overlap (`> 2`, `> 5`) |
| `sequence-one-arg-exclusive` | A then B. Both read arg 1 with ranges that cannot both hold (`< 2`, `> 5`) |
| `sequence-three-args-one-unused` | A then B, and a third parameter nothing reads |

A slot with no `under` (the `cond` slot of an `if`, a `??` left operand) never holds a nested piece, because the
nested piece would be a leaf of the condition, not a branch of its own. DESIGN.md's example "a ternary inside a
`??`" is the pair (`nullish`, `ternary`) with the ternary in the `fallback` slot, which runs under `right`.

For `if` with itself only, add the three-piece shapes `sequence-three-args` and `nested-three-args`. For every
piece whose declaration lists the shape `two-args-one-check` (the `gt` piece), add that shape: both holes are
parameters (decision "Two arguments feeding one check").

The overlap and exclusive shapes need a comparison in each condition. When A or B has no comparison in its
condition, use the `gt` and `lt` forms with the literals from the DESIGN.md cards (2, 5). A pair whose B tag fits no
`under` slot of A yields no `nested` entry.

The sequence shapes write their arms with the `push` arm kind (task 1.1.1), so the second branch is met after the
first on every route (DESIGN.md's iterative cards use `seen.push`). Nested shapes keep `return`.

`folderPieces` names the pieces for the folder (`['if', 'if']`). Task 4.1.2 turns it into
`src/shape/if-if/nested/two-args`.

## Tests

On a piece set of `if`, `ternary`, `nullish` and `gt`:

- `VALID:` each shape for (`if`, `if`) asserts its tree, matching the cards in DESIGN.md "Iteratives".
- `VALID:` the pair (`if`, `ternary`) yields entries with `folderPieces` `['if', 'ternary']`.
- `VALID:` the pair (`nullish`, `ternary`) nests the ternary in `fallback`.
- `VALID:` `two-args-one-check` for `gt`.
- `EMPTY:` the pair (`ternary`, `nullish`) has no `nested` entry when no `under` slot of `ternary` accepts `nullish`'s tag
  (assert only the cases the hand-built set makes true).
- `EMPTY:` no branching pieces gives `[]`.
