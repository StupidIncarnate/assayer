## Contract

`compositionTreeTransformer({ pieces, card }): PiecePlan`

The plan has `card: true`, `folder` the card's own, `focus` the card's declared focus piece (the first piece under
the root container when the card declares none), `axis` the card's `axis` or the focus's default position, and
`level` as below.

**Level.** Walk the card's tree from the entry's body. A piece directly in the entry's body has level 0. Each piece
node that holds it adds 1. An object or array literal counts as a holder. The module and the entry do not count. A
method body is a slot of its class or object, not a holder. The plan's level is the highest level of any node that
is not a reader and not a leaf. Examples: card `const/in/module` is 0, `const/in/for-of-body/if-then` is 2,
`ternary/in/ternary-else/ternary-else` is 2, `deep/object-3` is 3.

## What to implement

A card with `sameAs` yields no plan: the caller skips it (task 4.5.1), and its check reads the named card's
specimen (task 7.3.1). Otherwise:

1. Walk the card's tree. Resolve each `piece` name to its loaded piece, and each slot name against that piece's
   slots. A leaf becomes a `PieceLeaf`. A snippet leaf becomes a `PieceSnippet`. A node's `rename` stays on the tree
   node.
2. Each card helper becomes a plan helper. A `tree` helper is resolved the same way.
3. Each card `siblings` entry becomes a plan sibling `{ file, tree?, reexport? }`, its `tree` resolved the same
   way. A sibling with `helpers` adds them to the plan helpers of that file.
4. A card's `exportName` is copied to the plan's `exportName` unchanged. A card `stubCorrection: { type, property, values }` is copied to the plan's `stubCorrection` unchanged. Its
   values are explicit, so the prediction engine reads them as known values (task 6.1.6).
5. Apply the card's `axis` with the same transformers the matrix uses. Call `structureAxisVariantsTransformer` for
   `companion-files` and `file-boundary`, which add files. Every other axis is already written into the card's
   tree.

Refuse with errors that name the card's folder and the fix:

- `the composition card 'src/x' names the piece 'iff', which no declaration defines. Known pieces: <sorted names>.`
- `the composition card 'src/x' fills the slot 'thn' of 'if', which has the slots: cond, else, then.`
- `the composition card 'src/x' puts a statement piece 'if' in the expression slot 'cond' of 'ternary'.`
- `the composition card 'src/x' has a snippet holding a <kind>, which is a branch. Write the branch as a piece so the generator predicts it.`
  Parse the snippet with `parse-snippet-expression` or `parse-snippet-statements` and refuse any `if`, conditional,
  `&&`, `||`, `??`, `?.`, `switch`, loop, `try` or initializer default in it.
