## What to implement

Read the responder as task 2.5.1 left it. It accepts `--check`, `--focus`, `--container`, `--depth` and
`--list-pieces`. Add three flags:

- `--count` plans everything with `specimensPlanBroker` and prints `countReportTextTransformer`'s text. It always
  exits 0, because the matrix has no cap.
- `--piece=<a,b>` and `--axis=<a,b>` narrow `--count` (and later `--show` and a write). A malformed value (an empty
  name) is refused with the existing "cannot read the argument" wording.
- An unknown piece or axis throws from the broker with the broker's message (task 4.6.1). The responder's existing
  `catch` turns it into exit 1 with that message.

`--check` still refuses every narrowing flag. Extend its refusal text to name them:
`specimen-generator: --check always compares the full default matrix, so it cannot be combined with --focus, --container, --depth, --piece or --axis. A narrowed run would report every file it skipped as extra. Run --check with no other flag.`

Extend the accepted-flags text by appending `--count`, `--piece=<a,b>` and `--axis=<a,b>` after the flags task 2.5.1
left in it. Update every assertion of that text word for word in the responder test. Task 4.7.2 updates the two integration
tests.

## Tests

- `VALID: {argv: [--count]}` => exit 0 and the output starts with `specimens: `.
- `VALID: {argv: [--count, --piece=if]}` => exit 0.
- `VALID: {argv: [--count, --axis=type]}` => exit 0.
- `INVALID: {argv: [--count, --piece=]}` => the "cannot read the argument" refusal.
- `INVALID: {argv: [--count, --piece=nope]}` => exit 1 with the unknown-piece message.
- `INVALID: {argv: [--count, --axis=nope]}` => exit 1 with the unknown-axis message.
- `INVALID: {argv: [--check, --piece=if]}` => the extended `--check` refusal, word for word.
- `INVALID: {argv: [--check, --axis=type]}` => the same refusal.
