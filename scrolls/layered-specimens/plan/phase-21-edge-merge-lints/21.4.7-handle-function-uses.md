## What to implement

The walk does not descend into every expression: `handle-function` reads a concise arrow body (`(a, b) => a + b`) directly and never passes it to `handle-exit`, and reads its condition or its exit with its own reader, so an operator inside it never reaches `handle-binary` (task 21.4.2). One reader, called from each site (packages/core/CLAUDE.md section 5.12): this task calls `readOperatorUseLayerTransformer` (task 21.2.6) for the expressions of the concise body and returns the uses in the handler result's `operatorUses` (task 21.3.2). Where the expression is a connective (`&&`, `||`, `!`, parentheses), read each operand the condition-tree reader already visits; never scan descendants.

A use in a concise arrow body is returned with the handler result, and the scope the handler opens claims it. Keep every other behavior of the handler unchanged.
