## What to implement

The walk does not descend into every expression: `handle-exit` splits a conditional exit (`return a || b`, `return a ? b : c`) through `read-conditional-exit` before any descent, and reads its condition or its exit with its own reader, so an operator inside it never reaches `handle-binary` (task 21.4.2). One reader, called from each site (packages/core/CLAUDE.md section 5.12): this task calls `readOperatorUseLayerTransformer` (task 21.2.6) for the expressions of a `return` or `throw`, including an `||` that is itself the exit and returns the uses in the handler result's `operatorUses` (task 21.3.2). Where the expression is a connective (`&&`, `||`, `!`, parentheses), read each operand the condition-tree reader already visits; never scan descendants.

A use in an exit expression (`return name || 'anon'`, `return value == 0`) is returned with the handler result.

## Tests
