## What to implement

Add one field to `assayerConfigContract`: `edgeValueMerge`, an object with one key per rule. Every key is `z.enum(['off', 'warn', 'error']).default('warn')`. The whole object defaults to `{}`, so a config that omits it gets six `'warn'` values.

| Key | Rule it governs |
|---|---|
| `truthiness` | `edge-merge-truthiness` |
| `orDefault` | `edge-merge-or-default` |
| `looseEquality` | `edge-merge-loose-equality` |
| `typeofObject` | `edge-merge-typeof-object` |
| `mixedPlus` | `edge-merge-mixed-plus` |
| `globalIsNaN` | `edge-merge-global-isnan` |

Brand the object (`.brand<'AssayerConfigEdgeValueMerge'>()`). Extend the PURPOSE block: each rule has its own toggle, the default is `warn` until the rule has been measured on real repos, the toggle decides the exit code alone, and there is no per-file or per-site setting. The stub keeps parsing `{ version: '1', repoRoot: '.', exclude: [], ...props }`; the nested defaults fill the rest, so the stub needs a change only if the typecheck asks for it.

The key names live in this one contract. Task 21.2.1 maps a rule to its key.

## Tests

- `VALID: {no edgeValueMerge} => six keys, all 'warn'`.
- `VALID: {edgeValueMerge: { truthiness: 'error' }} => truthiness 'error', the other five 'warn'`.
- `VALID: {every key 'off'} => parses`.
- `INVALID: {edgeValueMerge: { truthiness: 'loud' }} => throws`.
- `VALID: {edgeValueMerge: { unknownRule: 'warn' }} => parses, the unknown key is stripped, and the six keys are 'warn'`. `assayerConfigContract` is a plain `z.object`, which strips a key it does not name (the top-level config behaves the same way); build `edgeValueMerge` as a plain `z.object` too, so the two agree.
