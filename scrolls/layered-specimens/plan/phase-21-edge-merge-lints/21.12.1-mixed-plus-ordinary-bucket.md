# 21.12.1 A rule-named value replaces a member's ordinary value in a branchless entry

- **Phase:** 21, the edge-value merge lint family (core). **Row:** #12, in parallel with 21.12.2 and 21.12.3. No task of the row depends on another task of the row.
- **Depends on:** row #11, and phase 12 (task 12.3.3 step 9, the branchless pins).
- **Model:** default (the worker's default model; this task is fully specified).
- **Covers:** README "The cause rule" step 1 ("When an edge-value-merge rule names a value for a member type, that value is the member's ordinary value on the arm it lands on: … `'1'` for `base + extra`"); DESIGN.md "Edge values" card `edge/mixed-plus` (`base '1', extra 2`: returns `'12'`).

## What to implement

Phase 12 gives a branchless entry one pin bucket per value class of each operand (task 12.3.3, step 9). A
`number | string` operand of `base + extra` takes, for its string member, the string's ordinary value. The cause rule
says the mixed-plus rule names that value instead: `'1'` (card `edge/mixed-plus`).

Add an optional input to `inputBucketsTransformer`: `ruleNamed?: { operand: string; value: RepresentativeValue }[]`.
For a branchless entry, an operand listed there takes that value as the ordinary value of the member type the value
belongs to (`'1'` belongs to the string member), in place of the value task 12.3.3 step 2 picks for that member. Every
other operand, and every entry with a branch or a `returnPredicate`, is unchanged. The transformer reads no statics
for this: the caller passes the value (task 21.14.1 reads it from `edgeValueStatics.ruleNamed.mixedPlus`, task
21.12.2). Update the PURPOSE block.

## Tests

- `VALID: {no branches, base: number | string, extra: number, ruleNamed [{ operand: 'base', value: '1' }]} => the string-member pin of base is '1'`
- `VALID: {the same without ruleNamed} => the string member's value of task 12.3.3`
- `EDGE: {ruleNamed on an entry with a branch} => ignored`
