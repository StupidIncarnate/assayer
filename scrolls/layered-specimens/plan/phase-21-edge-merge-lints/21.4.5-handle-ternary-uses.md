## What to implement

The walk does not descend into every expression: `handle-ternary` reads the ternary condition through the condition readers, and reads its condition or its exit with its own reader, so an operator inside it never reaches `handle-binary` (task 21.4.2). One reader, called from each site (packages/core/CLAUDE.md section 5.12): this task calls `readOperatorUseLayerTransformer` (task 21.2.6) for the expressions of the ternary condition and returns the uses in the handler result's `operatorUses` (task 21.3.2). Where the expression is a connective (`&&`, `||`, `!`, parentheses), read each operand the condition-tree reader already visits; never scan descendants.

A use inside the condition of a value-position ternary is returned with the handler result.
