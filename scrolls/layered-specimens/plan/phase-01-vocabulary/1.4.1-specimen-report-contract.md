## Contract

The one shape both the prediction (task 6.4.1) and the observation (task 8.2.1) produce, so a generated test
compares like with like. It replaces `specimenOutcomeContract` when task 9.7.4 deletes it.

```ts
specimenReportContract = z.object({
  branches: z.array(z.object({
    file: z.string().min(1).brand<'SpecimenReportBranchesFile'>(),   // specimen-relative path: 'entry.ts', 'check-limit.ts'
    kind: z.string().min(1).brand<'SpecimenReportBranchesKind'>(),
    line: z.number().int().positive().brand<'SpecimenReportBranchesLine'>(),
    arms: z.array(z.string().min(1).brand<'SpecimenReportBranchesArms'>()),
  }).brand<'SpecimenReportBranches'>()),
  routes: z.array(routeContract),
  fewestRuns: z.number().int().min(0).brand<'SpecimenReportFewestRuns'>(),
  caseFailures: z.array(z.object({ status: z.enum(['failed', 'errored']), message: z.string().brand<'SpecimenReportCaseFailuresMessage'>() }).brand<'SpecimenReportCaseFailures'>()),
  lints: z.array(z.object({
    rule: z.string().min(1).brand<'SpecimenReportLintsRule'>(),
    severity: z.enum(['warn', 'error']),
    file: z.string().min(1).brand<'SpecimenReportLintsFile'>(),        // specimen-relative: 'entry.ts', 'helpers.ts'
    startLine: z.number().int().positive().brand<'SpecimenReportLintsStartLine'>(),
    trace: z.array(traceStep),
  }).brand<'SpecimenReportLints'>()),
  undriven: z.array(z.object({
    file: z.string().min(1).brand<'SpecimenReportUndrivenFile'>(),
    startLine: z.number().int().positive().brand<'SpecimenReportUndrivenStartLine'>(),
  }).brand<'SpecimenReportUndriven'>()),
  darkSpots: z.array(z.object({
    file: z.string().min(1).brand<'SpecimenReportDarkSpotsFile'>(),
    startLine: z.number().int().positive().brand<'SpecimenReportDarkSpotsStartLine'>(),
  }).brand<'SpecimenReportDarkSpots'>()),
  gaps: z.array(z.object({ name: z.string().min(1).brand<'SpecimenReportGapsName'>() }).brand<'SpecimenReportGaps'>()),
  buildErrors: z.array(z.object({
    file: z.string().min(1).brand<'SpecimenReportBuildErrorsFile'>(),
    line: z.number().int().positive().brand<'SpecimenReportBuildErrorsLine'>(),
    reason: z.string().min(1).brand<'SpecimenReportBuildErrorsReason'>(),
    trace: z.array(traceStep),
  }).brand<'SpecimenReportBuildErrors'>()),
  stubValues: z.array(z.object({
    path: z.string().min(1).brand<'SpecimenReportStubValuesPath'>(),
    values: z.array(z.string().min(1).brand<'SpecimenReportStubValuesValues'>()),
  }).brand<'SpecimenReportStubValues'>()),
}).brand<'SpecimenReport'>();
```

`traceStep` is `z.object({ file: z.string().min(1).brand<'SpecimenReportTraceFile'>(), line: z.number().int().positive().brand<'SpecimenReportTraceLine'>() }).brand<'SpecimenReportTraceStep'>()`.

Header comment, in plain words, one line per field:

- `branches`: every listed branch in the specimen's analysed files (file, kind, line, every arm it has), sorted by file (`entry.ts` first, then the other files by path), line, then kind. A card whose branches all sit in `entry.ts` still carries `file: 'entry.ts'` on each. A branch in a sibling file carries the specimen-relative path of the file its syntax sits in: card `known/env-two-files`'s `checkLimit if` is `file: 'check-limit.ts'`, never the file that calls it.
- `routes`: the every-route set, one row per route. A route is its arm set plus the values its run read, so
  two rows can hold equal arms.
- `fewestRuns`: how many cases the fewest-runs set holds. Which cases the tie-break picks is Assayer's own
  enumeration order, so only the count is compared.
- `caseFailures`: run cases that failed or errored. The prediction leaves it empty.
- `lints`: rule, severity, file, line and the path trace from the consumption point to the dead arm. `file` is
  the specimen-relative file the lint lands in: card `consume/dead-export`'s `never-read` lint on `isHuge` is
  `file: 'helpers.ts'`. `severity` is the severity of the rule's default config, because the smoke repo uses the
  default config (DESIGN.md decision "Lint severity").
- `undriven`: admission file and line in each analysed file's own analysis. `darkSpots`: Assayer's own debt,
  file and line, always empty in a prediction.
- `gaps`: `name` is `<entry>.<param>` (the entry and the parameter Assayer could not build a value for).
- `buildErrors`: P1 errors, keyed by a reason token and a trace, never by message text.
- `stubValues`: the stub values Assayer derives, one row per path, sorted by path, each `values` list sorted
  (DESIGN.md decision "Do generated tests compare derived stub values?"). A value is written as TypeScript
  literal text (`3`, `'NZ'`, `[100]`, `{ size: 1 }`), plus two words for a value that is no value: `missing`
  (an optional property left out) and `unset` (an environment variable not set). A row exists for each environment variable a branch reads, each property of an object parameter a branch
  reads (a destructured parameter's and an array element's property included), and each whole parameter whose
  type has an object member (card `edge/typeof-object`: `value`). A scalar parameter, and a scalar element of an
  array parameter (`counts[0]`, the `item` of `items.map`), add no row: Assayer builds those itself, never from the
  stub view. That is why most cards list no stub values. The path rules:
  - an environment variable is its name: `SIZE`;
  - a whole parameter is its name: `value`;
  - a property of a parameter is the parameter, then each property, joined by `.`: `box.count`,
    `order.customer.address.country`;
  - a property of a destructured parameter starts at the property: `count`;
  - an element of an array parameter is the parameter followed by `[]`: "`count` on each item" of
    `items: { count: number }[]` is `items[].count`, and "`order.prices` on each order" of `orders: Order[]` is
    `orders[].prices`.

## Tests

- `VALID: the stub parses to itself`.
- `VALID: a report with one of every channel filled parses`.
- `VALID: a lint with a two-step trace parses`.
- `VALID: a branch with file 'check-limit.ts' parses`.
- `VALID: a lint with file 'helpers.ts' and severity 'error' parses`.
- `INVALID: a lint with severity 'off' throws`.
- `VALID: a stub value row { path: 'items[].count', values: ['2', '3'] } parses`.
- `INVALID: a stub value row with path '' throws`.
- `INVALID: a branch with file '' throws`.
- `EMPTY: a lint with trace [] parses`.
- `INVALID: a lint with startLine 0 throws`.
- `INVALID: a case failure with status 'passed' throws`.
- `INVALID: a build error without reason throws`.

The stub's default is every list empty (`stubValues` included) and `fewestRuns: 0`.
