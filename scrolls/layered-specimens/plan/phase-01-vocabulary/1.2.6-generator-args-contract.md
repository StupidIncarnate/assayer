## Contract

Keep `mode`, `focus`, `container` and `depth`: the old pipeline reads them until task 9.7.8. Widen `mode` to
`z.enum(['write', 'check', 'count', 'list-pieces', 'show'])`. Add these optional fields:

- `piece: z.array(z.string().min(1).brand<'GeneratorArgsPiece'>())`, the pieces `--piece=a,b` names;
- `axis: z.array(z.string().min(1).brand<'GeneratorArgsAxis'>())`, the axes `--axis=a,b` names;
- `show: z.array(z.string().min(1).brand<'GeneratorArgsShow'>())`, the specimen folders `--show=a,b` names;
- `fresh: z.boolean()`, true when `--fresh` ignores the generation cache.

Callers: `generate-run-responder.ts` builds the object with `generatorArgsContract.parse` and
`specimens-generate-broker.ts` takes the `GeneratorArgs` type. Both keep working, because every new field is
optional and the old modes stay valid. Tasks 2.5.1, 4.7.1, 6.5.1 and 9.3.1 fill the new fields.

## Tests

Keep every existing test. Add:

- `VALID: {mode: <each new mode>}` for `count`, `list-pieces`, `show` (`it.each`).
- `VALID: {mode: 'count', piece: ['if'], axis: ['type']} => both lists kept`.
- `VALID: {mode: 'show', show: ['src/if/alone']} => list kept`.
- `VALID: {mode: 'write', fresh: true} => fresh kept`.
- `INVALID: {mode: 'show', show: ['']} => throws`.
- `INVALID: {mode: 'count', piece: ['']} => throws`.

The stub keeps its default and accepts overrides for the new fields.
