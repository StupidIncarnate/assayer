## What to implement

`reportVocabularyStatics`, `as const`, with two groups, `forms` and `lintSeverity`. Each key is a design form. Each value holds:

- `kind`: the branch kind Assayer reports (`BranchNode.kind` in `packages/shared`, or the pseudo kinds
  `callback` and `return-comparison`, which have no `BranchNode`).
- `arms`: an object from the design arm name to the arm label Assayer reports.
- `listed`: `true` when the form shows in a card's "Expected branches" line, `false` when it shows only in
  routes (a returned comparison, card `arrow › ===`).

Copy this table row for row from README "The report vocabulary".

| Form | kind | arms (design → reported) | listed |
|---|---|---|---|
| `if` | `if` | `then`→`then`, `else`→`else` | true |
| `ternary` | `ternary` | `then`→`then`, `else`→`else` | true |
| `and` | `ternary` | `evaluates-right`→`then`, `stops-at-left`→`else` | true |

Comments to write:

- above `and` and `or`: why their `then` and `else` swap. Assayer splits a short-circuit chain on the
  truthiness of its left operand, so for `&&` a truthy left goes on to the right operand, and for `||` a
  truthy left stops there;
- above `switch`: the labels come from each case's literal value, and the `case:<a>|<b>` form joins labels
  that share one arm (card `arrow › switch that falls through`). A case on an enum member is labelled with the
  member's value, so card `type/enum`'s `case Level.Low` is `case:0`;
- above `do-while-loop`: the body always runs once, so there is no `skipped` arm (decision "`do…while` arms");
- above `promise-callback`: a `.then` or `.catch` callback is listed only when its receiver can reject. A
  receiver that never rejects (`Promise.resolve(x)`) leaves the callback with one arm, which is no branch, so
  nothing is listed (README "The report vocabulary"). Task 6.1.4 applies this rule;
- above `optional-chain`: `present` and `absent` are names the generator uses inside its own declarations only. A
  report always says `then` and `else` (DESIGN.md decision "`?.` arms");
- above `listed`: what `true` and `false` mean.

`lintSeverity` maps each lint rule to the severity of its default config (DESIGN.md decision "Lint severity"; the
smoke repo uses the default config):

| Rule | Severity | The default it comes from |
|---|---|---|
| `unreachable-exit` | `error` | `deadSurface` defaults to `error` |
| `dead-surface` | `error` | `deadSurface` |
| `never-read` | `error` | `deadSurface` (phase 20) |
| `edge-merge-truthiness`, `edge-merge-or-default`, `edge-merge-loose-equality`, `edge-merge-typeof-object`, `edge-merge-mixed-plus`, `edge-merge-global-isnan` | `warn` | each rule's own toggle, default `warn` (phase 21) |

Above it, write that the prediction takes a lint's severity from here, and the observation (task 8.2.1) takes it
from core's config defaults, so a generated test catches a default that drifts from DESIGN.md.
