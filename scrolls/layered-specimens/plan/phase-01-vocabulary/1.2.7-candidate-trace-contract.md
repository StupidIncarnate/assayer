## Contract

A candidate trace is what one run of one specimen with one candidate input recorded (task 6.3.1).

```ts
z.object({
  input: z.string().brand<'CandidateTraceInput'>(),                  // the input in display form, for messages only
  arms: z.array(z.string().min(1).brand<'CandidateTraceArms'>()),    // probe ids of the arms reached, sorted, unique
  causes: z.array(z.string().min(1).brand<'CandidateTraceCauses'>()),// '<leaf probe id>=<cause class>', sorted, unique
  reads: z.array(z.string().min(1).brand<'CandidateTraceReads'>()),  // '<input>=<display value>' pairs the run read, sorted
  cause: z.string().min(1).brand<'CandidateTraceCause'>(),           // the cause class the candidate was built for
  settable: z.boolean(),                                             // false when an input a test cannot set decided it
  outcome: z.enum(['returned', 'threw', 'resolved', 'rejected', 'capped']),
}).brand<'CandidateTrace'>()
```

The header comment says: `reads` lists the inputs the run read. A route is identified by its arm set plus
the values it read (README "The cause rule" step 4). `cause` is one of the cause class names in
`edgeValueStatics.causes` (task 1.1.3). `capped` means the run hit a deterministic cap (task 6.1.3): a pass
count, a generator step count or a call depth. No outcome is a timeout.

## Tests

- `VALID: the stub parses to itself`.
- `VALID: {outcome: 'capped'} parses`.
- `INVALID: {outcome: 'timed-out'} throws`.
- `INVALID: {cause: ''} throws`.
- `EMPTY: {arms: [], causes: [], reads: []} parses`: a run that reached nothing.

The stub returns `{ input: 'count=3', arms: [], causes: [], reads: ['count=3'], cause: 'ordinary', settable: true, outcome: 'returned' }`.
