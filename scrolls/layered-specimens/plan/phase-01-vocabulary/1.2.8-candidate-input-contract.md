# 1.2.8 Candidate input contract

- **Phase:** 1, Vocabulary. **Row:** #2, in parallel with 1.2.1, 1.2.2, 1.2.3, 1.2.4, 1.2.5, 1.2.6 and 1.2.7. No task of the row depends on another task of the row.
- **Depends on:** 1.1.3 (cause classes).
- **Model:** default (the worker's default model; this task is fully specified).
- **Covers:** README "The cause rule" (one candidate input per ordinary or edge value); tasks 6.2.1 (produces it), 6.2.3 and 6.3.1 (read it).

## What to implement

Declare the type every prediction task shares, so no task hides it inside its own file:

```ts
export type CandidateInput = {
  args: unknown[];                       // the entry's arguments, in parameter order
  env: Record<string, string | null>;    // null removes the key
  argv: string[];                        // the arguments after the script name; [] in a test worker
  calls: number;                         // how many times the entry is called in a row
  cause: string;                         // 'ordinary', or the cause class of the edge value (task 1.1.3)
  display: string;                       // readable form, for messages: 'count 3, ready true'
  displays: Record<string, string>;      // input name -> display of its value: 'count' -> '3', 'limit' -> 'left out'
  settable: boolean;                     // false when a value a test cannot set decided it
  edgeOf?: { input: string; base: number };  // set on an edge candidate; base is the index of its ordinary candidate
};
```

It is a types-only contract (worker brief rule 7): `args` holds run values such as `NaN` and `undefined`, which a JSON
schema cannot carry, so it has no Zod schema, no test and no stub. Write the meaning of each field in the header.
