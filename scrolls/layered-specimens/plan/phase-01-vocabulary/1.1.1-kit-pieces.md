## What to implement

Keep every existing export of `kit.ts`. The old pipeline still reads `container`, `syntax` and `shim`
until task 9.7.6 removes the first two.

Change two existing types:

- `Arm` becomes `'return' | 'log' | 'yield' | 'push' | 'throw'`. The new members mean:
  - `push` writes `seen.push('<arm>');` into a `const seen: string[] = []` the container returns. It neither
    returns nor throws, so a second branch after it is still met.
  - `throw` writes `throw new Error('<arm>');`. It ends the scope by throwing (card `return/throw`).
- `Reach` gains `'construct-then-assign'`, for a class setter a test reaches by assigning the property
  (card `class instance › setter › ternary`).

Add these declarations, each with a one-line comment saying what it means:

```ts
export type Tag = 'statement' | 'expression' | 'parameter-list' | 'loop-head' | 'root';
export type Position = 'statement' | 'condition' | 'exit' | 'value';
export type AxisName =
  | 'position' | 'level' | 'iteratives' | 'routes' | 'type' | 'nullability' | 'wrapper' | 'array-size'
  | 'exit-kind' | 'file-boundary' | 'consumption' | 'compiler-options' | 'source' | 'companion-files'
  | 'shared-state';
export type SourceKind = 'param' | 'literal' | 'const' | 'env-load' | 'env-call' | 'argv' | 'random' | 'prop';
// How one use of a piece in a condition splits into separate causes on the every-route list.
// presence is an `in` check: the property is present, or missing.
export type LeafCause = 'outcome' | 'truthiness' | 'nullish' | 'member' | 'presence';
// A slot accepts one tag or several, and sets the position of what fills it.
// 'inherit' means the piece's own position, as a ternary's then and else do.
// `arm` says what an arm becomes inside a statement slot of a container.
// `under` names the arm of the piece whose code runs this slot (a ternary's `then` slot runs under `then`).
// A slot that runs under no arm declares no `under`. The planner nests a piece only in a slot that declares `under`.
export type PieceSlot = {
  accepts: Tag | readonly Tag[];
  position: Position | 'inherit';
  segment?: string;
  arm?: Arm;
  under?: string;
};
// One arm a piece has in one position. `cause` says how routes through this arm split into cases.
export type PieceArm = { name: string; cause?: LeafCause };
// Per position: the arms, or 'leaves' when the piece adds no branch and its operands become leaves.
export type PieceArms = { [P in Position]?: readonly PieceArm[] | 'leaves' };
export declare const piece: (p: {
  description: string;
  folder: string;
  tag: Tag | readonly Tag[];
  slots: Record<string, PieceSlot>;
  arms: PieceArms;
  leaf?: LeafCause;
  axes: readonly AxisName[];
  levelCap?: 2 | 3;
  // The type argument every specimen that does not vary the type axis uses.
  defaultType?: string;
  reach?: Reach;
  code: (...holes: any[]) => unknown;
  // Statements written once at the top of the specimen file, before the entry: a same-file callee, a
  // class, an enum or a type alias the piece's code refers to.
  helpers?: () => void;
  anchors?: Record<string, unknown>;
}) => typeof p;

// A leaf is a value a hole reads, or a snippet: an expression or statement no piece describes
// (`new Counter(count)`, `counter.count = count;`). A snippet never holds a branch; task 4.4.1 refuses one that does.
export type CompositionLeaf =
  | { source: SourceKind | 'binding'; name: string; type: string; value?: unknown }
  | { snippet: string; form: 'expression' | 'statement' };
export type CompositionNode = {
  piece: string;
  type?: string;
  // Renames identifiers the piece's code writes, such as { isBig: 'checkLow' }, so a card can name its values.
  rename?: Record<string, string>;
  slots?: Record<string, CompositionNode | CompositionLeaf | readonly (CompositionNode | CompositionLeaf)[]>;
};
// A named function built from pieces, a type alias, or an enum, written at the top of a file.
export type CompositionHelper =
  | { name: string; tree: CompositionNode }
  | { name: string; typeAlias: string }
  | { name: string; enumMembers: readonly string[] };
// Another file of the same specimen. `tree` is an exported function built from pieces, `helpers` are its
// top-level statements, `reexport` makes the file a barrel that re-exports `name` from the file `from`.
export type CompositionSibling = {
  file: string;
  tree?: CompositionNode;
  helpers?: readonly CompositionHelper[];
  reexport?: { name: string; from: string };
};
export type CompositionCard = {
  folder: string;
  description: string;
  tree?: CompositionNode;
  axis?: { axis: AxisName; value: string };
  // Two DESIGN.md cards show the same code: the second names the first, and no second specimen is written.
  sameAs?: string;
  helpers?: readonly CompositionHelper[];
  // Other files of the card (cards `boundary/sibling`, `consume/dead-export`, `known/env-two-files`).
  siblings?: readonly CompositionSibling[];
  // A human's correction of the values Assayer derives for one property (card `known/stub-correction`).
  stubCorrection?: { type: string; property: string; values: readonly unknown[] };
  // The name the card's entry exports when it is not `entry` (or the class `Entry`): `'Counter'` for card
  // `state/this-field`, `'result'` for `known/env-two-files`. `null` when the card exports nothing (`export {};`,
  // card `const/in/module`). A card keeps its own export name.
  exportName?: string | null;
};
export declare const compositions: (c: { description: string; cards: readonly CompositionCard[] }) => typeof c;
```

Write the meaning of each of these in the file's header comment:

- A **piece** is one declaration that can be placed in a slot of another piece. Its `tag` says which slots
  accept it. Each entry of `slots` names one place inside the piece's `code` where another piece goes. An
  expression slot is a parameter of `code`, exactly like a hole of a `syntax` today. A statement slot is a
  `$stmts('name')` marker. A parameter-list slot is `$params`. A container's markers (`$Entry`, `$R`,
  `$exportDefault`) keep their meaning.
- `arms` is declared per position, because Assayer reads the same syntax three ways (DESIGN.md "The pieces").
- `under` ties a slot to the arm that runs it. A piece with arms declares `under` on every slot its code
  runs only under one arm.
- `folder` is the piece's folder name in the output layout (`nullish` for `??`; task 1.1.7 lists the segments).
- `helpers` holds statements the generator writes once at the top of the file, such as the callee of a
  `call` piece. They are never a slot.
- `defaultType` is the piece's own default type (DESIGN.md "Type variation": `boolean` for a bare `if` or
  ternary, `number` for `>`, `string | undefined` for `??`). The type axis varies away from it.
- `levelCap` is 3 only for object and array literals (DESIGN.md "How the matrix is built", step 1).
- A **composition card** is one hand-declared specimen from DESIGN.md, written as a tree of piece names and
  leaves. Group 7.2 declares one card per DESIGN.md card.

In `declarations/tsconfig.json`, add `"pieces/**/*.ts"` and `"compositions/**/*.ts"` to `include`.
