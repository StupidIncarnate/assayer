`object-destructure` crosses `compiler-options` because the optional property it reads meets
`exactOptionalPropertyTypes` (DESIGN.md "Compiler options": "reach-in by index, optional properties"). Both
pieces bind a name (`count`, `first`) that the plainest reader can read, so `binds` lists it. Only `undefined`
triggers the default (decision "Is a default a branch?").


## Rules for every declaration in this phase

- Write each file with the kit's `piece` (task 1.1.1). One file, one export, named by
  `declarationExportNameTransformer` (`for-of.piece.ts` exports `forOfPiece`). A generic piece (one type
  parameter) declares `defaultType`, the type its DESIGN.md card uses; the loader refuses a generic piece
  without one (task 2.2.1).
- Every value in the table comes from DESIGN.md "The pieces" table, the row named in "Covers". Never add an
  arm, an axis or a slot the row does not name. Where this task names something the row does not, it says
  which DESIGN.md card or decision it comes from.
- `code` is a template, never run. Write it as the plainest real TypeScript that shows the piece, with holes
  as `code` parameters, statement slots as `$stmts('<slot>')`, and arm positions as `$arm('<arm>')`.
- Name values the way DESIGN.md's cards name them (`count`, `flag`, `ready`, `mode`, `name`, `items`, `limit`,
  `box`, `label`), so a composition card renders the card's code.
- A piece that never branches declares no arms. Task 4.1.1 adds the reader after it.
- Every piece that declares arms (an array in any position, not `'leaves'`) crosses the `iteratives` axis. The
  loader refuses a piece that does not (task 2.1.1).
- Every slot that runs under an arm declares `under: '<arm name>'`, the name of an arm the piece declares. A
  slot that runs whatever arm is taken (a condition, a receiver, a `finally` block) declares none. The loader
  refuses an `under` that names no declared arm, and one that disagrees with the `$arm` the code puts before
  its `$stmts` (task 2.2.1). The planner nests a piece inside another only in a slot that declares `under`
  (task 4.3.4).
- Declarations are not linted and have no tests. The generator typechecks them on every load.
