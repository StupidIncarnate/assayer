## What to implement

In `callArgContract` (a discriminated union on `kind`):

1. The `literal` variant gains the optional field `line` (the start line of the argument), branded like its neighbours.
2. A new variant `{ kind: 'literal-set', values: RepresentativeValue[] (at least two), line }`: an argument that is an identifier bound to a same-file `const` whose initializer is a ternary of literals (`applyLimit(limit)` with `const limit = process.env.STRICT ? 5 : 10`). It is the set twin of `literal`.

Both are new information, so no existing argument changes. Update the doc comment above the union: say what `literal-set` is, in the present tense. The readers that match specific kinds (`call-arg-bindings-transformer.ts:34` matches `param-ref`; `follow-calls-transformer.ts:246` matches `param-ref` and one more kind) keep their meaning: an argument kind they do not name is not a pass-through. Task 24.3.4 produces the new shape and task 24.5.1 consumes it.
