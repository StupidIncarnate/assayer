## Contract

```ts
unreachableLintTransformer({
  name, displayName, relPath, unreachableExits,
}: {
  name: string;
  displayName: string;
  relPath?: string;                     // the file being analyzed; the file of every trace step that carries no file
  unreachableExits: {
    line: number;                       // the dead exit or arm
    armEndLine?: number;
    guardLines: number[];
    welded?: {
      line: number;                     // the branch that is welded
      operand?: string;
      value?: RepresentativeValue;
      length?: number;
      file?: string;                    // the file that holds the branch and the dead arm, when it is not relPath
      known?: { values: RepresentativeValue[]; from: 'literal' | 'type'; origin: { line: number }; hops: { file?: string; line: number }[] };
    };
  }[];
}): LintEntry[]
```

## What to implement

A lint with no `welded.known`, or built without `relPath`, is exactly what the transformer builds today, with no `trace` key. A guard contradiction stays at the dead exit's line.

A lint whose exit has `welded.known`, built with `relPath`, lands at the consumption point:

- `startLine` and `endLine` are `known.origin.line`;
- `trace` is `[{ file: relPath, line: origin.line }, ...hops (file defaults to relPath), { file: welded.file ?? relPath, line: welded.line }]`;
- `name` and `displayName` stay the function that holds the dead arm, as the caller passes them;
- the message is, word for word:

  `` `<displayName>` can never <target>: <subject> is <known>, so the branch on line <branchLine> always takes its other arm and this one is dead. <origin sentence> Either a comparison is wrong, or this arm should be deleted. ``

  with `<target>` as today (`reach the exit on line N`, `run the arm on line N`, `run the arm on lines N to M`) plus ` of <welded.file>` when `welded.file` is set, `<subject>` as today (`` `operand` `` or `the value it branches on`), `<branchLine>` = `welded.line`, and

  | `known` | `<known>` | `<origin sentence>` |
  |---|---|---|
  | `from: 'literal'`, one value | ``welded to `5` `` (the value through `JSON.stringify`) | `The known value enters on line <origin>.` |
  | `from: 'literal'`, several values | ``welded to one of `5`, `10` `` | `The known value enters on line <origin>.` |
  | `from: 'type'` | ``limited by its declared type to `"a"`, `"b"` `` | `The type is declared on line <origin>.` |

  A lint with `welded` but no `known` keeps today's welded message.

Example for card `known/call-site-literal`, where `fromCall` holds `measure(5)` on line 10 and `label`'s dead exit is on line 5: `` `label` can never reach the exit on line 5: `size` is welded to `5`, so the branch on line 2 always takes its other arm and this one is dead. The known value enters on line 10. Either a comparison is wrong, or this arm should be deleted. `` with `startLine` 10, `endLine` 10 and `trace` `[{ file, line: 10 }, { file, line: 8 }, { file, line: 2 }]`.

For a type (DESIGN.md decision "Where a type known value is reported"): `origin.line` is the parameter's declaration line.
