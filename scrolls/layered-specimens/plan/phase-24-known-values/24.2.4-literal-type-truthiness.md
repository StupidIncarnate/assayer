## Read first

`packages/core/src/transformers/type-to-range/truthiness-range-layer-transformer.ts`: for a union with no falsy point it falls back to the representative reading, so the falsy arm of `if (mode)` on `'a' | 'b'` gets `{ members: [''] }`. That domain is not empty, and `cause-arrange` then builds `mode = ''`, which the type refuses.

## What to implement

When the operand's type is made only of literals, the type is a known set (DESIGN.md decision "Does a type count as a known value?"; a type with any non-literal member, such as `number` or `string`, is not known). A `type` of kind `literal`, or a `union` whose every member is a `literal`, answers from its members:

- `truthy`: `satisfying` is `{ members: <the truthy literal members> }` and `violating` is `{ members: <the falsy literal members> }`;
- `falsy`: the two swap.

A falsy literal is `0`, `''`, `false`, `null` or `undefined`. Members are read in the type's member order and de-duplicated. For `'a' | 'b'`, the falsy side is `{ members: [] }`: an enumeration with no member. A union that mixes a literal with a non-literal member keeps today's behavior.

A `type` of kind `array` or `object` (not inside a union with `undefined` or `null`) is never falsy, because every
array and every object is truthy. It answers:

- `truthy`: `satisfying` is `{}` (any value) and `violating` is `{ members: [] }`;
- `falsy`: the two swap.

So the falsy arm of `if (items)` on `items: number[]` has an empty domain, and the unreachable-exit lint reports it
at the parameter's line (the generator predicts the same, task 6.1.6). A union of an object or array with
`undefined` or `null` keeps today's behavior: `undefined` and `null` reach the falsy arm.

Update the PURPOSE block. The proof of a dead arm stays with `isDomainEmptyGuard` (task 24.2.5): an empty `members` list is an empty domain.
