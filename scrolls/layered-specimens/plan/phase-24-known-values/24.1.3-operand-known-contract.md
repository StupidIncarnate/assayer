## What to implement

Add to `conditionLeafContract` the optional field `operandKnown`, beside `operandConstValue` and `operandConstLength`:

```ts
operandKnown: z.object({
  values: z.array(representativeValueContract).min(1),
  from: z.enum(['literal', 'type']),
  origin: z.object({ line: z.number().int().positive().brand<'ConditionLeafOperandKnownOriginLine'>() }).brand<'ConditionLeafOperandKnownOrigin'>(),
  hops: z.array(z.object({
    file: z.string().min(1).brand<'ConditionLeafOperandKnownHopFile'>().optional(),
    line: z.number().int().positive().brand<'ConditionLeafOperandKnownHopLine'>(),
  }).brand<'ConditionLeafOperandKnownHop'>()),
}).brand<'ConditionLeafOperandKnown'>().optional(),
```

Extend the PURPOSE block: a known set is the values a leaf's operand can take because of a literal in code, a literal at a call site, or its declared literal type; `origin` is the consumption point and `hops` the calls it crossed. The stub gets no `operandKnown`; a test builds one by override. The field is absent when nothing is known, so no existing leaf changes.

## The known-value record

Tasks of this phase share one record. It is a field of a condition leaf, `operandKnown` (contract: task 24.1.3):

```ts
operandKnown: {
  values: RepresentativeValue[];          // one or more; a ternary of literals gives two
  from: 'literal' | 'type';               // a literal in code or at a call site, or the operand's declared literal type
  origin: { line: number };               // the consumption point, a line in the file being analyzed
  hops: { file?: string; line: number }[];// each call or import step after the origin; `file` is absent for the file being analyzed
}
```

`operandConstValue` stays for the case of exactly one value, so the readers that exist today keep working. Every reader that takes a set reads `operandKnown`. The field is optional and absent when no known value reaches the leaf.
