## Contract

```ts
export const stubConsumersTransformer = ({
  blobs,
  guards,
}: {
  blobs: readonly CompiledFileBlob[];
  guards: readonly PropertyGuard[];
}): { typeKey: string; relPath: string; line: number; hops: { file: string; line: number }[] }[]
```

## What to implement

For each guard, find the entries that pass a value of the guarded type to it, and report where the value enters. A value of type `T` enters at an exported entry whose parameter is declared with `T` (the entry parameter, `line` = the entry's declaration line, which is the parameter's line while the signature is on one line, DESIGN.md decision "Where a type known value is reported"'s rule). The hops are the calls from that entry down to the guard's reader, in call order: each same-file call is `{ file: <the file>, line: <the call's line> }`, each import hop is the call's line in the importing file followed by the next file's steps. Use the call sites the blobs hold (`calls`, with `position`) and the resolved edges the blob's module graph holds; follow a pass-through of the parameter only (a `param-ref` argument). Keep a seen-set of `(file, function)` pairs so a cycle stops. Recursion only, no loop.

`typeKey` is `<definitionRelPath>#<TypeName>`, the key the overlay uses. Sort the result by `typeKey`, then `relPath`, then `line`, and drop exact duplicates. Where no entry takes the type, report nothing for it.

## Tests

- `VALID: {card known/stub-correction: Job, entry(job) -> triage(job) -> rank(job)} => one consumer at entry's parameter line, hops [line of triage(job), line of rank(job)], guard line last}`.
- `VALID: {an entry that passes the value across an import} => a hop carries the importing file and line, then the next file's call line`.
- `VALID: {two entries take the type} => two consumers, sorted`.
- `EDGE: {two functions that call each other} => stops at the seen-set`.
- `EMPTY: {no entry takes the type} => []`.
- `EMPTY: {no guards} => []`.
