## The known-value record

Tasks of this phase share one record. It is a field of a condition leaf, `operandKnown` (contract: task 24.1.3):

```ts
operandKnown: {
  values: RepresentativeValue[];          // one or more; a ternary of literals gives two
  from: 'literal' | 'type';               // a literal in code or at a call site, or the operand's declared literal type
  origin: { line: number };               // the consumption point, a line in the file being analyzed
  hops: { file?: string; line: number }[];// each call or import step after the origin; `file` is absent for the file being analyzed
}
```

`operandConstValue` stays for the case of exactly one value, so the readers that exist today keep working. Every reader that takes a set reads `operandKnown`. The field is optional and absent when no known value reaches the leaf.

## What to implement

1. A leaf with `operandKnown` seeds its domain with `{ members: operandKnown.values }`, in that order. A leaf with only `operandConstValue` seeds as today. A leaf with both uses `operandKnown`.
2. A leaf whose operand type is a literal or a union made only of literals (the type is a known set, README "Known values and the consumption point") and that carries no `operandKnown` of its own seeds its domain with `{ members: <the literal members> }`, in the type's member order. Such a leaf gets an implicit known record for the lint: `from: 'type'`, `values` the members, `origin` the declaration line of the operand's parameter (DESIGN.md decision "Where a type known value is reported": the entry's declaration line, `EntrySignature.line`, which is the parameter's line while the signature is on one line), `hops: []`.
3. `.length` of a literal union needs no extra seed: the leaf's operand is the union itself with a `length-*` predicate, and an enumeration of strings is filtered by the length axis (task 24.2.5). `if (mode.length)` on `'a' | 'b'` has a falsy arm whose domain is empty, because every member has length 1.
4. When an arm's domain is empty, the returned `unreachable` entry carries the leaf's known-value record: `known = { values, from, origin, hops }` beside what it carries today. Task 24.4.2 forwards it into `welded.known`.
5. A leaf with neither a known set nor a literal type is unchanged: nothing is flagged, and every arm is assumed reachable.
