## Read first

`packages/core/src/guards/is-domain-empty/is-domain-empty-guard.ts`. It errs toward "not empty" on purpose: it is what a lint is raised on, and a false positive tells a reader to delete correct code. It already counts an enumeration with no surviving member as empty (`survivors.length === 0` when `members` is defined).

## What to implement

Task 24.2.4 produces `{ members: [] }` for the falsy arm of a truthiness check on a literal union. Task 24.3.2 seeds a leaf's domain from the type's literal members, so a length or equality arm intersects to an enumeration whose members are all ruled out. This task makes the guard's answer exact for both, and proves it:

1. `members: []` is empty on its own, with every other axis open.
2. A `members` list whose every member is ruled out by `excluded`, by the value bounds, by the length bounds (`lengthMin`, `lengthMax`, exclusive or not) or by `includes` / `notIncludes` is empty.
3. A `members` list with at least one survivor is not empty.
4. `members` undefined stays "not empty": the domain says nothing, so nothing is proven.
5. For an enumeration of strings, the length axis is read over the integers: members `['a', 'b']` with `lengthMax: 0` is empty.

If the guard already answers every row, change only the tests and the PURPOSE block (state the enumeration rule in the present tense). Change the guard's code only where a row fails.

## Tests

- `VALID: {members []} => true`.
- `VALID: {members ['a','b'], lengthMax 0} => true` (card shape `if (mode.length)` falsy arm).
- `VALID: {members ['a','b'], excluded ['a','b']} => true`.
- `VALID: {members [''], includes ['a']}` is not a valid domain shape; use `members ['b'], notIncludes ['b']` => true.
- `VALID: {members ['a','b'], excluded ['a']} => false`.
- `EMPTY: {domain undefined} => false`.
- `EDGE: {no members, only a length axis that leaves a length} => false`.
- The existing tests stay.
