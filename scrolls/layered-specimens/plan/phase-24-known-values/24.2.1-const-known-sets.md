## The known-value record

Tasks of this phase share one record. It is a field of a condition leaf, `operandKnown` (contract: task 24.1.3):

```ts
operandKnown: {
  values: RepresentativeValue[];          // one or more; a ternary of literals gives two
  from: 'literal' | 'type';               // a literal in code or at a call site, or the operand's declared literal type
  origin: { line: number };               // the consumption point, a line in the file being analyzed
  hops: { file?: string; line: number }[];// each call or import step after the origin; `file` is absent for the file being analyzed
}
```

`operandConstValue` stays for the case of exactly one value, so the readers that exist today keep working. Every reader that takes a set reads `operandKnown`. The field is optional and absent when no known value reaches the leaf.

## What to implement

`readConstOperandLayerTransformer({ node })` reads the operand identifier and follows it to a same-file `const`. Extend its answer with `known`:

- a `const` whose initializer is a literal gives `known: { values: [v], line }`;
- a `const` whose initializer is a ternary whose then and else are each a literal, or again such a ternary, gives every distinct leaf literal, in source order (`const limit = process.env.STRICT ? 5 : 10` gives `[5, 10]`);
- anything else gives no `known`.

`line` is the start line of the operand identifier being read: the read is the consumption point (README "Known values and the consumption point"). Read every literal with `getLiteralValue()`, never from node text. The ternary's condition is not read here. When `known.values` has exactly one value, `value` is set as today. `length` for an array literal is unchanged.

## Tests

- `VALID: {const x = 5; if (x > 2)} => known values [5], line of the read`.
- `VALID: {const limit = process.env.STRICT ? 5 : 10} => known values [5, 10]`.
- `VALID: {a nested ternary of literals} => every distinct literal, in source order`.
- `VALID: {const items = [1, 2, 3]} => length 3, no known values`.
- `EDGE: {a ternary with a non-literal arm} => no known`.
- `EDGE: {a let} => no known`.
- `EMPTY: {a parameter} => undefined`.
- Formatting immunity: a reformatted copy answers the same values.
