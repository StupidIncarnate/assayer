## The known-value record

Tasks of this phase share one record. It is a field of a condition leaf, `operandKnown` (contract: task 24.1.3):

```ts
operandKnown: {
  values: RepresentativeValue[];          // one or more; a ternary of literals gives two
  from: 'literal' | 'type';               // a literal in code or at a call site, or the operand's declared literal type
  origin: { line: number };               // the consumption point, a line in the file being analyzed
  hops: { file?: string; line: number }[];// each call or import step after the origin; `file` is absent for the file being analyzed
}
```

`operandConstValue` stays for the case of exactly one value, so the readers that exist today keep working. Every reader that takes a set reads `operandKnown`. The field is optional and absent when no known value reaches the leaf.

## What to implement

1. When a caller's argument is a known value (a `literal` or a `literal-set`, tasks 24.1.5 and 24.3.4), build a `KnownWeld` (imported from `contracts/known-weld/known-weld-contract.ts`, task 24.1.7) for the callee's parameter: `values`, `origin` = the argument's `line` (the call that passes the literal in), `hops` = the calls it crossed after that. Pass the map as `known` to `deriveCasesRequestTransformer` (task 24.4.1), beside `welds`, which keeps its single-value behavior.
2. When the caller is itself private and passes its own parameter straight to the callee (`const measure = (size: number): string => label(size)`), the known weld of `measure`'s parameter is passed on. The new weld for `label` keeps the same `values` and `origin` and appends one hop: `{ line: <the line of the call label(size)> }`. The chain may be any length; the recursion runs through the call graph walk, with a seen-set that stops a cycle, never a loop.
3. A parameter that any caller passes a non-known value to (a caller's own parameter that nothing welds, an opaque call result) has no known weld. When two callers pass different known values, the parameter gets the union of the two sets, with the origin of the first caller in source order.
4. Card `known/call-site-literal`: `label`'s parameter `size` gets `[5]`, origin the line of `measure(5)` (line 10), hops `[{ line: 8 }]` (the call `label(size)` inside `measure`).

## Tests

- `VALID: {card known/call-site-literal} => label's size is known [5], origin 10, hops [8]`.
- `VALID: {entry calls label(5) directly} => origin the call line, hops []`.
- `VALID: {a three-call chain} => hops in call order`.
- `VALID: {two callers pass 3 and 7} => values [3, 7]`.
- `VALID: {a literal-set argument} => the set is passed on`.
- `EDGE: {one caller passes a known value and one an opaque result} => no known weld`.
- `EDGE: {a cycle of private calls} => stops at the seen-set, no weld`.
- `EMPTY: {no known value anywhere} => unchanged`.
