## The known-value record

Tasks of this phase share one record. It is a field of a condition leaf, `operandKnown` (contract: task 24.1.3):

```ts
operandKnown: {
  values: RepresentativeValue[];          // one or more; a ternary of literals gives two
  from: 'literal' | 'type';               // a literal in code or at a call site, or the operand's declared literal type
  origin: { line: number };               // the consumption point, a line in the file being analyzed
  hops: { file?: string; line: number }[];// each call or import step after the origin; `file` is absent for the file being analyzed
}
```

`operandConstValue` stays for the case of exactly one value, so the readers that exist today keep working. Every reader that takes a set reads `operandKnown`. The field is optional and absent when no known value reaches the leaf.

## What to implement

Add an optional input `known?: Map<string, KnownWeld>` beside `welds`. `KnownWeld` is imported from
`packages/core/src/contracts/known-weld/known-weld-contract.ts` (task 24.1.7).

For a leaf whose operand is a scalar parameter named in `known` (never an object-member read, as today), the leaf also gets `operandKnown: { values, from: 'literal', origin, hops }`, and `operandConstValue` when `values` has exactly one value. `welds` keeps working unchanged: a parameter in `welds` and not in `known` is stamped as today, with no `operandKnown`. The recursion through `not`, `and` and `or` passes `known` on.

The callers pass `known` in later rows: `stamp-branches` (task 24.3.1), then `derive-cases-request` (24.4.1), then `through-caller-cases` and `through-invocation-cases` (24.5.1 and 24.5.2).
