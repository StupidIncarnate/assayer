## What to implement

`pieceInstancesTransformer({ pieces }): { piece: LoadedPiece; typeArgument?: string; label: string }[]`
(`LoadedPiece` from task 1.3.5). Port the old transformer: one instance per allowed type argument, or one plain
instance for a piece with no type parameter. `label` is `<name>-<typeArgument>` (`gt-number`) or the piece
name, and the result is sorted by label. A `PieceTree` node (task 1.4.2) carries exactly `piece` plus
`typeArgument`, so an instance is that pair plus its label. The return type is written inline, which a
transformer may do for a shape no contract owns.

The type substitution into holes, anchors and return type happens where a hole is filled (task 4.2.1, the
plainest tree), by reading `typeParameter` and `typeArgument`. Keep the old transformer's anchor check there,
not here. A shim yields one plain instance; it is listed but never placed.

## Tests

- `VALID: {pieces: [generic piece with three allowed types]} => three instances in the order of the labels`.
- `VALID: {pieces: [plain piece]} => one instance named after the piece`.
- `VALID: {pieces: [shim]} => one plain instance`.
- `EMPTY: {pieces: []} => []`.
