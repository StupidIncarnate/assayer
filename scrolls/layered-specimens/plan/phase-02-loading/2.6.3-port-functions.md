## What to implement

Port each container. The marker vocabulary is unchanged: `$Entry`, `$R`, `$params`, `$stmts('<slot>')`,
`$expr('<slot>')`. Keep each container's slot names and reach. A container has no arms, so none of its slots
declares `under`, and it declares no `iteratives`. Each statement slot keeps its `arm` (`return`, `log`,
`yield`, `push` or `throw`, the kit's `Arm` from task 1.1.1) exactly as the old container slot did.

| Piece | folder | tag | slots (accepts, position) | axes |
|---|---|---|---|---|
| `arrow-function` | `arrow` | expression | `params` (parameter-list), `block-body` (statement, statement), `expression-body` (expression, exit) | `level`, `exit-kind` |
| `function-expression` | `function-expression` | expression | `params` (parameter-list), `body` (statement, statement) | `level`, `exit-kind` |
| `function-declaration` | `function` | statement | `params` (parameter-list), `body` (statement, statement). Drop the old `default-param` slot: the `parameter` piece of task 3.1.4 owns defaults | `level`, `exit-kind` |

One file, one export (`arrowFunctionPiece`, `functionExpressionPiece`, `functionDeclarationPiece`). No `iife`
piece is written: an immediately invoked function is a `call` piece holding an `arrow-function`.
