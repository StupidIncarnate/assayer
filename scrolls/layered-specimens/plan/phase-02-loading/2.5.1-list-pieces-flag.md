## What to implement

The responder accepts `--list-pieces` and nothing else with it. Callers: `GenerateFlow` calls the responder
(through `StartSpecimenGenerator`); neither changes.

- The refusal check treats `--list-pieces` as a read argument.
- Combined with any other argument it answers exit 1: `specimen-generator: --list-pieces takes no other flag. Run it on its own.`
- On its own it parses `generatorArgsContract` with `mode: 'list-pieces'` (task 1.2.6), calls `piecesLoadBroker`
  (task 2.3.1) with the declarations root, and answers exit 0 with `pieceListTextTransformer`'s text (task 2.4.1).
- A `DeclarationError` becomes exit 1 with its own message, like every other failure.

The accepted-flags text in the refusal message does not change in this task. The startup integration test
`start-specimen-generator.integration.test.ts` pins that text word for word, and task 9.3.1 writes the final
text for every flag at once. Say so in a comment above `acceptedFlags`.

The proxy composes `piecesLoadBrokerProxy` (task 2.3.1) and exposes a `setupPieces({ repoRoot })` method that
stages a small declarations tree: one piece (`if`) and one shim.

## Tests

- `VALID: {argv: [--list-pieces]} => exit 0 and the text of the staged pieces`.
- `INVALID: {argv: [--list-pieces, --check]} => exit 1 with the message above`.
- `INVALID: {argv: [--list-pieces, --focus=if]} => exit 1 with the same message`.
- `ERROR: {argv: [--list-pieces]} with a piece that fails to load => exit 1 with the DeclarationError message`.
- Every existing test keeps passing.
