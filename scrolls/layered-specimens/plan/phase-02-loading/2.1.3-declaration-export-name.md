## What to implement

`declarationExportNameTransformer({ fileName, kind })` accepts `kind: 'piece' | 'compositions'` besides the
existing `'container' | 'shim' | 'syntax'`. The suffix for each kind comes from `generatorLayoutStatics.declarations`
(`pieces.suffix`, `compositions.suffix`, task 1.1.8). The export name is the camel-cased base name plus the
capitalised kind:

- `if.piece.ts` exports `ifPiece`;
- `for-of.piece.ts` exports `forOfPiece`;
- `position.compositions.ts` exports `positionCompositions`.

Keep `container`, `syntax` and `shim` working: the old pipeline reads them until row 9.5.

Callers: the old `declarations-load-broker.ts` (kinds `container`, `shim`, `syntax`) and the pieces load broker
of task 2.3.1 (kinds `piece`, `shim`, `compositions`). Neither changes in this task.

## Tests

`it.each` over the five kinds, with the list built from the kinds the transformer accepts. Each case gives a
file name and the expected export name (`array-at.shim.ts` → `arrayAtShim`, `if.piece.ts` → `ifPiece`,
`position.compositions.ts` → `positionCompositions`, `arrow-function.container.ts` → `arrowFunctionContainer`,
`eq.syntax.ts` → `eqSyntax`). `EDGE:` a path with folders (`declarations/pieces/if.piece.ts`) uses only the file name.
