## What to implement

One branch of kind `loop` per loop statement.

1. **Arms.** `for`, `for…of`, `for…in` and `while`: `arms: ['runs', 'skipped']`. `do…while`: `arms: ['repeats', 'stops']`.
   Inside Assayer the guard steps are `then` (the first label) and `else` (the second).
2. **Condition.**
   - `for…of` and `for…in`: a leaf on the iterated collection, predicate `length-gt` with literal `0` (it holds when the
     collection is not empty). When the collection is a parameter or a property path of one, the leaf has
     `operandParamName` (and `operandPropertyPath`); otherwise the leaf is `unrecognized` and the branch is admitted
     undriven by the usual gate.
   - `while` and `for`: the loop's own test, read through the condition lens (`readConditionTreeLayerTransformer`) with a
     context built by `walkContextTransformer({ context, condition: true })` (task 11.1.1), so an `&&` in the test stays a
     leaf. A `for` with no test (`for (;;)`) emits no branch: its body runs, so descend the body unguarded and say so in the
     PURPOSE block.
   - `do…while`: the loop's test, read the same way. It holds after a pass when the loop goes round again (`repeats`);
     otherwise it `stops`.
3. **Coverage ID:** `coverageIdTransformer({ scopePath: context.scopePath, segment: 'loop:' + projectNodeLayerTransformer({ node: <the test, or the iterated expression> }) })`, so reformatting never moves it.
4. **Descents.**
   - `for…of`, `for…in`, `while`, `for`: the body descends under `{ branchCoverageId, arm: 'then' }` (`runs`), with
     `tail: false`: reaching the end of a body never ends the scope.
   - `do…while`: the body descends under the enclosing guards, unguarded, with `tail: false`: it always runs once. Its test
     descends with the condition marker.
   - The `for` initializer and incrementor, and the `for…of` iterated expression, descend under the enclosing guards with
     `tail: false`, so a call in them reaches `handle-call`.
5. **The head binding.** A `for…of` head (`const item of items`) binds `item` to an element of the collection. Give the
   body's descent context an `elements` entry for it (task 14.1.2): build the context with `walkContextTransformer` as
   step 4 says, then set `elements: { ...context.elements, item: <element> }` on the result. `<element>` is
   `{ param: <the collection parameter>, path: [...<the collection's own path>, '[0]'] }` when the collection is a
   parameter or a property path of one (read with `readPropertyPathLayerTransformer`), and
   `{ param, path: [...elements[root].path, ...<the chain's path>, '[0]'] }` when the collection's root is itself an
   element (a nested loop over `order.prices`). A collection that is neither adds no entry. Task 14.2.4 makes a
   condition read the entry; the value form is the index segment `'[0]'` of task 12.1.7, so no value-expression
   contract change is needed. Cards `loop/for-of`, `reach/array-of-objects`, `deep/array-of-objects-2`.
6. **Fall-through.** Both arms meet again at the code after the loop, so the handler emits no exit. Record the `runs` arm
   (the body's span) as a fall-through arm; the `skipped` arm owns no code.
7. **`break`, `continue` and a `return` in the body** are handled by their own readers: task 14.2.2 makes `break` and
   `continue` end the body and not the function, and `handle-exit` already emits a guarded exit for a `return`, which the loop's
   `runs` step guards.
8. A labelled statement around a loop keeps its default descent; the loop inside is reached by the walk.

Write the PURPOSE block in plain words: what each arm means, why a body descends under `runs`, why a `do…while` body does
not.

## Tests

One `VALID:` per loop kind.

- `VALID: {for (const item of items) {…}} => one loop branch, arms ['runs', 'skipped'], leaf length-gt 0 on items`
- `VALID: {for (const key in record) {…}} => one loop branch`
- `VALID: {while (count < limit) {…}} => one loop branch whose leaf is lt on count`
- `VALID: {for (let i = 0; i < n; i += 1) {…}} => one loop branch whose leaf is lt on i`
- `VALID: {do {…} while (count < limit)} => one loop branch, arms ['repeats', 'stops'], the body descent has no guard step`
- `VALID: {for-of body descent} => carries the then guard step and tail false`
- `VALID: {a return in the body} => reached by the walk under the runs guard (assert via walkFileTransformer: the exit's guard path holds the loop's then step)`
- `VALID: {an if in the body} => its branch guard path holds the loop's then step`
- `VALID: {for (const item of items)} => the body descent's context has elements { item: { param: 'items', path: ['[0]'] } }`
- `VALID: {a for-of over order.prices inside a for-of over orders} => elements price: { param: 'orders', path: ['[0]', 'prices', '[0]'] }`
- `VALID: {for (;;) {…}} => no loop branch, body unguarded`
- `EDGE: {for (const item of load()) {…}} => leaf unrecognized`
- `EDGE: {the same for-of with different spacing} => identical coverage IDs`
