## What to implement

A `for…of` over an array parameter drives its `loop` branch the way a mapped callback's `skipped`/`runs` is driven today:
the empty array takes `skipped` (the `else` step), one item and many items take `runs` (the `then` step). The body's
branches read the loop item, which task 14.2.1 recorded as an element of the collection.

1. **Sizes.** The loop branch's leaf is `length-gt 0` on the array parameter, so the existing array cardinalities steer
   it: `[]` is `skipped`, a non-empty array is `runs`.
2. **One item per arm.** For a body branch whose leaf reads the loop item, each arm of that branch needs an item value that
   takes it. Take the value from the same domain math a scalar uses (`typeToRange`, `domainValues`) and from the edge values
   of the element type (task 12.3.3's pins, `edgeValueStatics`). The case is the one-item array holding that value, built
   with a pin on the array parameter (task 12.4.1, array pins) using `arrayArrangeTransformer({ element, count: 1, items: [v] })`.
   For `if (item > 2)`: `[3]` takes `then`, and `[2]`, `[0]`, `[NaN]`, `[-1]` take `else`.
3. **Many items take many arms.** One extra case per body branch set: a many-item array whose items take every arm of
   every body branch that reads the item, one arm per item (`items: [2, 3]` takes `else` then `then`). Its `arms` list the
   loop's `runs` step and one step per body arm taken. A case's arms are exactly the arms its input takes: never list an arm
   an item does not take.
4. **`return` in the body.** A body `return` is an exit guarded by `runs` and its own `if` arm. The exit path of a case is
   the exit its items reach first: `[2, 3]` returns at the second item (card `loop/return-inside`: `exits found`).
5. **Branches that read something else.** A body branch whose leaf reads a variable the body writes (`count += 1`) is not
   followed (phase 15). Its routes are kept and marked undriven, never guessed (card `loop/while-break`).
6. **`while` and `for` on a parameter.** A loop test on a scalar parameter (`while (count < limit)`) is an ordinary leaf, so
   the ordinary and pinned buckets steer it. The body is met only on the `runs` arm.
7. **`do…while`.** The loop's test is the leaf: `repeats` when it holds after a pass, `stops` otherwise. A `do…while` has no
   `skipped` arm.
8. **Fewest runs** keeps its tie-break. `[]` and `[2, 3]` together take every arm of card `loop/for-of`.
