## What to implement

`arrayArrangeTransformer({ element, count })` builds a real array of `count` items, each the element type's filled value.
A loop whose body branches on its item needs different items to take different arms in one run. Add an optional input
`items?: ArrangeValue[]`:

- With `items`, the first `items.length` positions take the given values in order; any remaining positions (when `count`
  is larger) take the element type's filled value, as today. `count` still decides the length, and a given list longer
  than `count` is a caller error: return `undefined` (the array is not buildable that way), the same answer the function
  gives for an unfillable element.
- Each given item is an arrange value, so it can be the tagged `undefined` or `NaN` (task 12.1.2) or a nested object.
- Without `items`, the function behaves as today.

Task 14.3.2 passes `items` from the element values the arms of the loop body's branches need. Update the PURPOSE block in
plain words.

## Tests

For `element: number`:

- `VALID: {count 2, items [2, 3]} => [2, 3]`
- `VALID: {count 3, items [2]} => [2, <filled>, <filled>]` (use the real representative)
- `VALID: {count 1, items [{ $assayer: 'nan' }]} => [{ $assayer: 'nan' }]`
- `VALID: {count 2, no items} => unchanged`
- `INVALID: {count 1, items [1, 2]} => undefined`
- `EMPTY: {count 0, items []} => []`
- `EDGE: {nested element: number[], count 1, items [[0]]} => [[0]]`
