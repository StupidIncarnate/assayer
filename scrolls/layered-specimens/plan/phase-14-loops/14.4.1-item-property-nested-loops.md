## What to implement

Task 14.3.2 gives a loop body branch that reads the loop item one one-item array per value of the item: its ordinary
values per arm and its edge values (`[2]`, `[0]`, `[NaN]`, `[-1]`, `[3]`). It covers a scalar item. Two shapes the cards
show are not covered: an item whose property the branch reads, and a loop nested in a loop.

1. **An item property.** When the body branch reads a property of the item (`item.count > 2`, the leaf's operand is the
   item with `operandPropertyPath ['count']`), build each one-item array from an object item: the element type's
   filled object with the read property set to the value (`[{ count: 0 }]`). The values are the property type's
   ordinary values per arm and its edge values, exactly as for a scalar item. The many array holds one such object per
   arm, in arm order (`[{ count: 2 }, { count: 3 }]`).
2. **A nested loop.** When the body of a loop over `orders` holds a loop over a property of its item
   (`for (const price of order.prices)`), the outer array's one-item case carries the inner array's cases as the
   item's property: one outer case per inner case, `[{ prices: <inner array> }]`, where the inner arrays are the inner
   loop's own cases (`[]`, the one-item arrays with each ordinary and edge value, the many array). Add one more case: an
   outer many array whose first item holds the inner `[]` and whose second item holds the inner many array, so one
   run takes `runs` of the outer loop, `skipped` and `runs` of the inner loop, and every inner branch arm (card
   `deep/array-of-objects-2`: `[{ prices: [] }, { prices: [100, 101] }]`). The outer `[]` case stays as it is.
3. Each case's `arms` are the arms its input takes, across all passes. Never list an arm an item does not take.

Update the PURPOSE block in plain words.
