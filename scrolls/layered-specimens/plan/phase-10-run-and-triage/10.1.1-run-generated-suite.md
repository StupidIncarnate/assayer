# 10.1.1 Run the generated suite, one top folder at a time

- **Phase:** 10, run the generated suite and triage. **Row:** #1, alone.
- **Depends on:** phase 9.
- **Model:** default (the worker's default model; this task is fully specified).
- **Covers:** README "How the operator tells an expected failure from a regression", "Running at scale", DESIGN.md decision "Speed of the generated run".

## Files

| Action | Path | Folder type |
|---|---|---|
| create | `scrolls/layered-specimens/RUN-1.md` | plan document (markdown) |

One worker only. The smoke repo's concurrency guard allows one generated run at a time.

## What to do

1. List the top folders under `smoke-repo/packages/syntax-repository/src/` (the first segment of each manifest row's `folder`), sorted.
2. For each, run `npm run test:generated -- <folder>/` with `timeout: 600000`, waiting on each before the next. The command goes through the wrapper (task 8b.6.1): it takes a capacity lease and may wait for a free machine. Never run two at once, never run it with no folder, and never run Jest directly.
3. Record per folder: tests run, passed, failed, and the failing test files.
4. Under Jest, an `it.failing` test whose assertion fails is reported as passed. So every failure in the list is one of two things: a specimen with no today id whose observation differs from its prediction, or an `it.failing` specimen whose observation matches the prediction (a today gap Assayer has closed). For each failing test file, record which of the two it is (the file's `it.failing` tells you) and the fields that differ (Jest prints the diff).
5. Read `smoke-repo/packages/syntax-repository/REFUSED.md`. Record the count of refused specimens per top folder and list any refusal reason that names an arm no known value kills, because each of those is the engine failing to derive an input.
6. Run each folder of step 2 a second time with `ASSAYER_SPECIMEN_STRICT=1` (task 8.2.2). Record each `it.failing`
   specimen that errors instead of failing on a diff: an `it.failing` test hides a crash, and this run shows it.
7. Record the generation count report (`npm run generate:specimens -- --count`) at the top of the file.

## Verify

Every top folder has a line in `RUN-1.md`, and the tests-run counts add up to the manifest's row count.

## Done when

`RUN-1.md` lists every top folder with its counts, every failure classified, and the refused counts.
