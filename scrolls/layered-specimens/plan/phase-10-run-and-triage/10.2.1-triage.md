## What to do

Follow the method `scrolls/specimen-generator/TRIAGE-1.md` used: read it first. Group the failures in `RUN-1.md` by the field that differs and by the shape of the specimen ("every `while` specimen reports a dark spot"). For each group record two or three example folders, what Assayer reports, what the generator predicts, and which of these it looks like:

- **Generator wrong**: a declaration or a prediction rule disagrees with DESIGN.md. Name the file.
- **A known gap without its today id**: Assayer lacks a feature a `todayStatics` row names, but the row's `match` misses this specimen. Name the row and the `match` change.
- **A new Assayer gap**: no row names it. Propose a today id, a `today` sentence, and the core phase that would close it: one of phases 11 to 26, or a new phase written with README "The core phase template".
- **A closed gap**: an `it.failing` specimen passes its assertion. Name the today id. Its core phase may already be done.
- **A refusal that looks wrong**: a specimen in `REFUSED.md` whose arm a known value does not kill. Name the piece and the input the engine could not derive.

Never decide which side is wrong yourself, and never change a prediction to match Assayer's output (rule P4). Write each group as a question for the user with your recommendation.

## Verify

Every failing test file named in `RUN-1.md` appears in exactly one group of `TRIAGE-2.md`.

## Done when

Every failure in `RUN-1.md` belongs to one group in `TRIAGE-2.md`.
