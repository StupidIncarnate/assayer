## What to implement

`env-encode` runs the steps backwards, last step first. Add a `template` case to its `switch`:

- The picked point must be a string. If it is not, answer `undefined`.
- If the point starts with `last.head` and ends with `last.tail`, and its length is at least the two lengths together, the step before must produce the text between them. Recurse with `steps: rest`, a domain whose only member is that inner text, and `type: restType`.
- Otherwise the template has no inverse for this wanted value: answer `undefined`. The case is then unreachable for that arm.

Update the PURPOSE block's list of steps. Values still come from the domain and the steps, never from running the code (P4).

## Tests

- `VALID: {steps [template(head 'size ', tail '')], domain members ['size 3']} => '3'`.
- `VALID: {steps [number, template(head 'n=', tail '')], domain members ['n=7']} => '7'` (`String` inverts `Number`).
- `VALID: {steps [template(head '', tail '!')], domain members ['x!']} => 'x'`.
- `VALID: {steps [template, equals('size 3', false)], domain members [false]} => a string that is not the literal after the template is inverted`: the equals step answers a value other than `'size 3'`, and the template inverts it when the value has the head. Write the expected value by reasoning.
- `EDGE: {wanted 'other'} with head 'size ' => undefined`.
- `EDGE: {wanted equals head + tail exactly} => ''`.
- `EDGE: {wanted shorter than head + tail} => undefined`.
- `EDGE: {point null (variable unset)} on a chain ending in a template => undefined` (a template makes the value a string, so the chain is not nullable).
