## What to implement

`isEnvRequirementMetGuard` runs the steps forward on a picked input and tests the predicate on the result. Its `switch` has no `template` case, and its `default` arm treats an unknown kind as `map`, which answers false for anything that is not an array, so every case that needs a template would be unreachable. Add the case:

```ts
case 'template':
  return isEnvRequirementMetGuard({ steps: rest, predicate, want, raw: `${step.head}${String(raw)}${step.tail}` });
```

`String(raw)` is the JavaScript meaning of a template substitution. An unset variable (`raw` is `undefined`) only reaches this case when no `guard` precedes it, and then the text is `'undefined'`, exactly as the code under test builds it. After a `guard` the existing `guard` case already skips the steps up to the `default`. Update the PURPOSE block's list of steps.

## Tests

- `VALID: {steps [template(head 'size ', tail ''), equals('size 3')], raw '3', want true} => true`.
- `VALID: {the same, raw '4', want true} => false`.
- `VALID: {steps [template(head 'n=', tail '')], predicate eq 'n=undefined', raw undefined, want true} => true`.
- `VALID: {steps [number, template(head '', tail '!')], predicate eq '7!', raw '7', want true} => true`.
- `EDGE: {steps [guard, template], raw undefined} => the template is skipped, as for every step after a guard}`.
- The existing tests stay.
