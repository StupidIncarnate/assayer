## Contract

Add one member to the discriminated union in `envStepContract`:

```ts
z.object({
  kind: z.literal('template'),
  head: z.string().brand<'EnvStepHead'>(),
  tail: z.string().brand<'EnvStepTail'>(),
}).brand<'EnvStep'>(),
```

`head` and `tail` may be empty strings: `` `${x}` `` has neither. Add a bullet to the PURPOSE block: `template` is a template literal with exactly one substitution, `` `<head>${x}<tail>` ``, where `head` and `tail` are literal text. It runs forward by joining `head`, the value and `tail`. It runs backwards by stripping `head` and `tail` from the wanted value. A wanted value that does not start with `head` and end with `tail` has no inverse. A template literal with two or more substitutions is not a step: it still ends the chain.

## Readers that switch on `EnvStep['kind']`

Each reader gets its own task in row #2: `env-encode` (22.2.9), `env-steps-type` (22.2.10), `read-env-chain` (22.2.8), `is-env-requirement-met-guard.ts` (22.2.11) and `argv-read-value-transformer.ts` (22.2.12). `is-env-steps-nullable-guard.ts` and `env-steps-domain-transformer.ts` need no edit: a `guard` step keeps an unset variable `undefined` and skips the steps after it, so a template after a guard leaves the chain nullable, and a template with no guard before it leaves it non-nullable, which is what both files already answer.
