## What to implement

`read-env-chain` follows an operand down to a `process.env.<X>` read and records each step the code applies, in order. Add the template step.

A `TemplateExpression` with exactly one substitution span, `` `size ${process.env.SIZE}` ``, is one step. Its `head` is the literal text of the template head and its `tail` the literal text of the span's literal. Read both through the walk's literal reader (`read-literal-value-layer-transformer`, `getLiteralValue()`), never from node text. The substitution is read as the chain's inner expression (an identifier bound to a same-file `const`, or a `process.env.<X>` read), and the `template` step is appended after the inner chain's steps, so `` `size ${Number(process.env.N)}` `` is `[number, template]`. A template with no substitution (`` `abc` ``) is a plain string literal, not a step. A template with two or more substitutions still ends the chain.

Task 22.1.5 makes the literal reader read a template head and a span's literal; this task only calls it.

The chain's consumers then see the step: `env-operand-key` names the operand by the read and its steps, `cause-arrange` decides the variable once per case, and `env-solve` calls `env-encode` (task 22.2.9).

## Tests

- `VALID: {` `` `size ${process.env.SIZE}` === 'size 3' `` `} => steps [template(head 'size ', tail ''), equals('size 3')]`.
- `VALID: {const label = `` `${process.env.A}!` ``; label === 'x!'} => the identifier is followed, steps [template(head '', tail '!'), equals]`.
- `VALID: {Number inside a template} => [number, template]`.
- `EDGE: {two substitutions} => the chain ends: no steps are recorded`.
- `EMPTY: {a template with no substitution} => no steps`.
- Formatting immunity: spacing and quote changes around the template give the same steps.
