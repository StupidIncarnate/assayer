## What to implement

1. The responder's write and `--check` modes call `specimensBuildBroker` (task 9.2.1), with `cacheRoot` from `runScaleStatics.cache.folder` and `fresh` true when `--fresh` is present. It returns `Promise<GenerateRunResult>`.
2. Accept `--fresh` with a write or with `--check`.
3. Write mode and `--check` both print the count report (the text transformer from task 4.4.3) after the summary line, separated by a newline.
   - Write: `generated <n> specimens into <outRoot relative to repoRoot>; TypeScript or the engine refused <r>`.
   - `--check` current: `smoke-repo is current: <n> specimens`.
   - `--check` drifted: the drift lines, then `run npm run generate:specimens to regenerate`, as today.
4. Refuse `--focus`, `--container` and `--depth` like any unknown flag, with the existing text and the new accepted-flags list: `specimen-generator: cannot read the argument "<arg>". It is not an accepted flag, or its value is malformed. Accepted flags: --check, --fresh, --count, --list-pieces, --show=<folder,folder>, --piece=<a,b>, --axis=<a,b>.` The contract fields themselves are removed in task 9.7.8.
5. In the startup integration test, `await` every call. Replace the `--focus=nope` case with `INVALID: {argv: [--focus=if]} => exit 1 with the refusal text`. Update the refusal text in the `--bogus` case to the new accepted-flags list. The `--check` case still expects the first words `smoke-repo is current`.

## Tests

The responder test keeps its cases for refusal text and adds:

- `VALID:` write mode calls the build broker then the write broker and prints the summary and the count report.
- `VALID:` `--check --fresh` passes `fresh: true` to the build broker.
- `INVALID:` `--focus=if`, `--container=iife` and `--depth=1` each give the refusal text.
- `ERROR:` a build broker rejection gives exit code 1 with its message.
