## What to implement

`--count` with no `--piece` and no `--axis` runs `specimensBuildBroker` (task 9.2.1) through the cache and prints `result.count` with the count report text transformer (task 4.4.3). The broker returns the files and never writes them (only `specimensWriteBroker` writes), so this is a dry run. The report's `by today id` block holds a count per id, and the first line, `specimens: <n>, estimated <m> minutes for the whole generated suite`, counts the specimens the build kept. `--fresh` is accepted with `--count`.

`--count` with `--piece` or `--axis` keeps the plan-only count from task 4.7.1, whose `by today id` line says `computed by a full generation (--count after task 9.8.1)`. Task 9.8.1 changes that line to `computed by a full generation: run --count with no filter`. A filtered count never takes a lease.

`--count` always exits 0.

The startup integration test's `--count` case keeps its regex `/^specimens: \d+, estimated \d+ minutes for the whole generated suite$/u` on the first line and asserts that a `by today id` block follows.
