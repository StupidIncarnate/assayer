These files are hand-written, not generator output. `smoke-repo/package.json` already lists `packages/*` as workspaces, so
the smoke repo picks the package up with no edit there. The name says what the package shows: a cross-package import
whose package ships no type information, which Assayer reports as a P1 build error with reason `no-usable-types`.

## What to implement

1. `package.json`: `{ "name": "project-without-types", "version": "1.0.0", "private": true, "main": "index.js" }`, with no `types` field.
2. `index.js` (CommonJS): `exports.isBig = (value) => value > 2;`. Write no `.d.ts` file anywhere in the package.

Task 4.1.3 names this package in `typeListStatics.packages.untyped`. Its specimens sit under
`src/boundary/*/unresolvable-no-types/`, which task 9.1.5's `exclude` keeps out of `typecheck:generated`, because
TypeScript refuses the import with TS7016.
