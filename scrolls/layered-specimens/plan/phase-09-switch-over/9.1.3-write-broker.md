## What to implement

The broker clears and writes what the generator owns: the `src` folder, the manifest, `REFUSED.md`, and the smoke
repo's stub correction folder `smoke-repo/assayer/stubs/` (DESIGN.md decision "Where a generated stub correction
lives"). The generator owns that folder exactly as it owns `src/`: it is cleared and rewritten on every write.

1. Add `EXPECTED-FAILURES.md` (`generatorLayoutStatics.output.expectedFailuresFile`, task 1.1.8) to the files it clears and writes.
2. Change the type of `result` to `{ files: readonly GeneratedFile[] }`. The broker reads only `result.files`, so both the old `GenerationResult` and the new `BuildResult` (task 9.1.6) satisfy it. Callers stay unchanged.
3. Every file under `src/` is generated, including `tsconfig.json` and `*.harness.ts` inside a specimen folder. The write does not filter by suffix. A file whose `relPath` starts with `assayer/stubs/` is a stub correction (task 5.4.1): write it under the smoke repo root `smoke-repo/`, not under the package root. Clear `smoke-repo/assayer/stubs/` before writing, as `src/` is cleared. Nothing else under `smoke-repo/assayer/` is touched.
4. The hand-written files at the package root (`package.json`, `tsconfig.json`, `jest.config.js`, `global-setup.js`, `global-teardown.js`, `concurrency-lock.js`) are never read, written, removed or reported: the broker names none of them. A specimen folder inside another specimen folder (card `src/const/in/for-of-body/if-then`) is ordinary: every path is just a file.

Callers of the broker: `generate-run-responder.ts` (task 9.3.1) and the build broker's tests. None passes anything the new parameter type rejects.

## Tests

Keep every test. Add:

- `VALID:` `EXPECTED-FAILURES.md` is written and an old one is removed first.
- `VALID:` a nested specimen folder is written, and a stub JSON file with `relPath` `assayer/stubs/objects/packages/syntax-repository/src/x/entry.ts/Job.json` is written under `smoke-repo/`, not under the package root.
- `VALID:` a stale stub JSON under `smoke-repo/assayer/stubs/` is removed by the next write.
- `VALID:` a hand-written package-root file survives a write.
