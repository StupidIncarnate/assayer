## Read first

`packages/core/src/transformers/fill-param/fill-param-transformer.ts`: the one authority for filling a value. Every site that fills a value goes through it, and it refuses what `isTypeFillableGuard` refuses. A refusal becomes a gap named by `input-gap`.

## What to implement

Add an optional input `narrowedTo?: TypeDescriptor`: the type a `narrows-to` leaf of the entry reads this parameter as (the first such leaf in branch order). When it is present and the parameter's declared type is `unknown`:

- call `isTypeFillableGuard` with `narrowed: true` (task 25.2.2), so the parameter is not refused;
- fill it as `narrowedTo` would be filled: the ordinary value of that type (`fill-value`), because a guard-passing value is a safe argument for a route no case steers.

The parameter is not refused, so no gap is reported for it. Without `narrowedTo` the answer is today's: an `unknown` parameter is refused and `input-gap` names it. A `callable` is refused whatever is passed.

The callers that know a leaf's predicate pass `narrowedTo`: `cause-arrange`, `stub-realize`, the funnel builders and the `through-*` builders. Which of them reach a narrowed `unknown` parameter in this phase is the worker's to find with `discover` (`grep: "fillParamTransformer"`); the card needs only `cause-arrange`. The worker reports the callers it did not change.

## Tests

- `VALID: {declared unknown, narrowedTo number} => a filled number value, no refusal`.
- `VALID: {declared unknown, narrowedTo a string | null union} => a filled value of the first fillable member`.
- `INVALID: {declared unknown, no narrowedTo} => refused, the same refusal as today (assert the whole result)`.
- `INVALID: {declared callable, narrowedTo number} => refused`.
- `EDGE: {declared number, narrowedTo string} => filled as a number}` (a declared type that is not unknown ignores `narrowedTo`).
- The existing tests stay.
