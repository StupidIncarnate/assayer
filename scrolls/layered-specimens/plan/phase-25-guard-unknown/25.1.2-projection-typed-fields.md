## What to implement

The projection reads a gap's `param`, a build error's `reason` and `trace`, and a lint's `trace` through small typed guards (`'param' in gap` and the like), written in task 8.2.1 so the projection needs no change when core adds a field. Core holds the typed fields: `EntryGap.param` (task 12.1.4), the compile error's `reason` (task 23.1.2) and `trace` (task 24.1.2), and `LintEntry.trace` (task 24.1.1). Task 13.2.1 replaces the guard for `arms`.

Replace the three remaining guards with the typed fields:

- gap name: `<entry>.<param>` from `gap.param`; when the contract leaves `param` optional, `gap.param === undefined` gives `<entry>`;
- build error `reason`: `error.reason`, and `unclassified` when it is absent (the field is optional in the contract);
- build error `trace` and lint `trace`: the field, and `[]` when absent.

Delete the guards and every comment that explains them. The projection's output shape (`SpecimenReport`) does not change. Do not import anything else from core. Read the four contracts first, to match their exact optionality.

## Tests

- The existing projection tests stay and still pass.
- `VALID: {a gap with param 'count'} => name '<entry>.count'`.
- `VALID: {a gap without param} => name '<entry>'`.
- `VALID: {a build error with reason 'contradicting-stub' and a trace} => both carried}`.
- `VALID: {a build error with no reason} => 'unclassified'`.
- `VALID: {a lint with a trace} => the trace carried; a lint without one => []`.
- Delete any test whose only purpose is to exercise a removed guard.
