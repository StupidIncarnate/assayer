## Read first

`packages/core/src/guards/is-type-fillable/is-type-fillable-guard.ts`: the one rule for whether a value of the right shape exists. An opaque `unknown` and a `callable` answer no, with or without a candidate value.

## What to implement

Add an optional input `narrowed?: boolean`. It is true when some leaf of the entry reads this parameter through a `narrows-to` predicate (task 25.2.1): the guard then names the types the parameter is built from, so an `unknown` parameter has a value to build.

- `type.kind === 'unknown'` with `narrowed === true`: fillable when `value` is undefined (the type question), and fillable when `value` is a scalar, `null` or `undefined` (the candidate question). A composite candidate (an array or an object) is not a candidate for `unknown` here; those come from the guard's own type through its own check.
- `type.kind === 'unknown'` without `narrowed`: refused, exactly as today.
- `callable` is refused whatever `narrowed` says.
- `narrowed` has no effect on any other kind, including a union that contains an `unknown` member: that member stays refused, and the union is fillable through its other members as today.

Callers that pass nothing keep today's answer. Task 25.3.1 (`fill-param`) is the caller that passes `narrowed`. Update the PURPOSE block: an `unknown` is fillable only when a guard narrows it.
